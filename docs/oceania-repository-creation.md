# AGID Oceania Repository Creation Plan

This document defines the first safe GitHub creation wave for AGID Oceania data.

## Conclusion

Do not create every Oceania repository at once. The Oceania plan currently contains
60 logical repositories:

- 1 continent index repository
- 3 region index repositories
- 35 country or territory parent repositories
- 21 Australia state, territory, external-territory, city, or metro child repositories

The first physical GitHub wave should create only the 4 index repositories. Country
parents and Australia child repositories stay in the generated plan until
maintainers, source licenses, datasets, and review ownership are ready.

## Wave 0: Create Now

These repositories are safe to create immediately under `dawnportinfo-design`:

```text
agid-oceania-index
agid-oceania-oceania-index
agid-oceania-australian-external-territories-index
agid-oceania-polynesia-index
```

The index repositories should contain coordination metadata, governance, source
license summaries, country pack pointers, postal status, and conformance status.
They should not contain raw personal addresses.

## GitHub Owner Requirement

`dawnportinfo-design` is treated by GitHub as a user account, not an organization.
Repository creation under that owner must be run while authenticated as
`dawnportinfo-design`, or after converting/mirroring the project into an
organization where maintainers have repository creation permission.

Do not run the physical creation command from another authenticated user account.
GitHub CLI may create repositories under the current authenticated user instead
of the intended owner when the owner is not an organization that the token can
administer.

## Wave 1: Country And Territory Parents

Create the 35 country and territory parent repositories after each pack has:

- a maintainer or region owner
- source and license notes
- no-raw-address release gate status
- country or territory address hierarchy rules
- breadcrumb reconstruction rules
- postal status, including no-postal-code and weak-postal-code classification
- safe synthetic fixtures

Examples:

```text
agid-country-au
agid-country-nz
agid-country-pg
agid-country-fj
agid-country-tv
agid-country-vu
agid-country-au-at
```

## Wave 2: Australia Child Repositories

Create the 21 Australia child repositories only when there is clear operational
pressure:

- large source data volume
- frequent pull requests
- separate local maintainer group
- separate source license boundary
- high update frequency for a state, territory, city, metro area, or external territory

Examples:

```text
agid-au-new-south-wales
agid-au-victoria
agid-au-queensland
agid-au-sydney
agid-au-melbourne
agid-au-australian-antarctic-territory
```

## Island And Marine Boundary

GitHub repositories may store:

- island, atoll, reef, port, and shore-handoff hierarchy
- administrative hierarchy ids
- AGID id allocation ranges
- country and region rendering rules
- source metadata
- quality score rules
- conformance fixtures
- synthetic examples

External storage should hold:

- building polygons
- precise private coordinates
- search indexes
- map tiles
- OSM or Overture extracts
- hydrographic datasets
- cache artifacts
- large generated country packs

Oceania packs may reference coarse marine areas, but they should not publish
private delivery coordinates or personal recipient material.

## Generated Files

The executable plan is generated by:

```bash
npm run generate:oceania-repo-plan
```

The generated manifest is:

```text
data/global_entities/agid-oceania-repository-creation-plan.json
```

Validation is included in:

```bash
npm run verify:repository-split-allocation
```
