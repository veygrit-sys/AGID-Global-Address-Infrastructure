# 第2章 住所参照の本質と住所写像論

## 2.0 互換ノート

本章は、現行29章構成における第2章、第21章、第23章、第25章を保存しつつ、v2構成の第2章として再記述する。

本章で保存する主張は次の通りである。

- 住所正規化は表現を整えるが、参照対象の同一性を定義しない。
- ジオコーディングは座標を与えるが、垂直参照、機能的参照、社会的参照を単独では解決しない。
- 郵便番号は地域や配送処理を圧縮するが、普遍的な住所識別子ではない。
- Place ID、POI ID、DID、VCは有用だが、異なる主体が同じ実体へ同じPIDを導く規則を単独では与えない。
- AMTの評価は、きれいな住所に対する正答率だけではなく、候補リコール、棄却品質、出典透明性、プライバシー漏えい、履歴保存を含むべきである。
- AMTは既存のGIS、郵便標準、住所標準、DID、VC、商用住所検証APIを置き換えるとは主張しない。

本章で導入する数理対象は、既存手法の出力型、限界行列、完全住所解決不可能性、検証分類、ベンチマーク関数である。

厳密な公理化は第4章、候補生成は第5章、構造同値は第6章、評価と意思決定は第9章、検証体系は第12章で扱う。

## 2.1 既存手法は失敗しているのではない

AMTは、既存の住所技術を失敗作として扱わない。

住所正規化、ジオコーディング、郵便番号、GIS、住所標準、配送会社の住所検証API、Place ID、DID、VC、地理データベース、POIデータベースは、それぞれ重要な役割を持つ。これらがなければ、AMTも実装できない。

問題は、これらの手法が扱う対象と、AMTが扱おうとする対象が異なることである。

多くの既存手法は、住所を次のいずれかとして扱う。

- 文字列
- 正規化された文字列
- 住所要素の列
- 緯度経度
- 郵便番号
- 地図上の点
- 行政区画コード
- POI ID
- サービス事業者内の内部ID
- 本人や組織に紐づくCredential

これらはすべて有用である。しかし、AMTが必要とするものは、これらを統合した「参照対象」である。

すなわち、AMTが問うのは次の問いである。

```text
この住所表現は、どの実体を、どの目的で、どの証拠に基づき、
どの程度安全に指しているのか。
```

既存手法の多くは、この問い全体ではなく、その一部分を解いている。

したがって、本章の目的は既存手法を否定することではない。既存手法が何を解き、何を解かないかを明確にし、AMTが補うべき欠けている対象を定義することである。

## 2.2 住所正規化の限界

住所正規化は、表記ゆれを減らす。

例えば、次のような処理を行う。

- 略称の展開
- 文字種の統一
- 国名や行政区画名の標準化
- 住所要素の分解
- 順序の変換
- 旧表記から現代表記への変換
- 多言語表記の対応

これは候補生成の前処理として不可欠である。

しかし、正規化は参照対象を決定しない。

正規化写像を次のように置く。

\[
\nu_t : S \rightharpoonup N_t
\]

ここで、\(S\) は表面住所表現集合、\(N_t\) は時刻 \(t\) における正規化表現空間である。

正規化の出力 \(\nu_t(s)\) は、解決済み実体ではない。これは、より扱いやすくなった表現である。

正規化には少なくとも三つの限界がある。

第一に、多対一の問題がある。異なる実体を指す複数の表現が、同じ正規化表現へ写ることがある。

第二に、一対多の問題がある。一つの正規化表現が、複数の建物、部屋、入口、店舗、ロッカー、行政対象、配送対象を指し得る。

第三に、目的依存性の問題がある。法的登録には十分でも配送には不十分、地図検索には十分でも本人確認には不十分、国レベル証明には十分でも部屋レベルの到達可能性には不十分、という場合がある。

したがって、正規化は次の性質を持つ。

\[
\nu_t(s_1)=\nu_t(s_2)
\centernot\Rightarrow
\operatorname{referent}(s_1)=\operatorname{referent}(s_2)
\]

また、

\[
\nu_t(s_1)\neq\nu_t(s_2)
\centernot\Rightarrow
\operatorname{referent}(s_1)\neq\operatorname{referent}(s_2)
\]

正規化は必要条件に近いが、同一性の十分条件ではない。

AMTでは、正規化を候補生成の入力とし、同一性は後段の構造距離、証拠、同値類、履歴、目的別損失によって判断する。

## 2.3 ジオコーディングとGISの限界

ジオコーディングは、住所表現を座標へ写す。

\[
g_t : S \rightharpoonup \mathbb{R}^2
\]

または、より一般に、地理空間オブジェクト集合 \(G_t\) への写像として表せる。

\[
g_t : S \rightharpoonup G_t
\]

GISは、座標、境界、多角形、道路、施設、土地利用、行政区画などを扱う強力な基盤である。

しかし、ジオコーディングとGISは、住所参照のすべてを解決するわけではない。

第一に、座標は参照対象の機能を表さない。建物の代表点、配送入口、搬入口、来客入口、緊急車両入口、法的筆界、店舗入口、ドローン受渡点は異なり得る。

第二に、座標は垂直方向を十分に表せないことがある。同じ緯度経度に、複数の階、部屋、事業所、ロッカー、地下区画が存在する。

第三に、座標は社会的参照を十分に表せないことがある。地域名、慣習的受渡点、旧地名、市場名、非公式集落、災害時避難所、港湾内の通称ゲートなどは、公式GISレイヤーに安定して現れない場合がある。

第四に、座標は履歴を自動的には保存しない。ある施設が改名される、入口が変わる、道路が閉鎖される、行政区画が変更される、避難所が一時的に設置される。このとき、同じ座標であっても参照対象としての意味は変わり得る。

第五に、精密座標はプライバシーリスクを持つ。配送可能性を証明したいだけなら、部屋レベルの座標や自宅の精密位置を公開する必要はない。

したがって、AMTではGISを否定しない。むしろ、GISを重要な証拠層として扱う。

しかし、AMTは次の区別を維持する。

```text
座標として近い
  !=
同じ参照対象である
```

```text
地図上で正しい
  !=
配送、登録、本人確認、監査、ZK証明に十分である
```

この区別が失われると、住所参照は座標解決に過剰に依存してしまう。

## 2.4 郵便番号と住所標準の限界

郵便番号は、住所処理における非常に強力な圧縮手段である。

郵便番号は、地域、配送区域、仕分け、ルート、行政単位、事業者運用を短い記号列へ圧縮する。多くの国では、入力補助や配送検証に不可欠である。

しかし、郵便番号は普遍的な住所識別子ではない。

郵便番号を持たない地域がある。郵便番号が粗すぎる地域がある。郵便番号が頻繁に変わる地域がある。郵便番号が配送会社や行政区画や歴史的制度に強く依存する場合がある。郵便番号が同一でも、複数の建物、部屋、施設、入口、島、道路、私書箱が含まれることがある。

郵便番号写像を次のように置く。

\[
z_t : S \rightharpoonup Z_t
\]

ここで、\(Z_t\) は時刻 \(t\) における郵便番号または郵便番号相当区域の集合である。

郵便番号は候補生成や圧縮には有用であるが、次は一般に成り立たない。

\[
z_t(s_1)=z_t(s_2)
\Rightarrow
\operatorname{referent}(s_1)=\operatorname{referent}(s_2)
\]

住所標準も同様である。

国際住所標準、国別住所テンプレート、住所要素定義、行政区画コードは、住所データを相互運用可能にするために重要である。しかし、標準化された要素列が得られても、それがどの実体を指すか、どの目的で十分か、どの履歴を持つか、どの証拠に基づくかは別問題である。

AMTは、郵便番号や住所標準を置き換えない。

AMTは、それらを次のように位置付ける。

```text
郵便番号・住所標準
  -> 圧縮、入力補助、候補生成、検証補助

AMT
  -> 参照対象、同値類、履歴、目的依存性、棄却、PID発行
```

この関係により、郵便番号が強い国でも、郵便番号が弱い国でも、郵便番号が存在しない地域でも、同じ理論枠組みを使える。

## 2.5 Place ID、POI ID、事業者IDの限界

地図サービスや検索サービスは、施設、店舗、ランドマーク、POIに対して独自のIDを発行する。

これらのIDは、検索、レビュー、ナビゲーション、広告、地図表示、店舗管理に非常に有用である。

しかし、AMTが必要とするPIDとは異なる。

Place IDやPOI IDは、発行主体に依存する。ある事業者が同一とみなす施設を、別の事業者は分割するかもしれない。ある事業者が一つの施設として扱うものを、配送会社は複数の入口や受渡点として扱うかもしれない。ある地図サービスのPOI IDが消えたり統合されたりしても、社会的実体としての場所は継続することがある。

この問題は次のように表せる。

ある事業者 \(i\) のID発行写像を

\[
\operatorname{id}_i : R_t \rightharpoonup I_i
\]

とする。

ここで、\(R_t\) は参照対象集合、\(I_i\) は事業者 \(i\) のID空間である。

別の事業者 \(j\) について、

\[
\operatorname{id}_i(r_1)=\operatorname{id}_i(r_2)
\]

であっても、

\[
\operatorname{id}_j(r_1)=\operatorname{id}_j(r_2)
\]

とは限らない。

また、

\[
\operatorname{id}_i(r)
\]

が存在しても、それが配送、本人確認、法的通知、ZK証明、ホテル受取、ロッカー受取に十分とは限らない。

AMTのPIDは、事業者IDを否定しない。むしろ、事業者IDを証拠や外部参照として利用する。

ただし、AMTが必要とするのは、単一事業者内のIDではなく、複数主体が同じ参照対象へ到達するための構造的導出規則である。

## 2.6 DID、VC、本人確認システムの限界

DIDやVerifiable Credentialsは、識別子、資格情報、発行者、保持者、検証者の関係を扱う上で強力である。

住所Credential、本人確認、端末署名、発行者信頼、失効管理、選択的開示、ZK証明と相性がよい。

しかし、DIDやVCは、住所参照の同一性を自動的に解くものではない。

DIDは主体の識別子を扱える。しかし、ある住所表現がどの実体を指すかを決める候補生成、構造距離、履歴保存、目的依存性、出典検証を単独で与えるわけではない。

VCは、発行者が何らかの主張を署名する仕組みを提供できる。しかし、その主張の中に含まれる住所参照が正しく解決されているかは、別途検証が必要である。

AMTでは、DIDやVCは次の位置に置かれる。

```text
AMT
  -> 住所参照、同値類、PID、品質、履歴、Envelope

DID / VC
  -> 主体識別、発行者署名、Credential、失効、選択的開示
```

つまり、AMTはDIDやVCの下にある住所参照層を提供する。

逆に言えば、AMTなしに住所Credentialを発行すると、正規化された住所文字列に署名しているだけなのか、参照対象に署名しているのかが曖昧になる。

この曖昧さは、住所プライバシー証明において重大である。

ZKで「配送可能である」と証明しても、証明対象となった住所参照が誤っていれば、ZKはその誤りを修復しない。

したがって、DID、VC、ZKはAMTの代替ではなく、AMTの出力を安全に使うための上位レイヤーである。

## 2.7 商用住所検証APIの限界

商用住所検証APIは、実務上非常に重要である。

住所入力の補完、正規化、存在確認、郵便番号照合、配送可否、国際住所表記、重複検出、リスク判定などを提供する。多くのEC、金融、物流、SaaSにとって不可欠な基盤である。

しかし、AMTは商用APIと同じものではない。

商用APIの多くは、内部データ、評価ロジック、出典、更新頻度、失敗時の扱い、曖昧候補の扱いを完全には公開しない。これは商用サービスとして自然な側面でもある。

AMTが求めるのは、次のような検証可能性である。

- どの候補が生成されたか。
- どの出典が使われたか。
- どの出典が使えなかったか。
- なぜ未解決になったか。
- なぜ手動確認になったか。
- どの目的には十分で、どの目的には不十分か。
- プライバシー上、何を公開していないか。
- 履歴や後継関係がどう保存されたか。

したがって、AMTと商用APIの比較では、単純な正答率だけを見てはならない。

比較すべき対象は、少なくとも次の通りである。

- 正規化精度
- 候補リコール
- 正しい棄却
- 誤った自信過剰の少なさ
- 出典透明性
- 多言語リコール
- 郵便番号なし地域への対応
- 履歴保存
- プライバシー漏えい量
- 目的別判断
- 再現性

AMTは、商用APIに対して勝利を宣言するものではない。AMTは、比較条件を明確にするための理論である。

## 2.8 欠けている対象

以上の整理から、欠けている対象が見えてくる。

既存手法の多くは、次のいずれかを出力する。

\[
f_i(s) \in Y_i
\]

ここで、\(s\) は住所表現、\(f_i\) は既存手法、\(Y_i\) はその手法の出力空間である。

例えば、

- 正規化器なら \(Y_i=N_t\)
- ジオコーダなら \(Y_i=G_t\)
- 郵便番号検索なら \(Y_i=Z_t\)
- Place IDなら \(Y_i=I_i\)
- VCなら \(Y_i=C\)
- 商用APIなら \(Y_i\) は独自の検証結果空間

しかし、AMTが必要とする出力は、単なる \(Y_i\) ではない。

AMTが必要とするのは、次のような対象である。

\[
\mathcal{R}_t(s,u,E)
=
\begin{cases}
r & \text{if a purpose-safe referent is resolved} \\
\bot & \text{otherwise}
\end{cases}
\]

ここで、

- \(s\) は表面住所表現
- \(u\) は目的
- \(E\) は証拠集合
- \(r\) は参照対象
- \(\bot\) は未解決、曖昧、拒否、手動確認

である。

欠けていた対象は、正規化文字列でも、座標でも、郵便番号でも、事業者IDでもない。

欠けていた対象は、

```text
目的に対して安全に解決された参照対象、
または安全な未解決状態
```

である。

AMTはこの対象を定義する。

## 2.9 無条件完全解決は不可能である

AMTの重要な立場は、無条件の完全住所解決を主張しないことである。

任意の住所表現 \(s\) に対し、常に正しい参照対象 \(r\) を返す解決器を考える。

\[
R : S \to R_t
\]

このような全域関数は、現実の住所世界では成立しない。

理由は明確である。

- 入力が不完全な場合がある。
- 同じ表現が複数の実体を指す場合がある。
- 出典が存在しない地域がある。
- 出典が衝突する場合がある。
- 旧地名や慣習名が混在する場合がある。
- 住所が政治的・行政的に係争中の場合がある。
- 建物内区画や入口が公開データに存在しない場合がある。
- 配送会社ごとに到達可能性が異なる場合がある。
- プライバシー上、必要な情報を公開できない場合がある。
- 時間変化により、過去には正しかった表現が現在は不十分になる場合がある。

したがって、健全な住所解決器は全域関数ではなく、部分関数または棄却可能な関数でなければならない。

\[
R : S \times U \times E \rightharpoonup R_t
\]

または、

\[
R : S \times U \times E \to R_t \cup \{\bot\}
\]

である。

この \(\bot\) は、AMTにおいて中心的な出力である。

AMTの強さは、常に答えることではない。答えてはいけないときに、答えないことである。

## 2.10 ベンチマークは正答率だけでは足りない

住所処理の評価では、しばしば正答率が重視される。

しかし、AMTにおける評価はそれだけでは足りない。

きれいな入力に対して座標を返す精度だけを測ると、曖昧な住所に対して過剰に自信を持つシステムが高く評価される危険がある。

AMTでは、評価対象を次のように拡張する。

\[
B =
(
A_{\text{clean}},
R_{\text{candidate}},
Q_{\text{abstain}},
T_{\text{source}},
P_{\text{privacy}},
H_{\text{history}},
L_{\text{purpose}}
)
\]

ここで、

- \(A_{\text{clean}}\) は明確な住所に対する精度
- \(R_{\text{candidate}}\) は候補リコール
- \(Q_{\text{abstain}}\) は棄却品質
- \(T_{\text{source}}\) は出典透明性
- \(P_{\text{privacy}}\) はプライバシー漏えい量
- \(H_{\text{history}}\) は履歴保存能力
- \(L_{\text{purpose}}\) は目的別損失

である。

特に重要なのは、棄却品質である。

住所処理では、誤って解決するより、正しく未解決にする方が望ましい場合がある。高額配送、医薬品配送、法的通知、本人確認、災害対応、ZK証明では、誤った自信過剰が大きな損害を生む。

したがって、AMTのベンチマークは次の問いを含む。

- 真の候補が候補集合に含まれているか。
- 候補が曖昧なときに棄却できるか。
- 出典不足を未解決として扱えるか。
- 古い住所を履歴として保存できるか。
- 目的別に十分性を変えられるか。
- 必要以上の住所情報を漏らしていないか。
- 同じ条件で商用API、オープンソース、AMTモデルを比較できるか。

AMTは、住所処理を単なる「当てる」問題から、「安全に判断する」問題へ拡張する。

## 2.11 検証分類

AMTの主張は、すべて同じ種類ではない。

本研究では、主張を少なくとも次の六種類に分類する。

1. 形式的主張
2. 実行モデル主張
3. 実証対象主張
4. 実装テスト主張
5. 研究仮説
6. 範囲外主張

形式的主張とは、公理、定義、補題、定理として証明可能なものである。

実行モデル主張とは、TypeScript、Python、JSON fixture、検証スクリプトなどで再現できるものである。

実証対象主張とは、国別データ、配送データ、GISデータ、候補生成データ、多言語ベンチマークなどを用いて検証すべきものである。

実装テスト主張とは、API、SDK、CLI、CI、schema validation、compatibility matrixによって確認できるものである。

研究仮説とは、理論的に有望だが、まだ実証や監査が不足しているものである。

範囲外主張とは、AMTが主張しないものである。

この分類により、AMTは過剰主張を避ける。

例えば、

- 構造距離と同値類の定義は形式的主張である。
- 候補生成fixtureは実行モデル主張である。
- 世界規模の候補生成完全性は実証対象主張であり、現時点では未完了である。
- ZK回路の暗号安全性はAMT本体の範囲外であり、ZK専用リポジトリと外部監査が必要である。

このように、AMTは何を証明済みとし、何を検証中とし、何を主張しないかを分ける。

---

## 2.12 既存手法との関係表

AMTと既存手法の関係を、簡略化して示す。

| 手法 | 主な出力 | 強い点 | AMTから見た限界 |
| --- | --- | --- | --- |
| 住所正規化 | 標準化表現 | 表記ゆれを減らす | 参照対象の同一性は決めない |
| ジオコーディング | 座標 | 地図・距離・検索に強い | 垂直・入口・履歴・目的差を単独では扱えない |
| 郵便番号 | 区域コード | 圧縮・仕分けに強い | 普遍的識別子ではない |
| GIS | 空間データ | 境界・道路・地物に強い | 社会的参照や目的別十分性は別問題 |
| Place ID / POI ID | 事業者ID | 検索・レビュー・地図連携に強い | 発行主体に依存する |
| DID | 主体識別子 | 分散識別に強い | 住所参照の導出規則は与えない |
| VC | 署名付き資格情報 | 発行者・保持者・検証者モデルに強い | Credential内の住所参照の正しさは別途必要 |
| ZK | 秘匿証明 | 条件だけを証明できる | 悪い住所解決を修復しない |
| 商用住所API | 検証結果 | 実務データと運用に強い | 出典・失敗時挙動・比較条件が閉じている場合がある |
| AMT | 参照対象または安全な未解決状態 | 同一性・履歴・目的依存・棄却を扱う | 実データ検証と地域別取材が必要 |

この表が示すように、AMTは他の手法の代替ではなく、それらを接続する参照理論である。

---

## 2.13 AMTの新規提案

ここまでの議論は、既存手法の限界を示すためだけのものではない。

本章の本来の目的は、既存手法の間に欠けている対象を明確にし、その対象を扱うための新しい理論層を提案することである。

AMTの新規提案は、次の七つに整理できる。

---

### 2.13.1 参照対象層の導入

第一の提案は、住所処理に「参照対象層」を導入することである。

従来の住所処理は、多くの場合、次のような変換として扱われる。

```text
住所文字列
  -> 正規化文字列
  -> 住所要素
  -> 座標
  -> 郵便番号
  -> 検証結果
```

AMTは、この列の中に欠けている層を置く。

```text
住所文字列
  -> 候補集合
  -> 参照対象候補
  -> 証拠に基づく同値類
  -> 目的安全な参照対象
  -> PID または未解決状態
```

ここで重要なのは、AMTが「住所文字列をきれいにする」理論ではなく、「住所表現が指す対象を安全に扱う」理論である点である。

この参照対象層を導入すると、既存手法は競合ではなく部品になる。

- 正規化は候補生成の前処理になる。
- ジオコーディングは空間証拠になる。
- 郵便番号は圧縮証拠になる。
- Place IDは外部参照証拠になる。
- DID/VCは発行者・主体・Credential層になる。
- ZKは参照対象に関する条件証明層になる。

AMTの新規性は、これらを一つの参照決定問題へ接続する点にある。

---

### 2.13.2 安全な未解決状態を出力として定義する

第二の提案は、未解決状態を失敗ではなく正式な出力として定義することである。

多くの住所システムは、入力に対して何らかの結果を返すことを期待される。その結果、曖昧な住所、出典が不足している住所、プライバシー上公開できない住所に対しても、もっともらしい答えを返す危険がある。

AMTでは、解決器を全域関数として定義しない。

\[
R : S \times U \times E \to R_t
\]

ではなく、次のように定義する。

\[
R : S \times U \times E \to R_t \cup \{\bot\}
\]

ここで、\(\bot\) は単なるエラーではない。これは、未解決、曖昧、拒否、手動確認、出典不足、ライセンス不適合、プライバシー制約を含む安全状態である。

この提案により、住所処理の評価は「どれだけ答えたか」ではなく、「答えるべきときに答え、答えてはいけないときに棄却したか」へ変わる。

---

### 2.13.3 目的依存の住所十分性

第三の提案は、住所の十分性を目的依存にすることである。

同じ住所表現でも、用途によって必要な情報は異なる。

例えば、

- 地図表示
- 通常配送
- 高額商品の配送
- 医薬品配送
- 法的通知
- ホテル受取
- 匿名配送
- ZKによる地域所属証明
- 災害時避難所案内

では、必要な精度、証拠、鮮度、開示範囲が異なる。

AMTでは、目的集合を \(U\) とし、住所解決を次のように目的依存にする。

\[
\mathcal{R}_t(s,u,E)
\]

ここで \(u \in U\) は利用目的である。

この定式化により、同じ住所でも次のような判断が可能になる。

```text
地図表示には十分
通常配送には要確認
高額配送には不十分
国レベルZK証明には十分
部屋レベル開示は禁止
```

これは既存の「住所が正しいか/正しくないか」という二値判定を拡張する。

---

### 2.13.4 構造距離による同一性の構成

第四の提案は、住所同一性を文字列一致や座標一致ではなく、構造距離から構成することである。

AMTでは、候補参照対象の間に構造距離 \(D_t\) を置く。

\[
D_t : C_t \times C_t \to \mathbb{R}_{\ge 0}
\]

この距離は、文字列差だけではなく、次の要素を含み得る。

- 行政階層
- 地理的位置
- 道路・経路
- 建物・入口
- 郵便番号
- 配送拠点
- 出典
- 履歴
- 言語表記
- 社会的連続性

閾値 \(\delta\) により、候補は同値類へまとめられる。

\[
c_1 \sim_{\delta,t} c_2
\]

この提案により、AMTは「同じ文字列だから同じ」「座標が近いから同じ」という単純な判定から離れる。

住所同一性は、複数の構造証拠から構成される対象になる。

---

### 2.13.5 履歴保存型PID

第五の提案は、住所識別子を履歴保存型にすることである。

住所や場所は変化する。

- 建物名が変わる。
- 道路名が変わる。
- 行政区画が変わる。
- 施設が移転する。
- 入口が変わる。
- 住所が分割される。
- 複数の実体が統合される。
- 旧地名が慣習として残る。

従来のIDは、この変化を単純な更新や上書きとして扱いやすい。

AMTでは、履歴グラフを導入する。

```text
old referent
  -> renamed
  -> split
  -> merged
  -> deprecated
  -> successor
```

PIDは、単なる現在のラベルではなく、履歴と系譜を持つ。

この提案により、AMTは「現在の住所」だけでなく、「なぜその住所がその実体を指し続けるのか」を扱える。

---

### 2.13.6 証明可能な比較方法

第六の提案は、住所システムの比較方法を再定義することである。

従来の比較は、正規化精度やジオコーディング精度に偏りやすい。

AMTでは、比較対象を次のように拡張する。

\[
B =
(
A_{\text{clean}},
R_{\text{candidate}},
Q_{\text{abstain}},
T_{\text{source}},
P_{\text{privacy}},
H_{\text{history}},
L_{\text{purpose}}
)
\]

このベンチマークは、単なる正答率ではなく、次を測る。

- 真の候補を落とさないか。
- 曖昧なときに棄却できるか。
- 出典を説明できるか。
- 履歴を保存できるか。
- 目的別に十分性を変えられるか。
- 必要以上の情報を漏らしていないか。

この提案により、AMTは商用APIや既存OSSに対して「勝利宣言」をするのではなく、同一条件で比較する枠組みを提供する。

---

### 2.13.7 プライバシー証明への接続点

第七の提案は、住所を直接渡すのではなく、住所に関する条件だけを証明できる接続点を定義することである。

AMTはZKそのものではない。

しかし、AMTが参照対象、品質、履歴、失効、目的、公開可能範囲をEnvelopeとして整理すれば、その上で次のような証明が可能になる。

- 配送可能区域に属する。
- 指定国または指定地域に属する。
- 住所Credentialが失効していない。
- 必要な品質閾値を満たす。
- 本人が特定目的に同意している。
- 配送会社だけが必要範囲を復号できる。

この接続点により、AMTは住所を公開するための理論ではなく、住所を過剰に公開せずに利用するための理論になる。

これは既存の住所検証APIとは異なる。

AMTは、住所全文を渡すことを前提とするのではなく、住所に関する必要最小限の事実を扱う方向へ拡張できる。

---

## 2.14 前半補強: 既存手法を置き換えずに欠けている層を定義する

本章の弱点は、既存手法の限界を列挙すると、AMTがそれらを否定する理論に見えてしまう点である。AMTの立場は逆である。既存手法は、AMTの証拠、圧縮、相互運用、認証、証明、実装の各層として必要である。しかし、それらは単独では「目的に対して安全に解決された参照対象」を定義しない。

既存手法の出力集合を次で置く。

\[
O =
N \cup G \cup Z \cup P \cup I \cup C
\]

ここで、\(N\) は正規化結果、\(G\) は座標、\(Z\) は郵便番号、\(P\) はPlace/POI ID、\(I\) は組織内ID、\(C\) はCredentialである。

AMTが必要とする対象は、

\[
\operatorname{SafeReferent}_{t,p}(s,E)
\in R_t\cup\{\bot\}
\]

である。したがって、AMTの主張は

\[
O \subseteq E_t
\]

であって、

\[
O = \operatorname{SafeReferent}
\]

ではない。

つまり、正規化結果、座標、郵便番号、Place ID、DID、VC、商用API結果は、AMTの入力証拠や比較対象になり得るが、AMTの最終対象そのものではない。

この関係を、依存行列として整理する。

| method | useful as | insufficient for |
| --- | --- | --- |
| normalization | expression alignment | referent identity |
| geocoding | spatial evidence | vertical/social/logistics identity |
| postal code | compression and routing evidence | universal identifier |
| GIS polygon | boundary evidence | purpose-specific sufficiency |
| Place/POI ID | local entity evidence | neutral AMT referent |
| DID/VC | credential and issuer layer | address resolution |
| ZK proof | privacy-preserving predicate | correcting bad resolution |
| commercial API | baseline and operational evidence | theory of safe abstention |

AMTの比較可能性は次で定義する。

\[
\operatorname{Comparable}(m_1,m_2)
\iff
\operatorname{SameDataset}
\land
\operatorname{SamePurpose}
\land
\operatorname{SameMetric}
\land
\operatorname{SameFailureTaxonomy}
\land
\operatorname{SameDisclosureBoundary}
\]

この条件を満たさない比較は、優劣の証明ではなく、観察または計画である。

本章の新しい提案は「既存研究の欠点探し」ではない。提案は、既存手法の出力を証拠として受け取り、それらを目的相対的な安全参照へ写像する中間層を明示することである。

```text
normalization / geocoding / postal code / GIS / DID / VC / ZK / API
  -> evidence and compatibility layer
  -> AMT safe referent or abstention
```

この補強により、第2章は比較章ではなく、AMTがどの空白を埋めるのかを定義する章になる。

---

## 2.15 本章のまとめ

本章では、既存手法とAMTの関係を整理した。

第一に、既存手法はそれぞれ重要であり、AMTはそれらを否定しない。

第二に、住所正規化は表現を整えるが、同一性を保証しない。

第三に、ジオコーディングとGISは空間情報として強力だが、垂直参照、機能的参照、社会的参照、目的別十分性を単独では扱えない。

第四に、郵便番号と住所標準は圧縮と相互運用性に有効だが、普遍的な住所識別子ではない。

第五に、Place ID、POI ID、DID、VC、商用APIは有用だが、住所参照の導出規則を単独では与えない。

第六に、AMTが補うべき欠けている対象は、目的に対して安全に解決された参照対象、または安全な未解決状態である。

第七に、AMTの評価は正答率だけでは足りない。候補リコール、棄却品質、出典透明性、プライバシー漏えい、履歴保存、目的別損失を含める必要がある。

第八に、AMTは既存標準や商用サービスに対して勝利宣言をする理論ではない。比較条件を明確にし、何を証明し、何を未検証とし、何を主張しないかを整理する理論である。

第九に、AMTの新規提案は、参照対象層、安全な未解決状態、目的依存十分性、構造距離による同一性、履歴保存型PID、証明可能な比較方法、プライバシー証明への接続点である。

次章では、AMTが扱う「住所対象」と「登録可能実体」を定義する。すなわち、住所が指すものは何か、建物・部屋・入口・自然地理・文化地・一時施設・垂直参照をどのように実体として扱うかを定式化する。

## 2.16 保存チェックリスト

本章は、現行29章構成から次の主張を保存した。

- 住所の参照、圧縮、通信、履歴の役割。
- 既存手法は有用だが、参照対象の同一性を単独では定義しない。
- 正規化は必要だが十分ではない。
- ジオコーディングは座標を返すが、参照対象を完全には決めない。
- 郵便番号は圧縮層であり、普遍的識別子ではない。
- DID、VC、Place IDは住所参照の導出規則そのものではない。
- AMTの検証には、形式、実行モデル、実証、実装テスト、研究仮説、範囲外の分類が必要である。
- ベンチマークは、正答率だけでなく、候補リコール、棄却品質、出典透明性、プライバシー漏えい、履歴保存を含む。
- AMTは既存標準、GIS、郵便制度、DID、VC、商用APIを置き換えるとは主張しない。
- AMTは完全な世界規模住所解決を現時点で主張しない。
- AMTは既存手法の限界を述べるだけでなく、参照対象層、安全な未解決状態、目的依存十分性、構造距離、履歴保存型PID、比較方法、プライバシー証明接続点を提案する。

本章で導入した数理モデルは次の通りである。

- 正規化写像 \(\nu_t : S \rightharpoonup N_t\)
- ジオコーディング写像 \(g_t : S \rightharpoonup G_t\)
- 郵便番号写像 \(z_t : S \rightharpoonup Z_t\)
- 事業者ID写像 \(\operatorname{id}_i : R_t \rightharpoonup I_i\)
- 目的安全な参照解決 \(\mathcal{R}_t(s,u,E)\)
- 棄却可能な解決器 \(R : S \times U \times E \to R_t \cup \{\bot\}\)
- 拡張ベンチマーク \(B\)

本章の詳細比較表と出典別検証は、付録E「関連研究行列」と第12章「検証・ベンチマーク・限界・結論」に引き継ぐ。
