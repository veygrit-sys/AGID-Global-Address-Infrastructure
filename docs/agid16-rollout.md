# AGID16と国判定の段階導入

AGIDは、郵便番号で建物を絞れない地域でも、受取人が選んだピンを同じセルとして共有できるようにする。郵便番号や番地が整った国では、既存住所に入口や受取地点のピンを添える用途がある。どちらの場合も、住所の実在、配達可否、受取人の同意は別に確認する。

## 発行済みIDの読み方

東京駅の例は `JP05AV8TJGHD` → `JP05AV8TJGHD1MEQ`。先頭12文字は発行時の接頭辞と位置をそのまま保持する。続く `1` は形式番号、最後の `MEQ` は誤入力の検査値。4文字区切りの `JP05-AV8T-JGHD-1MEQ` も読める。チェックサムの対象は大文字ASCIIの先頭13文字。投影、各軸21ビットの量子化、Hilbert順序は共通である。[機械可読仕様と照合例](../sdk/agid-spec/agid-spec.json)

| 利用箇所 | 今回の利用方法 |
| --- | --- |
| TypeScriptコア | `encodeAGID` で12文字、`encodeAGID16` で16文字を発行。`decodeAGID` と `getAGIDCellKey` は両形式に対応 |
| 既存IDを渡す連携 | `toAGID16(issuedId)` で変換。既存のDB・QR作成側へ渡すときは `toLegacyAGID(input)` で検証・復元。不正値は `null` |
| CLI | `encode` と `batch encode` で `--id-length 16` を選択。`validate`、`decode`、`polygon`、`resolve` はどちらの形式も受け付ける |
| 地図 | 検索で両形式を受理。公開ホームの地図は入力した16文字を表示・コピーできる。メイン地図の保存キーには元の12文字を使う |
| スタンドアロンJS/TS SDK | 発行済みIDの変換・検証に対応。座標からの生成と地理的な復号はリポジトリのコアを使う |

座標から既存IDを作り直すと、境界データや海域接頭辞の修正が混ざり得る。既存IDの移行は文字列から行う。無効な16文字はエラーとして扱い、先頭12文字への切り捨てを避ける。CRCは誤入力を検出する仕組みで、発行者の署名とは別に扱う。

## 国境・海岸と接頭辞

南アフリカ、レソト、エスワティニは、Natural Earthの版固定Map Unitsで、複数ポリゴンと内側の穴を照合する。対象の旧矩形は候補から外す。共有する境界線上では `mapUnitMatch` が `relation`、候補コード、出典、版を返す。レソトと南アフリカの境界なら両方を残し、ID用接頭辞は候補コードの昇順で固定する。対象外の国との境界では、候補一覧は取込済み3か国の範囲に限られる。郵送先には本人が選んだ国を使う。データは1,000万分の1の地図用で、セルの大きさと同じ精度で国境を示すものではない。[Natural Earth Map Units](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/10m-admin-0-details/)

旧版 `411a49b` と同じ17地点を比較すると、期待した国または海域に一致した地点は8から17になった。ダーバン沖、マリオン島、エスワティニ西側を含む。全球精度を測るには、対象選定から独立した地点が別途必要になる。[17地点の座標と期待値](../src/testFixtures/southernAfricaCountryMapUnits.json) · [データ出典と版](../src/data/countryMapUnits.json)

登録済みの188海域には、旧版で全海域台帳を順に生成したときの接頭辞を固定した。旧台帳でサヴ海と重複したオマーン湾には `8F` を割り当てた。海域を開いた順番で接頭辞が変わっていた時代のIDも、元の位置へ復号できる。海域を追加するときは割り当て表に追記し、既存の値は維持する。[海域の割り当て表](../src/data/namedSeaPrefixes.json)

## 次の実行順

| 順序 | 対象 | 完了を判断する方法 |
| --- | --- | --- |
| 1 | Veygrit住所帳の保存・共有、構造化QR、APIの入力仕様、モバイル、PHP | 既存の12文字と新しい16文字を同一セル・同一保存キーとして読み、破損IDを拒否する。旧版アプリ用の共有も試す |
| 2 | 香港・マカオと周辺の中国本土、島しょ部のフィジーを次の境界候補にする | 公開可能な出典と地理的な対象範囲を記録し、陸側・水側・境界線の対照点で旧版と比較する。フィジーでは日付変更線を通るポリゴンと境界ボックスを先に検証する |
| 3 | 郵便番号が不十分な地域の登録画面 | ピン・現地表記・ランドマークを保存し、境界付近や測位誤差の大きいときは利用者が国・入口を確認できることを実端末で試す |
| 4 | 新規発行の既定切替 | 実際の保存・共有・再読込と端末上の初回・反復処理を確認した利用先から切り替える。設定を戻しても発行済みの両形式を引き続き読めるようにする |

## 再現

```sh
npm ci
npm run verify:agid16
npm run benchmark:agid16
npm run agid -- encode --lat 35.681236 --lon 139.767125 --id-length 16 --json
npm run agid -- encode --lat -28.9086735 --lon 28.988132 --json
```

速度計測は全球4,096点を決定的に選び、6面のセル・境界が一致することを確かめてから行う。出力の時間はウォームアップ後のバッチ平均の中央値で、個々の要求の95パーセンタイルとは異なる。国境データは `node scripts/build-country-map-units.mjs` で再生成できる。指定版の原典をローカルに置いた場合は、引数にGeoJSONのパスを渡す。

### 今回の計測結果

Node.js v24.22.3、Linux x64の同一改修版で、8バッチ（各12,288件）の中央値を比較した。

| 処理 | 12文字 | 16文字 |
| --- | ---: | ---: |
| 地域判定を含む座標からの生成 | 13.49 µs/件 | 15.56 µs/件 |
| IDからセルへの復号 | 3.91 µs/件 | 4.21 µs/件 |

別に旧版 `411a49b` と比較した全球4,096点では、位置部分、セル番号、境界はすべて一致した。座標から新規採番した場合は123点で接頭辞が変わった。119点は同じ海域の割り当て固定、4点は国・陸海判定の修正によるもの。過去IDを文字列から変換した場合は先頭12文字を保持する。計測時の負荷で生成時間にばらつきがあり、端末ごとの応答時間は別途測定する。
