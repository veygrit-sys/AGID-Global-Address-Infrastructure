# AGID Africa Repository Creation Plan

AGID Africa is staged as a continent index, five regional indexes, country or
territory parent packs, and logical child repositories for countries that need
province, city, postal-weak, or high-change split plans.

The first public GitHub wave creates only complete index repositories. Country
and child repositories stay logical until maintainers, source licenses, postal
policy, quality gates, and no-raw-address checks are ready.

## Wave 0: Create Now

These repositories are safe to publish now because they contain coordination
metadata, manifests, source policy, and quality gates, not raw address data.

```text
agid-africa-index
agid-africa-northern-africa-index
agid-africa-western-africa-index
agid-africa-eastern-africa-index
agid-africa-southern-africa-index
agid-africa-central-africa-index
```

Each index repository contains:

- `README.md`
- `manifest.json`
- `sources.json`
- `quality-gates.json`
- `repositories.json`
- `DATA_LICENSES.md`
- `LICENSE`
- `.github/workflows/validate.yml`

## Wave 1: Country And Territory Parents

Africa has 61 planned country or territory parent repositories. These represent
country packs and territory packs such as Nigeria, Kenya, Tanzania, Algeria,
Egypt, Democratic Republic of the Congo, South Africa, Morocco, Ghana, Uganda,
and other Africa address systems.

These repositories should not be created as empty shells. A country parent is
ready when it has:

- clear README scope
- AGID manifest
- address hierarchy model
- postal status, including weak or absent postal code policy
- source and license policy
- quality gates
- no-raw-address release policy
- synthetic fixtures only

## Wave 2: Logical Child Repositories

Africa has 300 planned child repositories. Child repositories are justified for:

- large population countries
- many first-level administrative divisions
- high postal weakness
- high humanitarian or field delivery complexity
- large metropolitan areas
- high pull request pressure
- dataset sizes that should be split from the country parent

Examples include Algeria, Democratic Republic of the Congo, Egypt, Kenya,
Tanzania, Nigeria, Ethiopia, and South Africa.

## Africa-Specific Data Boundary

Africa packs must handle more than formal postal addressing. The data model must
support:

- postal-code-weak countries
- postal-code-absent areas
- informal settlements
- rural delivery points
- nomadic and pastoral routes
- islands, deserts, wetlands, lakeshores, and remote roads
- humanitarian delivery contexts
- de facto or special regional display policies

Public GitHub repositories may store rules, manifests, source notes, synthetic
fixtures, and quality metadata. Large GIS extracts, routing graphs, building
polygons, search indexes, OSM or Overture extracts, humanitarian datasets, and
generated caches must stay in external content-addressed packs.

## Validation

Generated by:

```text
npm run generate:africa-repo-plan
npm run prepare:africa-index-repos
```

Validated by:

```text
npm run verify:repository-split-allocation
```

The generated GitHub repositories also include a lightweight JSON validation
workflow.
