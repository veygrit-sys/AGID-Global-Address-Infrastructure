# AGID Asia Repository Creation Plan

This document defines the first safe GitHub creation wave for AGID Asia data.

## Conclusion

Do not create every Asia repository at once. The Asia plan currently contains
842 logical repositories:

- 1 continent index repository
- 6 region index repositories
- 50 country or territory parent repositories
- 785 state, province, prefecture, city, metro, or special child repositories

The first physical GitHub wave should create only the 7 index repositories.
Country parents and child repositories stay in the generated plan until
maintainers, source licenses, datasets, and review ownership are ready.

## Wave 0: Create Now

These repositories are safe to create immediately under `dawnportinfo-design`:

```text
agid-asia-index
agid-asia-caucasus-index
agid-asia-east-asia-index
agid-asia-southeast-asia-index
agid-asia-south-asia-index
agid-asia-central-asia-index
agid-asia-middle-east-index
```

The index repositories should contain coordination metadata, governance, source
license summaries, country pack pointers, postal status, and conformance status.
They should not contain raw personal addresses.

## GitHub Owner Requirement

`dawnportinfo-design` is treated by GitHub as a user account, not an organization.
Repository creation under that owner must be run while authenticated as
`dawnportinfo-design`, or after converting/mirroring the project into an
organization where maintainers have repository creation permission.

Do not run the physical creation command from another authenticated user account.
GitHub CLI may create repositories under the current authenticated user instead
of the intended owner when the owner is not an organization that the token can
administer.

## Wave 1: Country And Territory Parents

Create the 50 country and territory parent repositories after each pack has:

- a maintainer or region owner
- source and license notes
- no-raw-address release gate status
- country or territory address hierarchy rules
- breadcrumb reconstruction rules
- postal status, including no-postal-code and weak-postal-code classification
- display policy for special or disputed areas
- safe synthetic fixtures

Examples:

```text
agid-country-jp
agid-country-cn
agid-country-in
agid-country-id
agid-country-ph
agid-country-tr
agid-country-ae
```

## Wave 2: Child Repositories

Create the 785 child repositories only when there is clear operational pressure:

- large source data volume
- frequent pull requests
- separate local maintainer group
- separate source license boundary
- high update frequency for a province, prefecture, city, metro area, or special region

Examples:

```text
agid-jp-tokyo-23
agid-cn-shanghai-city
agid-in-delhi-metro
agid-id-jakarta-metro
agid-ph-metro-manila
agid-tr-istanbul
```

## Caucasus And Special Regions

AGID keeps `AM`, `AZ`, and `GE` canonical under Asia/Caucasus for repository
placement. This is a technical data organization rule, not a political claim.

Disputed or special regions must be represented as technical address identifiers
with explicit display policy. Repository placement must not imply sovereignty,
recognition, or territorial ownership.

## Data Boundary

GitHub repositories may store:

- address breadcrumb schema
- administrative hierarchy ids
- AGID id allocation ranges
- country and region rendering rules
- source metadata
- quality score rules
- conformance fixtures
- synthetic examples

External storage should hold:

- building polygons
- precise private coordinates
- search indexes
- map tiles
- OSM or Overture extracts
- hydrographic datasets
- cache artifacts
- large generated country packs

## Generated Files

The executable plan is generated by:

```bash
npm run generate:asia-repo-plan
```

The generated manifest is:

```text
data/global_entities/agid-asia-repository-creation-plan.json
```

Validation is included in:

```bash
npm run verify:repository-split-allocation
```
