# Sint Maarten Postal Context M2 review

## Result - excluded from postcode data creation; M2 remains unmet

The Universal Postal Union September 2025 no-postcode list includes Sint Maarten (Dutch part). The UPU Sint Maarten sheet (11/2011) and the UPU designated-operator list (12 March 2025) identify Postal Services Sint Maarten (PSS). BTP publishes postal-sector regulation and a PSS concession link, while a 17 July 2024 Sint Maarten government page supplies a dated operator-activity marker. None supplies a postcode assignment or reusable postal Polygon/MultiPolygon.

## Corrected address and ID detail

The AGID address definition now removes the unsupported four-digit postcode rule and keeps recipient, street, house number, city and country as typed address fields. Region, district and neighbourhood may remain independently typed context where another authoritative source supplies them. A future building display requires a separately rights-cleared civic identity and explicit building relation. No address, building, administrative ID or AGID cell becomes postal authority.

The existing generated SX country pack is retained as synthetic planning research, but its generated localities, planning cells and draft codes are explicitly excluded from PSS assignment, search and Polygon/MultiPolygon promotion.

## Exact evidence and reproducibility

Five exact official bodies totaling 1,116,875 bytes were fixed outside Git with SHA-256. The offline inspector accepts only those filenames, sizes and digests, validates three PDF page counts and country/operator/no-postcode markers plus two HTML regulator/operator/date marker sets, and emits only aggregate zero-production receipts. Missing, renamed, additional or changed bodies fail closed. Raw source bodies and government page contents remain outside Git.

## Application and polygon-quality boundary

Shared deterministic contracts passed for normalization, loading, no-match, multiple candidates, API failure, invalid geometry, Polygon/MultiPolygon-only rendering, fit, translucent fill, clear outline, clear and re-search. They do not prove an SX runtime. The in-app Browser failed during Windows ACL setup; the ambient port had no listening process, and safely starting the isolated app would have required writable dependency links into another worktree, which was rejected. Since there is no legitimate SX postcode input or postal polygon, no browser area E2E, positive visual result or synthetic surface is claimed.

## Rights, retry and promotion gate

Public access to UPU, BTP and government reference pages does not grant processing, derivation, redistribution or public-serving rights for a postal dataset. Keep SX blocked and do not re-check before 2026-12-02 or before the pending-country sweep completes, unless PSS, BTP, UPU or another competent authority announces a postcode system.

M2 can be reconsidered only after a current complete authoritative assignment denominator, compatible rights, fixed real postal Polygon/MultiPolygon artifacts and actual SX API/app visual verification exist. Provider contact, registration, authentication, terms acceptance, contract, payment, protected-data access, destination creation, publication or deployment needs explicit approval.
