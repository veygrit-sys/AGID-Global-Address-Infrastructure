# AGID Americas Repository Creation Plan

This document defines the first safe GitHub creation wave for AGID Americas data.

## Conclusion

Do not create every Americas repository at once. The Americas plan currently contains
340 logical repositories:

- 1 continent index repository
- 8 region index repositories
- 60 country or territory parent repositories
- 271 state, province, territory, city, or metro child repositories

The first physical GitHub wave should create only the 9 index repositories. Country
parents and child repositories stay in the generated plan until maintainers, source
licenses, datasets, and review ownership are ready.

## Wave 0: Create Now

These repositories are safe to create immediately under `dawnportinfo-design`:

```text
agid-americas-index
agid-americas-north-america-index
agid-americas-central-america-index
agid-americas-north-atlantic-territories-index
agid-americas-caribbean-index
agid-americas-us-territories-index
agid-americas-south-america-index
agid-americas-chile-territories-index
agid-americas-french-oceanic-territories-index
```

The index repositories should contain coordination metadata, governance, source
license summaries, country pack pointers, and conformance status. They should not
contain raw personal addresses.

## GitHub Owner Requirement

`dawnportinfo-design` is treated by GitHub as a user account, not an organization.
Repository creation under that owner must be run while authenticated as
`dawnportinfo-design`, or after converting/mirroring the project into an
organization where maintainers have repository creation permission.

Do not run the physical creation command from another authenticated user account.
GitHub CLI may create repositories under the current authenticated user instead
of the intended owner when the owner is not an organization that the token can
administer.

## Wave 1: Country Parents

Create the 60 country and territory parent repositories after each pack has:

- a maintainer or region owner
- source and license notes
- no-raw-address release gate status
- country or territory address hierarchy rules
- breadcrumb reconstruction rules
- safe synthetic fixtures

Examples:

```text
agid-country-us
agid-country-ca
agid-country-mx
agid-country-br
agid-country-ar
agid-country-co
agid-country-pe
agid-country-cl
```

## Wave 2: Child Repositories

Create the 271 child repositories only when there is clear operational pressure:

- large source data volume
- frequent pull requests
- separate local maintainer group
- separate source license boundary
- high update frequency for a state, province, city, or metro area

Examples:

```text
agid-us-california
agid-us-new-york-city
agid-ca-ontario
agid-mx-mexico-city-metro
agid-br-sao-paulo
agid-ar-greater-buenos-aires
agid-co-bogota-metro
agid-cl-santiago-metro
```

## Data Boundary

GitHub repositories may store:

- address breadcrumb schema
- administrative hierarchy ids
- AGID id allocation ranges
- country and region rendering rules
- source metadata
- quality score rules
- conformance fixtures
- synthetic examples

External storage should hold:

- building polygons
- precise private coordinates
- search indexes
- map tiles
- OSM or Overture extracts
- cache artifacts
- large generated datasets

## Generated Files

The executable plan is generated by:

```bash
npm run generate:americas-repo-plan
```

The generated manifest is:

```text
data/global_entities/agid-americas-repository-creation-plan.json
```

Validation is included in:

```bash
npm run verify:repository-split-allocation
```
