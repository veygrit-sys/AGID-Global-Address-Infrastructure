# Panama Postal Context M2 review

PA remains M2-blocked. Current Correos Panamá primary material confirms the geolocated national postcode system launched on 7 May 2026, while two live official API observations consistently normalize `A7C95-69R3E` and expose one selected PICO cell among nine finite rectangular cells. The reviewed evidence does not provide a current complete immutable assignment denominator, compatible reuse/public-serving rights, or an approved AGID artifact driving the real app.

## Country-specific M2 definition

`M2_current_correos_panama_complete_geolocated_code_and_pico_cell_visualization` requires a current complete competent-authority release of every full code, accepted grid-only alias, estafeta prefix and postal-zone association, validity interval, correction, exception and typed area/non-area postal object. The denominator must be fixed by retrieval time, release or service version, stable identity, schema, coverage, exact bytes and SHA-256 under rights compatible with AGID processing, storage, derivation, redistribution and public serving. The launch announcement, client bundle, an area scalar, a single coordinate lookup or decoder response cannot substitute for that denominator.

Every drawable code must reconcile to finite closed valid Polygon/MultiPolygon geometry with official/derived/virtual class, source feature identity, reference date, CRS, topology, reproducible method, confidence and exceptions. An officially observed PICO cell may qualify only under a fixed public algorithm or immutable complete artifact and compatible rights. A three-by-three response neighborhood, postal-zone area scalar, administrative boundary, point, route, P.O. box, organization, address, building, buffer, hull, Voronoi/raster surface or AGID cell cannot be promoted as a postal area merely because the public portal can display it. Non-area objects must expose type and reason without fabricated surfaces.

An approved immutable artifact must drive the real PA API/app, normalize full and grid-only forms without inventing a prefix, handle loading, no-match, multiple candidates, API failure and invalid geometry, fit and render a translucent fill with a clear outline only for eligible real geometry, support clear and re-search, and display selected code, geometry kind, official/derived/virtual class, source, reference date and confidence.

## Fixed primary evidence

- Correos Panamá launch article: dated 7 May 2026, confirms a geolocated national system, precise home/building/point lookup and free citizen use through the official portal. Free lookup is not a bulk automation, caching, derivation, redistribution or public-serving licence.
- Official portal HTML, fixed JS and CSS: the current client calls `/api/location` and `/api/postal/decode`, accepts full or grid-only input and renders returned PICO cell bounds as translucent Leaflet rectangles with outlines. No Creative Commons, open-licence, reuse or redistribution marker was present in the reviewed portal bodies.
- Official live API: a public Panama City test point returned normalized `A7C95-69R3E`; decoding that code returned the same code. Both exact responses contained nine valid PICO cells and one selected cell. These are time-bound observations, not a complete fixed release or permission to republish household-scale cell geometry.
- UPU copyright page: written-permission and database-access restrictions are fixed for the separately governed UPU publication context.

Seven exact bodies total 1,037,823 bytes. The fail-closed inspector binds every body to its URL, byte count and SHA-256, validates the current API schema and finite cell bounds, and emits zero production records. API bodies, exact coordinate observations, cell geometry and screenshots remain outside Git.

## App and visual result

The actual isolated app returned HTTP 200 at `http://127.0.0.1:3019/`. Direct unmocked `GET /api/v1/postal/PA/A7C95-69R3E?geometry=geojson` returned HTTP 503 `Postal Context pack is unavailable`.

The in-app Browser failed before navigation while its Windows deny-read ACL sandbox initialized. Deterministic Playwright therefore queried `A7C95-69R3E Panama` against the actual app without mocking the Postal Context API. It returned two generic non-Panama geocoder results and selected a Halifax result; zero PA Postal Context requests occurred. The fixed image was manually inspected through the app: the background map and AGID grid were visible, but no Panama result, translucent postal fill, clear outline or postal source/date/confidence panel was visible. This is negative visual evidence, not a successful browser E2E.

## Decision and unblock condition
