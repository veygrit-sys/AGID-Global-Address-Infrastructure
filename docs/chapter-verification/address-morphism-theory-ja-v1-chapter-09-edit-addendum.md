# 住所写像論 日本語版 v1 第9章 追加・編集差分案

作成日: 2026-06-06

対象: `docs/address-morphism-theory-ja-v1-master.md` 第9章

目的: 第9章「クラスタと住所同値類」を、検証済みの参照同値関係、同値類安定性、bounded clustering、矛盾ゲート、PID発行安全性に合わせて強化するための差し込み文、定義、命題、反例、注意点をまとめる。

## 1. 編集方針

第9章では、「住所同値類」と「実装クラスタ」を明確に分ける。

```text
数理層:
  住所表現 a,b が同じ参照対象を持つなら同値

実装層:
  候補集合を、出典・構造距離・履歴・粒度・文脈でクラスタ化する

運用層:
  クラスタ代表を選び、条件を満たす場合だけPID発行へ進む
```

冒頭に、次を追加するとよい。

> AMTにおけるクラスタは、生住所文字列を一つの標準文字列へ潰すための処理ではない。クラスタは、複数の表面表現、旧住所、翻訳名、地図ラベル、郵便表記、自然地理名が同じ参照対象を指す可能性を、証拠つきで扱うための構造である。ただし、実装上のクラスタは数学的同値類そのものではなく、同値類の近似である。

## 2. 9.1に追加する三層モデル

9.1の直後に、次の表を追加する。

| 層 | 対象 | 安定性 | 危険 |
| --- | --- | --- | --- |
| 表面表現層 | 住所文字列、翻訳、略称、旧名 | 低い | 正規化衝突、表記揺れ |
| 参照同値類層 | 同じ参照対象を持つ表現のクラス | 条件付きで高い | split/merge、名称再利用 |
| 実装クラスタ層 | 証拠から作る有限候補群 | データ品質依存 | 誤統合、誤分割 |

追加本文:

> AMTの安定単位は、表面文字列そのものではなく、参照対象を保存する表現群である。ただし、実装が扱うクラスタは、その参照同値類を候補証拠から近似したものであり、常に真の同値類と一致するとは限らない。

## 3. 9.2 住所同値関係の定義を強化する

現行本文の

```text
x ~_{c,t,g} y
```

の前に、参照写像を入れる。

```text
ref_{c,t,g}: A_t -> E_{c,t,g}
```

ここで、

| 記号 | 意味 |
| --- | --- |
| \(A_t\) | 時刻 \(t\) に観測される住所表現 |
| \(E_{c,t,g}\) | 文脈、時刻、粒度で区別された参照対象 |
| \(ref_{c,t,g}\) | 住所表現から参照対象への写像 |

定義:

```text
a ~_{c,t,g} b
  iff
ref_{c,t,g}(a) = ref_{c,t,g}(b)
```

追加本文:

> 参照写像が明示されている場合、\(\sim_{c,t,g}\) は数学的な同値関係になる。すなわち、反射律、対称律、推移律を満たす。しかし、実装上の「近い」「似ている」「同じクラスタに入れられる」という関係は、この参照同値関係の近似であり、必ずしも同値関係ではない。

## 4. 9.2に追加する数理層と実装層の分離

次の表を追加する。

| 項目 | 数理層 | 実装層 |
| --- | --- | --- |
| 関係 | `ref(a)=ref(b)` | 構造距離、出典、履歴、文脈で近い |
| 性質 | 反射、対称、推移 | 非推移的になり得る |
| 失敗 | 参照写像が未定義または誤っている | 誤統合、誤分割 |
| 検証 | Leanで形式化可能 | GIS/実装テスト/監査で検証 |
| PID | 参照クラスから導出 | 発行ゲートを通過したクラスタから導出 |

追加本文:

> この分離により、AMTは数学的な同値類を定義しつつ、実装上は保守的なクラスタ近似を使える。クラスタが不十分な場合、AMTは無理に同値類を形成せず、`ambiguous` または `unresolved` を返す。

## 5. 9.3 粒度の定義を補強する

現行本文の粒度説明に、次を追加する。

```text
g in {
  country,
  administrative_area,
  locality,
  parcel,
  building,
  entrance,
  floor,
  unit,
  locker,
  delivery_route,
  natural_feature,
  natural_feature_part
}
```

追加本文:

> 粒度 \(g\) は、同値関係の意味を変える。建物粒度で同値な候補が、部屋粒度では非同値になることがある。湖全体の粒度で同値な候補が、湖岸の到達点粒度では非同値になることがある。したがって、AMTはクラスタを作るたびに粒度を明示する必要がある。

追加例:

| 入力 | 建物粒度 | 部屋粒度 | 配送粒度 |
| --- | --- | --- | --- |
| 中央ビル | 中央ビル全体 | 不足 | 不足 |
| 中央ビル501 | 中央ビルに属する | 501号室 | 入口、階、受取人が必要 |
| A湖 | 湖全体 | 該当なし | 到達点が不足 |
| A湖北岸 | 湖の一部 | 該当なし | 北岸候補として利用可能 |

## 6. 9.4 クラスタリング形式の修正

現行本文:

```text
候補集合 C に対し、クラスタリングは分割を返す。
```

修正案:

```text
候補集合 C に対し、クラスタリングは有界クラスタ族を返す。
実装方針によっては、各候補を一つのクラスタへ割り当てる分割として扱う。
```

形式:

```text
Pi_{\delta,c,t,g}: P_f(X_t) -> ClusterFamily_{c,t,g}
```

ここで、

```text
ClusterFamily_{c,t,g} = {K_1, K_2, ..., K_n}
```

各 \(K_i\) は有限候補集合の部分集合であり、文脈と粒度に応じて、分割、被覆、または有界クラスタ族として扱う。

追加本文:

> しきい値クラスタリングでは、近接関係が推移的になるとは限らない。AがBに近く、BがCに近くても、AがCに遠い場合がある。このとき単純な連結成分クラスタリングを使うと、A,B,Cが一つのクラスタに過統合される。AMTでは、クラスタ内の候補が有界条件を満たすことを要求し、近接連鎖による過統合を避ける。

## 7. 9.4に追加する構造的非類似度の対称化

次を追加する。

```text
\bar{D}_{c,t,g}(x,y)
  = max(D_{c,t,g}(x,y), D_{c,t,g}(y,x))
```

追加本文:

> 構造的非類似度 \(D\) は、文脈によって方向付きになる場合がある。たとえば、詳細住所から粗い住所への距離と、粗い住所から詳細住所への距離は同じではない。クラスタリングで対称的な判断が必要な場合、AMTは方向付き非類似度から対称化された \(\bar{D}\) を使う。

## 8. 9.5 安定な同値類の条件を明記する

現行本文は良いが、安定条件を表にすると強い。

| 安定しやすい条件 | 不安定になりやすい条件 |
| --- | --- |
| 同じ参照対象を保存する表記変更 | 建物分割、土地分筆 |
| 出典が独立して一致する | 同名異地、名称再利用 |
| 履歴グラフが連続している | 履歴欠落、境界変更 |
| 粒度が一致している | 建物粒度と部屋粒度の混在 |
| 競合証拠がない | 国、行政、建物ID、座標の矛盾 |
| 鮮度が十分 | 古いデータ、失効データ |

追加本文:

> 住所同値類安定性は、表面表現より参照クラスが安定し得るという条件付き性質である。安定性は、参照保存性、履歴連続性、出典一致、粒度一致、鮮度、矛盾の不在に依存する。

## 9. 9.6 クラスタ代表の選択を補強する

現行本文に、代表選択ルールを追加する。

| 代表選択方針 | 用途 |
| --- | --- |
| 公式代表 | 行政、法務、郵便 |
| 配送代表 | 入口、階、部屋、ロッカー、ルート |
| 表示代表 | UI、利用者説明、多言語表示 |
| 履歴代表 | 旧住所、新住所、lineage |
| 自然地理代表 | 地物名、到達点、管理施設 |
| PID代表 | 参照クラスから導く監査可能キー |

追加本文:

> 代表選択は、クラスタ内の同一性そのものではない。代表は、表示、配送、行政、履歴、PID発行などの目的に応じて選ばれる。したがって、代表文字列が変わっても参照クラスが保存される場合があるし、同じ代表文字列でも文脈や粒度が違えば別クラスタになる場合がある。

## 10. 9.7 誤統合と誤分割の補強

現行本文に、次の比較表を追加する。

| 失敗 | 定義 | 主な危険 | 回復策 |
| --- | --- | --- | --- |
| 誤統合 | 別実体を同じクラスタへ入れる | 別実体が同じPIDに固定される | split、失効、再発行、監査 |
| 誤分割 | 同一実体を複数クラスタへ分ける | 重複PID、履歴分断、証明不一致 | merge、lineage保存、重複検出 |

追加本文:

> PID発行では誤統合の危険が特に大きい。誤統合されたPIDは、異なる実体を同じ永続参照に結びつける。一方、誤分割も無害ではない。同一実体に複数PIDが発行され、配送履歴、credential、ZK証明、レピュテーションが分断される可能性がある。したがって、AMTは誤統合を厳しく防ぎつつ、誤分割をmerge監査とlineage保存で回復できるようにする。

## 11. 9.7に追加する矛盾ゲート

次のゲートを追加する。

```text
Conflict_{c,t,g}(x,y)
  -> not Mergeable_{c,t,g}(x,y)
```

代表的な矛盾:

| 矛盾 | 例 |
| --- | --- |
| 国境矛盾 | 同じ地名だが国が違う。 |
| 行政矛盾 | 州、市区町村、町名が一致しない。 |
| 座標矛盾 | 同名だが距離が大きすぎる。 |
| 建物矛盾 | 建物IDや地籍IDが違う。 |
| 部屋矛盾 | 同じ建物だが部屋番号が違う。 |
| 履歴矛盾 | split後の複数後継を同一視している。 |
| 配送矛盾 | 一方は成功、一方は失敗し続ける。 |
| 出典矛盾 | 信頼できる複数出典が違う実体を示す。 |

追加本文:

> 矛盾ゲートは、クラスタリングの安全装置である。名前、文字列類似、近接座標が強くても、国、行政、建物、部屋、履歴、配送、出典に重大な矛盾がある場合、AMTは同値形成を止める。

## 12. 9.8 同値類安定性の安全な定式化

現行本文の方向は正しい。章末に、次の定式化を入れるとよい。

### 定理 9.1 参照保存的表記変更に対する同値類不変性

文脈 \(c\)、時刻 \(t\)、粒度 \(g\) において、改名写像 \(r\) が参照対象を保存するとする。

```text
forall a, ref_{c,t,g}(r(a)) = ref_{c,t,g}(a)
```

このとき、

```text
r(a) ~_{c,t,g} a
```

であり、\(r(a)\) と \(a\) は同じ参照クラスを持つ。

解説:

> これはLeanの `equivalence_class_invariant_under_renaming` と `renamed_address_has_same_reference_class` に対応する。旧名、新名、翻訳名、ローマ字表記、略称を安全に扱うための定理である。

### 系 9.1 クラスPID不変性

PIDが参照クラスから発行されるなら、参照保存的表記変更はPIDを変えない。

```text
PID([r(a)]) = PID([a])
```

解説:

> PIDを生文字列から発行すると、この系は成り立たない。PIDは参照クラスまたはその十分に検証されたクラスタ近似から発行する必要がある。

第9章には、次の反例を入れると章が強くなる。

| 反例 | 示すこと | 正しいAMT挙動 |
| --- | --- | --- |
| AはBに近く、BはCに近いが、AはCに遠い | 近接関係は推移的とは限らない | 有界クラスタにする |
| 同名ビルが別地域にある | 名前一致だけでは同値でない | 行政・座標で分離 |

| 代表文字列が変わる | 代表と同一性は別 | 参照クラスを維持 |

## 14. 追加すべき命題

### 命題 9.1 数理同値類と実装クラスタの分離

実装クラスタは、参照同値類そのものではなく、出典、距離、履歴、文脈、粒度により構成される有限近似である。

### 命題 9.2 有界クラスタ命題

クラスタ内の任意の候補が、指定された構造的非類似度、出典整合性、文脈粒度、矛盾ゲートを満たす場合、そのクラスタはPID発行候補になり得る。

### 命題 9.3 誤統合優先回避命題

PID発行前のクラスタリングでは、誤分割より誤統合の回避を優先する。ただし、誤分割を回復するためにmerge監査と履歴保存を持つ。

### 命題 9.4 代表非同一性命題

クラスタ代表の変更は、参照クラスの変更を意味しない。同様に、同じ代表文字列は、参照クラスの同一性を保証しない。

## 17. 章末の差し替え案

第9章の最後に、次のまとめを追加するとよい。

> AMTにおけるクラスタは、住所表面表現を単一の標準文字列へ圧縮する処理ではない。クラスタは、複数の住所表現が同じ参照対象を指す可能性を、文脈、時刻、粒度、出典、履歴、品質、鮮度、矛盾ゲートに基づいて扱うための構造である。
>
> 数理的には、住所同値類は参照写像 \(ref_{c,t,g}\) によって定義される。参照対象を保存する表記変更では、住所表面表現が変わっても参照クラスは保たれる。しかし、実装上のクラスタはこの同値類の近似であり、誤統合と誤分割の危険を持つ。したがってAMTは、過剰な近接連鎖を避ける有界クラスタ、矛盾ゲート、粒度管理、代表選択、merge/split監査を必要とする。
