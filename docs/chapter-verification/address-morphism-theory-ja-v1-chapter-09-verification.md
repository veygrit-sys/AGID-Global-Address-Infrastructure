# 住所写像論 日本語版 v1 第9章 検証ノート

作成日: 2026-06-06

対象: `docs/address-morphism-theory-ja-v1-master.md` 第9章「クラスタと住所同値類」

目的: 第9章で述べるクラスタ、住所同値関係、粒度、クラスタ代表、誤統合、誤分割、住所同値類安定性が、Lean形式化、実装テスト、PID監査、履歴更新、既存の同値類安定性評価と整合するかを確認する。

## 1. 第9章の位置づけ

第9章は、AMTにおける「表記」と「参照対象」の分離を扱う章である。

候補生成では、同じ対象を指す複数の候補が出る。

```text
東京都千代田区丸の内1丁目9-1
Tokyo Station, Marunouchi
東京駅
旧表記
地図ラベル
郵便表記
```

これらを個別候補として扱うだけでは、同じ対象への証拠が分散する。一方で、似ている候補を過剰にまとめると、別の部屋、別の建物、別の同名地物、別の履歴状態が同じPIDへ結びつく。

したがって、第9章の中核は次の分離である。

| 層 | 内容 | 注意点 |
| --- | --- | --- |
| 数理層 | 参照写像により定義される住所同値類。 | 本当に同じ参照対象なら同値関係を満たす。 |
| 実装層 | 候補集合上の証拠つきクラスタ。 | 同値類の近似であり、誤統合・誤分割がある。 |
| 運用層 | 表示代表、配送代表、行政代表、PID発行対象。 | 代表選択と同一性を混同しない。 |

第9章は、同値類を無条件に安定と主張する章ではない。むしろ、どの条件で安定し、どの条件で分裂・統合・保留すべきかを定義する章である。

## 5. 主張別検証

### 5.1 CH09-C01 住所同値関係

本文は、文脈 \(c\)、時刻 \(t\)、粒度 \(g\) において、候補 \(x,y\) が同じ参照対象として扱えることを

```text
x ~_{c,t,g} y
```

と書いている。この方向は正しい。

ただし、数理的に安全にするには、参照写像を明示した方がよい。

```text
ref_{c,t,g}: A_t -> E_{c,t,g}
```

このとき、

```text
a ~_{c,t,g} b iff ref_{c,t,g}(a) = ref_{c,t,g}(b)
```

と定義する。Leanの `RefEquivalent` はこの形で形式化されている。

### 5.2 CH09-C02 同値関係の条件

Leanでは、`RefEquivalent` が反射律、対称律、推移律を満たすことが証明されている。

ただし、これは「参照写像が確定している数理層」の話である。実装上のクラスタ近接関係がそのまま反射・対称・推移を満たすとは限らない。

したがって本文では、次の二層を分けるべきである。

| 層 | 関係 | 性質 |
| --- | --- | --- |
| 数理層 | `ref(a)=ref(b)` | 真の同値関係。 |
| 実装層 | 距離、出典、履歴、文脈による近似 | 非推移的、条件付き、誤差あり。 |

### 5.3 CH09-C03 同じ参照クラス

Leanの `same_reference_yields_same_reference_class` により、参照同値な住所表現は同じ参照クラスを与えることが確認されている。

これは第9章の中心である。

```text
raw string changes
  -> reference preserved
  -> same reference class
  -> class-derived PID preserved
```

この流れにより、AMTは「文字列正規化」ではなく「参照クラス維持」を目標にする理論として書ける。

### 5.4 CH09-C04 クラスPID不変性

Leanの `class_pid_invariant_under_ref_equivalence` は、第9章からPID章へ接続する重要定理である。

意味:

```text
if ref(a) = ref(b)
then pidOfReferenceClass(ref(a)) = pidOfReferenceClass(ref(b))
```

したがって、PIDは生の住所文字列から直接発行するのではなく、参照クラスまたはその十分に検証された近似クラスタから発行するべきである。

ただし、実装上のクラスタが本当に参照クラスを近似しているかは、候補被覆、構造距離、出典、履歴、品質、鮮度、リスク、矛盾ゲートに依存する。

### 5.5 CH09-C05 参照保存的改名

Lean拡張の `ReferencePreservingRename` は、住所同値類安定性を安全に書くためのよい形式である。

```text
forall address, ref(rename(address)) = ref(address)
```

この条件があると、`equivalence_class_invariant_under_renaming` と `renamed_address_has_same_reference_class` により、改名後の住所表現が元の住所表現と同じ参照クラスを持つことが示せる。

この形なら、次のような表記変更を扱える。

| 変更 | 安定条件 |
| --- | --- |
| 日本語表記からローマ字表記 | 同じ実体を参照すること。 |
| 旧行政表記から新行政表記 | lineageが同じ対象を保存すること。 |
| 略称から正式名称 | 同じ対象を指す出典があること。 |
| 翻訳名から現地名 | 参照対象が同一であること。 |

### 5.6 CH09-C06 矛盾ゲート

Leanの `conflict_gate_prevents_ref_equivalence` は、誤統合対策の形式的核である。

本文の9.7では誤統合を扱っているが、ここに明示的な矛盾ゲートを入れるべきである。

代表的な矛盾:

| 矛盾 | 説明 |
| --- | --- |
| 国の不一致 | 同一表記でも国が違う。 |
| 行政階層の不一致 | 州、市区町村、町名が矛盾する。 |
| 座標距離の過大 | 同じ名称だが遠すぎる。 |
| 建物IDの不一致 | 同じ住所表記だが建物が違う。 |
| 部屋・階・ロッカーの不一致 | 建物粒度では近いが配送粒度では別。 |
| 履歴方向の矛盾 | 旧住所から複数の後継へ分裂している。 |
| 配送履歴の矛盾 | 一方は成功し一方は失敗し続ける。 |

このゲートにより、AMTは「近いから同じ」とは言わない。

### 5.7 CH09-C07 実装クラスタは近似である

第9章本文は「クラスタを住所同値類の近似として扱う」と述べており、これは正しい。

ただし、9.4の「クラスタリングは分割を返す」は少し強い。実装では各候補を一つのクラスタに割り当てるため分割に近いが、理論上は重複候補、粒度差、複数文脈でクラスタ族または被覆として扱う方が安全である。

推奨表現:

```text
Pi_{\delta,c,t,g}: P_f(X_t) -> ClusterFamily_{c,t,g}
```

必要に応じて、`ClusterFamily` が分割になる条件を別に置く。

### 5.8 CH09-C08 構造的非類似度の対称化

実装では、方向付きの `structuralDistance` から、クラスタリング用の対称化された `structuralDissimilarity` を作っている。

テストでは、AからBへの距離とBからAへの距離が異なる場合でも、クラスタリングでは最大値を使って対称化し、危険な片方向近接による統合を避けている。

本文では次を入れるとよい。

> 構造的非類似度は、通常の距離とは限らない。クラスタリングで対称性が必要な場合、方向付き非類似度 \(D\) から \(\bar{D}\) を作る。たとえば \(\bar{D}(x,y)=\max(D(x,y),D(y,x))\) とすることで、片方向だけ近い候補を安易に統合しない。

### 5.9 CH09-C09 近接連鎖と有界クラスタ

実装テストでは、次の反例を確認している。

```text
A close to B
B close to C
A far from C
```

単純な推移的連結成分でクラスタを作ると、A,B,Cが同じクラスタになってしまう。しかし実装では、クラスタ内のすべての既存メンバーと候補が閾値以内であることを要求し、AとCが遠い場合に過統合を防ぐ。

これは第9章で必ず入れるべき反例である。

### 5.10 CH09-C10 クラスタ代表

本文の「代表選択を同一性と混同してはいけない」は正しい。

実装テストでは、クラスタ代表の canonical field が、単に長いラベルではなく、出典信頼度と証拠合意に基づいて選ばれることを確認している。

代表選択は文脈依存である。

| 文脈 | 代表に向くもの |
| --- | --- |
| 行政 | 公式住所、公式行政名 |
| 配送 | 入口、階、部屋、ロッカーを含む表現 |
| 利用者表示 | 分かりやすい現地語または利用者言語 |
| 歴史検索 | 旧住所または履歴ノード |
| 自然地理 | 地物名、到達点、管理施設 |
| PID発行 | 参照クラスから導かれる監査可能な正規キー |

したがって、代表文字列をPIDの根拠そのものにしてはならない。

### 5.11 CH09-C11 誤統合と誤分割

本文の「PID発行では誤統合の方が危険」という主張は正しい。

ただし、誤分割も無害ではない。

| 失敗 | 危険 | 回復策 |
| --- | --- | --- |
| 誤統合 | 別実体が同じPIDに固定される。 | split、失効、監査、再発行が必要。 |
| 誤分割 | 同一実体に複数PIDが発行される。 | merge、履歴保存、重複検出が必要。 |

PID lifecycle tests では、PID merge と split が、秘密の履歴ルートや候補割当を公開せずに検証できることを確認している。

したがって本文では、誤分割を「修正できる場合がある」と書きつつ、merge監査とlineage保存が必要と明記するとよい。

### 5.12 CH09-C12 住所同値類安定性

住所同値類安定性は、強い仮説である。ただし、無条件定理として書いてはいけない。

安全な定式化:

```text
参照対象を保存する表記変更では、
生文字列より参照クラスの方が安定する。
```

危険な定式化:

```text
住所同値類は常に安定である。
```

反例:

| 反例 | 何を示すか |
| --- | --- |
| 建物分割 | 元クラスタが複数クラスタへ分かれる。 |
| 建物統合 | 複数クラスタが一つへ統合される。 |
| 住所名称再利用 | 同じ名前が別実体を指す。 |
| 自然地理境界差 | 出典によりクラスタ範囲が変わる。 |
| 災害後仮設住所 | 参照対象と到達点が変わる。 |
| 行政境界変更 | 管轄文脈と配送文脈の同値がずれる。 |

第9章では、安定性を「傾向」「条件付き命題」「検証対象」として扱うのが正しい。

## 6. 第9章で弱めるべき点

| 注意点 | 理由 | 修正文 |
| --- | --- | --- |
| 実装クラスタを数学的同値類と同一視する | 実装クラスタには誤差がある。 | クラスタは同値類の証拠つき近似と書く。 |
| `~` が常に同値関係だと書く | 実務上の近接関係は非推移的になり得る。 | 参照写像で定義される数理層では同値関係と書く。 |
| クラスタリングは常に分割を返す | 複数粒度・複数文脈では被覆やクラスタ族が自然。 | 有界クラスタ族と書き、分割は条件付きにする。 |
| 表記変更なら常に同じクラス | 名称再利用や境界変更がある。 | 参照保存的表記変更なら同じクラスと書く。 |
| 誤分割は安全と書く | duplicate PIDや履歴分断が起きる。 | 誤統合より回復しやすいが監査が必要と書く。 |
| 代表文字列を同一性とみなす | 代表は文脈依存で変わる。 | 代表は表示・運用上の選択と書く。 |

## 7. 追加すべき命題

### 命題 9.1 参照同値類定義命題

文脈 \(c\)、時刻 \(t\)、粒度 \(g\) において、参照写像 \(ref_{c,t,g}\) が定義されているとする。このとき、

```text
a ~_{c,t,g} b iff ref_{c,t,g}(a) = ref_{c,t,g}(b)
```

で定義される関係は同値関係である。

解説:

> これはLeanの `RefEquivalent` と反射・対称・推移定理に対応する。

### 命題 9.2 クラスPID不変命題

PIDが生住所文字列ではなく参照クラスから発行されるなら、参照同値な住所表現は同じPIDを持つ。

```text
a ~ b -> PID([a]) = PID([b])
```

解説:

> Leanの `class_pid_invariant_under_ref_equivalence` に対応する。

### 命題 9.3 参照保存改名不変命題

改名写像 \(r\) が参照対象を保存するなら、任意の住所表現 \(a\) について \(r(a)\) は \(a\) と同じ参照クラスに属する。

解説:

> 旧名、新名、翻訳名、ローマ字表記、略称を扱うための命題である。

### 命題 9.4 矛盾ゲート命題

国、行政階層、建物、部屋、座標、履歴、配送履歴に矛盾があり、その矛盾が同一参照を排除するなら、二つの候補を同じクラスタへ統合してはならない。

解説:

> Leanの `conflict_gate_prevents_ref_equivalence` に対応する。

### 命題 9.5 有界クラスタ命題

候補が既存クラスタの一部メンバーに近いだけでは、クラスタ統合の十分条件にならない。候補はクラスタ内の全メンバーまたは代表と、指定された有界条件を満たす必要がある。

解説:

> A-B、B-Cは近いがA-Cが遠い反例を防ぐための命題である。

## 8. 総合評価

第9章の方向性は正しい。AMTが生住所文字列を直接安定単位にするのではなく、参照対象に基づく同値類またはその実装近似であるクラスタを扱うことは、住所写像論の中核である。

特に、次の点は強く採用できる。

| 採用点 | 評価 |
| --- | --- |
| クラスタが必要な理由 | 証拠分散と誤統合の両方を扱える。 |
| 住所同値関係の導入 | AMTの数理的中心。 |
| 粒度依存性 | 建物、部屋、自然地理で必須。 |
| 代表選択と同一性の分離 | 表示とPIDを安全に分けられる。 |
| 誤統合・誤分割の整理 | PID lifecycleと接続できる。 |
| 同値類安定性を条件付きにする姿勢 | 過剰主張を避けられる。 |

修正が必要なのは、数理的同値類と実装クラスタの分離、9.4の分割表現、参照保存的改名条件、矛盾ゲート、誤分割のリスク明示である。

推奨判定:
