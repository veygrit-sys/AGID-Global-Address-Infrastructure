# 住所写像論 日本語版 v1 第13章 検証ノート

対象: 第13章「社会的連続性」

本ノートは、第13章で主張されている「住所は地理的対象だけでなく、社会的主体や制度的連続性とも結びつく」という考えを、Lean形式化、GIS検証、実装テスト、反例分析に照らして検証したものである。

結論を先に述べると、第13章は採用してよい。ただし、「社会的連続性が住所同一性を常に決める」という定理としてではなく、「地理的同一性とは別に管理される証拠付き関係ラベル」として書く必要がある。

## 1. 検証結果の要約

| 観点 | 判定 | 理由 |
|---|---:|---|
| 地理だけでは住所同一性を完全に決められない | 採用 | 同一建物内の複数法人、私書箱、店舗、避難所、世帯などで反例がある。 |
| 社会的実体集合 `Y_t` と所在関係 `R_located(t)` | 採用 | 住所対象と社会的主体を分離するモデルとして有効。 |
| 移転を履歴グラフ上のエッジで扱う | 採用 | Leanの履歴グラフ保存命題、PID lifecycleテストと整合する。 |
| 社会的連続性を地理的同一性と同一視する | 不採用 | 会社が移転しても旧拠点と新拠点は別の物理実体である。 |
| 同じ名称なら同じ社会的主体である | 不採用 | 商号継承、フランチャイズ、なりすまし、運営者変更で破綻する。 |
| GISだけで社会的連続性を証明する | 不採用 | GISは位置・形状・包含関係を扱えるが、法人・運営・居住・権限の継続性は証明できない。 |
| 社会的連続性を証拠モデルとして扱う | 強く採用 | 出典、時刻、関係種別、権限、履歴を持つ場合にのみ安全に使える。 |

第13章の中心文は、次のように弱めると安全である。

> 住所同一性は、地理的同一性だけでは決まらない場合がある。会社、店舗、世帯、避難者、施設、行政窓口のような対象では、社会的連続性が重要になる。ただし、社会的連続性は無条件の同一性判定ではなく、出典と履歴を伴う条件付き関係として扱う。

## 2. 実行した検証

| 検証 | コマンド | 結果 |
|---|---|---:|
| Lean中核 | `lean formal\AMTCore.lean` | 成功 |
| Lean拡張 | `$env:LEAN_PATH='formal'; lean formal\AMTPaperExtensions.lean` | 成功 |
| GIS証明書生成とLean照合 | `npm run verify:gis:lean` | 成功 |
| 実装テスト | `npx tsx --test ...` | 69 tests pass |

実装テストでは、PID lifecycle、PID issuance audit、住所資格鮮度、重複防止nullifier、ZK address proof互換性、API/OpenAPI上の秘匿表面も通っている。これらは第13章の中核定理ではないが、社会的連続性を直接PIDや配送可能性へ短絡させないための応用層の安全性を支える。

## 3. Leanで確認できる部分

第13章の社会的連続性そのものは、社会制度、法人記録、運営主体、住民関係、災害支援記録に依存するため、Leanだけで完全証明する対象ではない。

ただし、次の周辺命題はLeanで確認されている。

### 3.1 観測衝突は完全解決を妨げる

`formal/AMTCore.lean` の `normalization_collision_prevents_perfect_resolution` は、異なる実体が同じ正規化観測へ潰れる場合、その観測値だけでは完全解決できないことを示す。

第13章では、これを次のように読む。

| 観測 | 衝突の例 | 含意 |
|---|---|---|
| 同じ住所文字列 | 同じビル内の複数法人 | 住所文字列だけでは法人主体を決められない。 |
| 同じ地理座標 | 1階店舗と2階事務所 | 座標だけでは利用主体を決められない。 |
| 同じ名称 | 同じ屋号の別運営店舗 | 名称だけでは社会的連続性を決められない。 |
| 同じ旧住所 | 移転後の旧拠点再利用 | 過去の所在だけでは現在の主体を決められない。 |

したがって、第13章の「地理だけでは足りない」という主張は、形式化された不可能性命題と整合する。

### 3.2 履歴グラフは社会的連続性の証拠を保持できる

`formal/AMTPaperExtensions.lean` の `LineageGraph` は、履歴を有向グラフとして扱う。

Leanでは、append-onlyな履歴拡張について次が確認されている。

| 命題 | 意味 |
|---|---|
| `append_only_lineage_preserves_node` | 既存ノードは履歴拡張後も残る。 |
| `append_only_lineage_preserves_edge` | 既存エッジは履歴拡張後も残る。 |
| `append_only_lineage_preserves_trace` | 既存の有限履歴列は拡張後も追跡可能である。 |

これは第13章の移転モデルを支える。記法としては、`y@x1 --relocated_to--> y@x2` のように表せる。

ただし、このエッジは「旧拠点と新拠点が同じ物理実体である」ことを意味しない。意味するのは、社会的主体 `y` に関する履歴関係が保存されるということである。

### 3.3 必須属性が欠けると目的別判定を通過できない

`formal/AMTCore.lean` の `missing_required_attribute_prevents_attribute_gate` は、目的別の属性ゲートに必要属性が欠けている場合、そのゲートを通過できないことを示す。

第13章では、これを関係ラベルの安全性に対応させられる。

| 関係ラベル | 必要な証拠の例 |
|---|---|
| `residesAt` | 居住資格、住民記録、本人同意、鮮度 |
| `registeredAt` | 法人登記、行政記録、時点 |
| `deliversTo` | 配送可能性、受取権限、配送履歴 |
| `owns` | 登記、契約、所有権記録 |
| `operatesAt` | 営業許可、店舗記録、運営主体 |

同じ場所にいることだけでは、これらの関係を自動的には満たさない。

## 4. GISで確認できる部分とできない部分

GIS検証は、空間関係を扱う点では有効である。

| GISで検証できるもの | 例 |
|---|---|
| 点が行政区域内にあるか | 東京都内、日本国内、配送区域内 |
| 建物・道路・島・湖・山などの位置関係 | 対象が地図上でどこにあるか |
| 旧区域と新区域の包含・重なり | 行政変更時の空間対応 |
| 候補集合の距離・近傍 | 同名地点の候補分離 |

一方で、GISだけでは次は検証できない。

| GISだけでは検証できないもの | 理由 |
|---|---|
| 同じ会社が移転後も同じ会社である | 法人番号、登記、契約、運営記録が必要。 |
| 同じ店名の店舗が同じ運営主体である | 屋号と運営主体は一致しない場合がある。 |
| ある世帯が同じ世帯として継続している | 住民・同意・時点・制度証拠が必要。 |
| 避難所にいる人が通常住所の居住者である | 災害支援上の仮想住所と居住住所は違う。 |
| 旧住所の利用者と新住所の利用者が同一である | 旧拠点の再利用や権限変更があり得る。 |

したがって、第13章では「GISで社会的連続性を証明する」と書かない方がよい。正しくは「GISは位置証拠を提供し、社会的連続性は制度証拠と履歴証拠を合わせて評価する」である。

## 5. 実装で確認できる部分

第13章と直接関係が強い実装上の確認は次である。

| 実装領域 | 第13章への意味 |
|---|---|
| PID lifecycle proof | 履歴更新、merge、splitの正当性を確認し、単純な同一視を避ける。 |
| PID issuance audit | 候補生成、クラスタ、unresolved判定、履歴更新を経たことを監査する。 |
| AMN envelope privacy | 私的住所、AOID、電話番号、座標を応答から漏らさない。 |
| Credential freshness proof | 古い資格や失効済み資格を使った社会的連続性主張を抑える。 |
| Duplicate nullifier | 同一住所・同一AOID・同一地域の二重登録防止を秘匿的に扱う。 |
| ZK proof compatibility | 住所証明、居住証明、配送可能性証明、AOID所有証明の衝突を抑える。 |

ただし、これらはAMT本体の第13章ではなく、応用層に近い。本文では「社会的連続性を証拠付きで扱う必要がある」という主張の補強として使うに留める。

## 6. 第13章の主要主張ごとの判定

### 6.1 地理的同一性だけでは十分でない

判定: 採用。

同じ建物や同じ住所表記が、複数の法人、世帯、部屋、私書箱、店舗、契約主体、配送先を含むことがある。これはLeanの観測衝突命題と整合する。

### 6.2 社会的実体を `Y_t` として分ける

判定: 採用。

地理的対象 `X_t` と社会的対象 `Y_t` を分けることで、住所写像論は次の誤りを避けられる。

| 誤り | 正しい扱い |
|---|---|
| 住所文字列 = 会社 | 住所文字列は会社主体への参照候補である。 |
| 座標 = 店舗 | 座標は店舗が所在する場所の一部である。 |
| 建物 = 世帯 | 建物は複数世帯を含み得る。 |
| 避難所 = 通常住所 | 避難所は災害時の支援到達先であり、通常居住地とは限らない。 |

### 6.3 所在関係は一対一ではない

判定: 強く採用。

所在関係 `R_located(t) <= Y_t x X_t` は、一般に一対一ではない。ここで `<=` は部分関係、`x` は直積を表す略記である。

| 型 | 例 |
|---|---|
| 多対一 | 同一ビルに複数法人が入る。 |
| 一対多 | 同じ会社が本社、支店、倉庫を持つ。 |
| 時間変化 | 同じ会社が移転する。 |
| 用途差 | 登記住所、配送先、請求先、営業場所が異なる。 |

この点は第13章で必ず明記するべきである。

### 6.4 移転は履歴グラフで扱う

判定: 採用。

移転は、物理拠点の同一性ではなく、社会的主体の履歴関係である。記法としては、`(y, x1, t1) --relocated_to--> (y, x2, t2)` と表せる。

ただし、次を同時に記録する必要がある。

| 項目 | 意味 |
|---|---|
| 主体 `y` | 法人、店舗、世帯、支援対象、施設など。 |
| 旧拠点 `x1` | 過去の所在地。 |
| 新拠点 `x2` | 現在または移転後の所在地。 |
| 時点 `t1,t2` | 有効期間。 |
| 関係ラベル | 移転、名称変更、合併、分割、権限移譲など。 |
| 出典 | 登記、行政記録、配送履歴、本人同意、運営記録など。 |

### 6.5 関係ラベルを潰してはいけない

判定: 強く採用。

第13章では、次の関係を一つの「住所」へ潰さないことが重要である。

| 関係 | 意味 |
|---|---|
| `locatedAt` | ある時点でそこに所在する。 |
| `residesAt` | 居住している。 |
| `deliversTo` | 配送可能である。 |
| `registeredAt` | 登記・登録上の所在地である。 |
| `owns` | 所有している。 |
| `operatesAt` | 事業や活動を行っている。 |
| `receivesSupportAt` | 災害支援や行政支援の到達先である。 |

たとえば、法人登記住所は配送先と異なる場合がある。住民票上の住所は現在の避難先と異なる場合がある。店舗の営業場所は法人本店所在地と異なる場合がある。

## 7. 反例分析

第13章は反例を入れることで大幅に強くなる。

| 反例 | 何を否定するか |
|---|---|
| 同じ店名だが運営会社が変わった | 名称一致による社会的同一性 |
| 会社が移転し、旧オフィスに別会社が入った | 旧住所による現在主体の同一性 |
| 同じビルに多数の法人がある | 地理的一点による社会的主体の一意性 |
| 家族構成が変わった | 住所と世帯の一対一対応 |
| 所有者が変わったが居住者は同じ | 所有と居住の同一視 |
| 居住者が変わったが所有者は同じ | 所有と居住の同一視 |
| 私書箱や宅配ロッカー | 物理居住と配送到達先の同一視 |
| 避難所・仮設住宅 | 通常住所と支援到達先の同一視 |
| フランチャイズ店舗 | ブランド名と運営主体の同一視 |
| 世界遺産・遺跡 | 文化的対象と住所文字列の単純対応 |

これらにより、「社会的連続性は重要だが危険でもある」という章の緊張感が出る。

## 8. 追加すべき命題

第13章には、次の命題を追加するとよい。

### 命題13.1 身分層分離原理

住所対象の同一性は、少なくとも地理的同一性、物理的同一性、制度的同一性、配送可能性、社会的連続性、履歴的連続性に分けて扱う必要がある。これらの一つを他のすべてへ還元してはならない。

### 命題13.2 地理的十分性の失敗

同一の地理的観測値に複数の社会的主体が対応する場合、その地理的観測値だけから社会的主体を完全に決定する解決器は存在しない。

これはLeanの観測衝突命題の第13章版として書ける。

### 命題13.3 証拠付き移転原理

社会的主体 `y` が `x1` から `x2` へ移転したと主張するためには、少なくとも主体識別子、旧所在地、新所在地、有効時刻、関係ラベル、出典が必要である。これらが欠ける場合、移転エッジは未解決として扱う。

### 命題13.4 関係ラベル非崩壊原理

`locatedAt`, `residesAt`, `deliversTo`, `registeredAt`, `owns`, `operatesAt` は互いに異なる関係であり、一つの住所同一性へ自動的に崩壊させてはならない。

### 命題13.5 社会的連続性の棄却可能性

社会的連続性を示す証拠が、より新しい証拠、失効情報、権限変更、運営主体変更、居住者変更、施設用途変更と衝突する場合、その社会的連続性主張は棄却またはunresolved化される。

## 9. 本文で避けるべき表現

| 避ける表現 | 推奨表現 |
|---|---|
| 住所の同一性は社会的連続性によって決まる | 住所同一性には社会的連続性が関与する場合がある。 |
| 会社が移転しても住所は同じである | 会社主体は継続し得るが、旧拠点と新拠点は別の物理実体である。 |
| 同じ店名なら同じ店舗である | 名称一致だけでは店舗主体の同一性を決められない。 |
| GISで社会的連続性を証明できる | GISは位置証拠を与えるが、社会的連続性には制度証拠が必要である。 |
| 社会的連続性があればPIDを統合できる | PID統合には目的、関係ラベル、履歴、出典、反例チェックが必要である。 |

## 10. 最終判定

第13章は、住所写像論を単なるGIS理論から社会的・制度的な参照理論へ拡張する重要章である。特に、会社、店舗、世帯、避難者、支援対象、施設、私書箱、配送ロッカー、行政窓口を扱うためには不可欠である。

ただし、社会的連続性は強いが危険な仮説である。正しい採用形は次である。

1. 地理的同一性とは分離する。
2. 関係ラベルを明示する。
3. 履歴グラフに載せる。
4. 出典と時刻を持たせる。
5. 証拠不足ならunresolvedにする。
6. 名称一致だけで同一視しない。
7. PID mergeや配送可能性へ短絡させない。

この修正を入れれば、第13章は第12章の履歴グラフ、第14章の文脈相対性、第18章の品質・評判、第25章の限界、AGID/AOID応用論文へ自然につながる。
