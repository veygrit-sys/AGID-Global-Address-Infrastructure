# 住所写像論 日本語版 v1 第2章 検証ノート

目的: 第2章の五つの基本仮説を、形式的に支えられる部分、実装で支えられる部分、作業仮説として残す部分へ分ける。第2章は導入層に属するため、後続章の動機として使えるが、単独で基礎定理の証明根拠にはしない。

## 3. 仮説別検証

## 3.1 CH02-C01 住所参照仮説

主張:

> 住所表現は、それ自体が実体ではなく、対象を指すための観測または手がかりである。

この主張は、第2章の中で最も強く採用できる。第6章の非単射観測不可能性、正規化衝突補題と直接接続する。異なる実体が同じ観測値を持つ場合、観測だけから真の実体を無条件に復元する完全解決器は存在しない。したがって、住所表現と参照対象を分離する必要がある。

対応する根拠:

| 根拠 | 内容 |
| --- | --- |
| `no_condition_free_perfect_resolver` | 非単射観測の下では無条件完全解決器が存在しない。 |
| `normalization_collision_prevents_perfect_resolution` | 正規化が異なる対象を同じ値へ潰す場合、完全解決できない。 |
| `addressMorphism.test.ts` | 近接タイは `ambiguous`、証拠不足は `unresolved` になる。 |

本文では強く書いてよい。ただし「住所は参照そのものである」という哲学的断定ではなく、「住所表現は対象参照を形成する観測である」と書く。

## 3.2 CH02-C02 住所圧縮仮説

主張:

> 住所は、複雑な地理的・社会的情報を人間や制度が扱える表現へ圧縮したものである。

この仮説は有効だが、現時点では作業仮説として扱う。Leanでは、非単射圧縮に完全復号器が存在しないという一般命題は支えられる。しかし、住所全体が常に圧縮であることや、都市化と住所情報量が必ず増加することは、情報量分析と実験が必要である。

対応する根拠:

| 根拠 | 内容 |
| --- | --- |
| `noninjective_compression_no_perfect_decoder` | 非単射圧縮では完全復号できない。 |
| `insufficient_bit_capacity_prevents_capacity_cover` | ビット容量が不足すれば対象集合を覆えない。 |
| `pidCollisionRisk.test.ts` | 有限長PIDは衝突リスク予算で扱う必要がある。 |

本文では「住所は情報圧縮である」と言い切るより、「本稿では住所を圧縮表現として捉える」と書く。第15章で数理化し、経験的測定は検証課題として残す。

## 3.3 CH02-C03 住所通信仮説

主張:

> 住所は、物理的、社会的、制度的な到達先を表す通信先として振る舞う。

この仮説は独創的であり、AGID/AOID、買い物Agent、MCP、配送、災害支援と相性がよい。しかし、第2章では定理として扱わない。通信仮説は、AMT本体の意味論から応用プロトコルへ進むための設計視点である。

対応する根拠:

| 根拠 | 内容 |
| --- | --- |
| 第20章 | 通信・登録・監査モデルで詳細化する。 |
| `issueIfAdmissible` | 候補返却と登録/発行を分ける抽象モデル。 |
| `addressMorphism.test.ts` | 候補表示、PID発行、履歴反映の実装挙動を確認。 |

本文では「住所は通信プロトコルである」と断定するより、「住所は通信先として解釈できる場面がある」と書く。IPアドレスやメールアドレスとの比較は例として有効だが、住所はそれらより曖昧で履歴的で文脈依存であることを必ず添える。

## 3.4 CH02-C04 住所履歴仮説

主張:

> 住所は現在値だけではなく、変更、分割、統合、継承、失効、訂正を含む履歴を持つ。

この仮説は強く採用できる。第12章の履歴グラフ保存命題と接続する。特に、append-onlyな履歴拡張が既存ノード、既存エッジ、既存トレースを保存することは、履歴を安全に追跡する基礎になる。また、単純な関数では分割を表せないことから、住所変更を単一の旧住所から単一の新住所への関数として扱うだけでは不十分である。

対応する根拠:

| 根拠 | 内容 |
| --- | --- |
| `append_only_lineage_preserves_node` | 履歴拡張は既存ノードを保つ。 |
| `append_only_lineage_preserves_edge` | 履歴拡張は既存エッジを保つ。 |
| `append_only_lineage_preserves_trace` | 履歴トレースは拡張後も保たれる。 |
| `functional_transition_cannot_represent_split` | 単純関数では分割を表せない。 |

本文では「住所保存則」という強い名前を使ってよい。ただし、物理学的な保存則ではなく、履歴グラフ上で参照関係を追跡する運用原理である、と明示する。

## 3.5 CH02-C05 社会的実体仮説

主張:

> 住所の同一性は、地理だけでなく社会的連続性とも結びつく場合がある。

この仮説は重要だが、最も慎重に扱う必要がある。会社、店舗、世帯、避難者、施設などは、地理的同一性と社会的同一性が一致しない場合がある。一方で、社会的連続性だけで住所同一性を決めると、なりすまし、商号継承、所有者変更、居住者変更、用途変更で誤る。

対応する根拠:

| 根拠 | 内容 |
| --- | --- |
| 第13章 | 社会的連続性を反例付きで検討する。 |
| 履歴グラフ命題 | 社会的連続性の証拠を履歴として保持できる。 |
| 第14章 | 用途によって重視する同一性が変わる。 |

本文では「住所の同一性は社会的連続性で決まる」と書かない。正しくは「地理的同一性、制度的同一性、社会的連続性、配送可能性を分離して扱う必要がある」である。

第2章の仮説は、後続章の動機として使う。証明根拠として使う場合は、必ず第6章、第10章、第11章、第12章、第14章、第15章などの形式章に接続する。

## 5. 弱めるべき表現

| 現在の方向 | 安全な表現 |
| --- | --- |
| 住所は参照である | 住所表現は対象参照を形成する観測である。 |
| 住所は情報圧縮である | 本稿では住所を損失を伴う圧縮表現として捉える。 |
| 住所は通信プロトコルである | 住所は到達や作用の宛先として通信先的に振る舞う場合がある。 |
| 住所は消滅せず写像される | 住所参照の変化は履歴グラフ上で追跡される場合がある。 |
| 住所の同一性は社会的連続性で決まる | 地理的同一性と社会的連続性は分離して評価する必要がある。 |

## 6. 最終判定

第2章は、論文全体の仮説地図として有効である。ただし、五つの仮説を同じ強度で扱うと危険である。

1. 住所参照仮説は、AMTの基礎として強く採用してよい。
2. 住所圧縮仮説は、情報理論章へ接続する作業仮説として採用する。
3. 住所通信仮説は、応用設計の視点として採用し、AMT本体の定理にはしない。
4. 住所履歴仮説は、履歴グラフ章の基礎として強く採用してよい。
5. 社会的実体仮説は、反例を含む挑戦的仮説として扱う。

この整理により、第2章は過剰な断定を避けながら、後続章の強い理論展開へ自然につながる。
