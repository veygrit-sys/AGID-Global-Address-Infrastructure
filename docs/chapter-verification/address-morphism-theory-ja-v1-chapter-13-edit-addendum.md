# 住所写像論 日本語版 v1 第13章 追加・編集差分案

対象: 第13章「社会的連続性」

本差分案は、第13章をより安全で検証可能な書き方にするための本文修正案である。中心方針は、社会的連続性を「同一性の最終決定因」ではなく、「証拠付きの関係ラベル」として扱うことである。

## 1. 章冒頭に追加する要約

第13章の冒頭に、次を追加するとよい。

> 本章では、住所が地理的対象だけでなく、法人、店舗、世帯、施設、避難者、行政窓口、配送先のような社会的主体とも結びつくことを扱う。ただし、本章は「住所の同一性は社会的連続性によって常に決まる」と主張しない。社会的連続性は、地理的同一性、物理的同一性、制度的同一性、配送可能性、履歴的連続性とは別の関係層である。したがってAMTでは、社会的連続性を履歴グラフ上の証拠付きエッジとして扱い、証拠が不足する場合はunresolvedに留める。

この追加により、第13章の主張の強さが最初に制御される。

## 2. 13.1の修正案

現在の論旨は良い。ただし「地理だけでは決まらない」という主張を、次のように明確化する。

> 地理的同一性は多くの住所処理に必要である。しかし、地理的同一性だけで、すべての住所同一性を決めることはできない。同じ建物に複数の法人が入る場合、同じ部屋を複数の世帯や事業が時期を変えて使う場合、同じ住所文字列が登記住所、配送先、請求先、営業場所として異なる意味を持つ場合がある。

続けて、次を入れる。

> したがって、AMTにおける住所解決器は、地理的候補を生成するだけでなく、その候補がどの社会的主体、制度的関係、配送関係、履歴関係に結びついているかを区別しなければならない。

## 3. 13.2の数理モデルを補強する

13.2では、社会的実体集合を次のように定義するとよい。

> 時刻 `t` における社会的実体集合を `Y_t` とする。ここで `Y_t` は、法人、店舗、学校、病院、行政窓口、世帯、避難者、支援対象、イベント、配送ロッカー、私書箱、運営主体などを含む。

所在関係は、単純な一対一対応ではなく、関係ラベル付きにする。記法としては `R_role(t) <= Y_t x X_t x P` と表せる。ここで `<=` は部分関係、`x` は直積を表す略記である。`X_t` は物理的・地理的対象集合、`P` は関係ラベル集合である。

例:

| 関係ラベル | 意味 |
|---|---|
| `locatedAt` | その時点で所在する。 |
| `residesAt` | 居住している。 |
| `registeredAt` | 登記・登録上の所在地である。 |
| `deliversTo` | 配送可能な到達先である。 |
| `owns` | 所有している。 |
| `operatesAt` | 営業・運営している。 |
| `receivesSupportAt` | 災害支援や行政支援の到達先である。 |

この修正により、「会社の所在地」「配送先」「居住地」「登記住所」を同じ関係として潰す危険を避けられる。

## 4. 13.3に追加する身分層表

13.3には、同一性の層を表として置くと読みやすくなる。

| 層 | 問い | 例 |
|---|---|---|
| 地理的同一性 | 同じ場所か | 同じ緯度経度、同じ行政区域内 |
| 物理的同一性 | 同じ建物・部屋・区画か | 同じ建物、同じ部屋、同じ階 |
| 制度的同一性 | 同じ登録・権限対象か | 法人登記、地籍、行政登録 |
| 配送同一性 | 同じ到達先か | 宅配ロッカー、私書箱、受取場所 |
| 居住同一性 | 同じ居住主体か | 世帯、個人、避難者 |
| 運営同一性 | 同じ運営主体か | 店舗、支店、フランチャイズ |
| 履歴的同一性 | 同じ系譜上にあるか | 移転、合併、分割、名称変更 |

この表の後に、次を追加する。

> これらの層は相互に関連するが、同一ではない。たとえば同じ物理拠点に複数の法人が存在し得る。同じ法人が複数の拠点を持ち得る。同じ配送先が通常の居住地とは限らない。同じ屋号が同じ運営主体を意味するとも限らない。

## 5. 13.4の移転モデルを強化する

移転モデルは、`(y, x1, t1) --relocated_to, s--> (y, x2, t2)` のように書くと安全である。ここで、`s` は出典または証拠集合である。

必要な情報:

| 項目 | 内容 |
|---|---|
| 主体識別子 | 法人番号、施設ID、世帯ID、支援IDなど |
| 旧所在地 | 移転前の住所またはAGID/PID |
| 新所在地 | 移転後の住所またはAGID/PID |
| 有効時刻 | 開始日、終了日、確認日 |
| 関係ラベル | 移転、名称変更、合併、分割、権限移譲 |
| 出典 | 登記、行政記録、配送履歴、本人同意、運営記録 |
| 状態 | active, retired, redirected, disputed, unresolved |

本文に追加する文:

> 移転エッジは、社会的主体の連続性を表すが、物理拠点の同一性を表さない。旧拠点と新拠点は別ノードとして保持される。旧拠点が別主体に再利用される可能性があるため、移転は旧住所の消滅や同一化ではなく、履歴グラフ上の有向関係として扱う。

## 6. 13.5の関係ラベルを明確化する

13.5には、次の表を入れる。

| 主張 | 必要な証拠 | 証拠がない場合 |
|---|---|---|
| `y` は `x` に所在する | 地図、施設記録、営業記録 | 候補として扱う |
| `y` は `x` に居住する | 居住資格、本人同意、鮮度 | 居住証明に使わない |
| `y` は `x` に配送可能 | 配送履歴、配送区域、受取権限 | 配送可能と断定しない |
| `y` は `x` に登記される | 登記・行政記録 | 登記住所として扱わない |
| `y` は `x` を所有する | 地籍、契約、所有権記録 | 所有関係を主張しない |
| `y` は `x` を運営する | 営業許可、運営記録 | 運営主体として扱わない |

追加文:

> 住所写像論では、これらの関係を一つの住所属性にまとめない。関係ラベルを潰すと、配送、本人確認、登記、所有、災害支援の文脈で誤判定が起きる。

## 7. 13.6を条件付き仮説として書き直す

見出しを次に変えるとよい。

> 13.6 社会的連続性仮説（条件付き）

本文案:

> 社会的連続性仮説は、次のように述べる。

> ある住所参照は、地理的対象だけでなく、法人、世帯、施設、運営主体、支援対象のような社会的実体の履歴的連続性にも結びつく場合がある。

> ただし、この仮説は無条件定理ではない。社会的連続性は、関係ラベル、時刻、出典、権限、履歴、反例チェックによって制約される。証拠が不足する場合、AMT解決器は社会的連続性を根拠にPID統合や配送可能性判定を行ってはならない。

この修正で、「住所は社会的実体である」という強すぎる表現を避けられる。

## 8. 13.7の反例表を増やす

13.7には、次の反例表を追加する。

| 反例 | 問題になる短絡 |
|---|---|
| 同じ屋号を別運営会社が使う | 名称一致から社会的同一性を推論する |
| 会社が移転し旧オフィスに別会社が入る | 旧住所から現在主体を推論する |
| 1つのビルに複数法人が入る | 座標から法人を一意に決める |
| 法人本店と配送倉庫が違う | 登記住所と配送先を同一視する |
| 所有者と居住者が違う | 所有関係と居住関係を同一視する |
| 居住者が変わるが住所表記は同じ | 住所文字列から人や世帯を同一視する |
| 避難所に一時滞在している | 支援到達先と通常居住地を同一視する |
| 私書箱を利用している | 受取先と居住地を同一視する |
| 世界遺産・遺跡・公園 | 文化対象の名称と住所対象を単純対応させる |
| 店舗ブランドが継続し運営者が変わる | ブランド連続性と法人連続性を同一視する |

反例の後に、次を追加する。

> したがって、社会的連続性を扱う章では、反例が補足ではなく中核である。反例を明示することで、AMTは社会的連続性を安全に使える範囲と、unresolvedにすべき範囲を分けられる。

## 9. 章末に追加する命題群

章末に次の命題を置くと、理論として締まる。

### 命題13.1 身分層分離原理

住所同一性を判定するとき、地理的同一性、物理的同一性、制度的同一性、配送可能性、居住関係、運営関係、履歴的連続性を同一視してはならない。

### 命題13.2 地理的十分性の失敗

同一の地理的観測に複数の社会的実体が対応する場合、地理的観測だけから社会的実体を完全に決定する住所解決器は存在しない。

証明スケッチ:

> 同じ観測値 `o` に対して、異なる社会的実体 `y1 != y2` が対応するとする。解決器が `o` だけを入力に取るなら、出力は一つである。したがって、少なくとも一方の実体について誤る。ゆえに地理的観測だけでは完全解決できない。

これはLeanの観測衝突命題と同じ構造を持つ。

### 命題13.3 証拠付き移転原理

移転、名称変更、合併、分割、権限移譲は、履歴グラフ上のエッジとして記録する。エッジには、関係ラベル、時刻、出典、状態を付与しなければならない。

### 命題13.4 関係ラベル非崩壊原理

`locatedAt`, `residesAt`, `registeredAt`, `deliversTo`, `owns`, `operatesAt` は互いに異なる関係であり、目的別に必要な証拠が異なる。

### 命題13.5 社会的連続性の棄却可能性

社会的連続性の主張は、新しい証拠、失効、運営主体変更、所有者変更、居住者変更、用途変更によって棄却またはunresolved化され得る。

## 10. 本文に入れる短い例

### 例1 会社移転

会社 `A` が2024年に住所 `x1` から `x2` へ移転したとする。法人主体 `A` は継続していても、`x1` と `x2` は同じ物理実体ではない。したがって、AMTは次を区別する。

| 対象 | 扱い |
|---|---|
| 法人主体 `A` | 継続し得る |
| 旧拠点 `x1` | retired または historical |
| 新拠点 `x2` | active |
| 移転関係 | 履歴グラフのエッジ |

### 例2 同じ建物の複数法人

同じビルの同じ住所表記に、複数の法人が入居している場合、地理的候補は同じでも社会的主体は異なる。したがって、部屋番号、階層、法人名、登記、配送履歴などの追加証拠が必要である。

### 例3 避難所

災害時に避難所 `s` が支援物資の到達先になる場合、`s` は配送可能な支援拠点である。しかし、それは避難者の通常居住住所を意味しない。AMTは `receivesSupportAt` と `residesAt` を分離する。

## 11. 第12章・第14章への接続

第13章は、第12章と第14章をつなぐ章として書くとよい。

| 接続先 | 役割 |
|---|---|
| 第12章 履歴グラフ | 社会的連続性を履歴エッジとして保持する。 |
| 第14章 文脈相対性 | 配送、登記、居住、所有で最適な同一性判定が違うことを示す。 |
| 第18章 品質・評判 | 社会的連続性証拠の信頼度を内部評価に使う。 |
| 第25章 限界 | 社会的連続性を完全自動判定できないことを明記する。 |
| AGID/AOID応用論文 | 所有、委譲、配送可能性、秘匿証明へ接続する。 |

章末に次の橋渡し文を入れると自然である。

> 社会的連続性は、住所解決を豊かにするが、同時に誤判定の危険を増やす。したがって次章では、住所の最適性が用途や観測者に依存することを扱う。配送、登記、行政、不動産、災害支援では、同じ住所表現に対して最適な解決結果が異なり得る。

## 12. 最終編集方針

第13章の修正方針は次で十分である。

1. 「住所は社会的実体である」と言い切らない。
2. 「住所参照は社会的実体と結びつく場合がある」と書く。
3. 地理的同一性、物理的同一性、制度的同一性、配送可能性、居住関係、運営関係を分ける。
4. 移転や継承は履歴グラフのエッジとして扱う。
5. 名称一致を同一性の根拠にしない。
6. 反例を中核に置く。
7. 証拠不足はunresolvedにする。
8. PID mergeや配送可能性判定には短絡させない。

この修正を入れると、第13章は第12章の履歴理論を受け、第14章の文脈相対性へ進むための強い中間章になる。
