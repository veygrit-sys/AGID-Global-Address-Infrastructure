# 住所写像論 日本語版 v1 章横断エビデンスマップ

作成日: 2026-06-06

対象: `docs/address-morphism-theory-ja-v1-master.md` 全26章

目的: 章同士で検証結果を根拠として使うためのルール、依存関係、引用方法を定める。これにより、各章を孤立させず、住所写像論全体を一つの検証済み理論体系として書けるようにする。

## 1. 基本方針

章同士の検証結果は、他章の根拠として使ってよい。ただし、次の条件を満たす必要がある。

1. 根拠にする主張には、章番号、Claim ID、検証方法、検証状態を付ける。
2. Leanで証明済みの命題は、複数章から共通基盤として参照してよい。
3. GIS/実装テストの結果は、現実データまたは実装挙動の証拠として使ってよいが、数学的定理の証明としては使わない。
4. 仮説章の主張を、基礎定理の証明根拠にしてはいけない。
5. 後続の応用章は、前半の形式章を根拠にしてよい。逆に、応用章の成功例を使って前半の定理を証明したことにはしない。

## 2. 依存関係の層

住所写像論の章は、次の5層に分けて扱う。

| 層 | 章 | 役割 | 他章への使い方 |
| --- | --- | --- | --- |
| 導入層 | 第1章、第2章 | 問題意識と仮説 | 後続章の動機として使う。証明根拠としては弱く扱う。 |
| 形式基礎層 | 第3章から第6章 | 実体、表現、形式定義、不可能性定理 | ほぼ全章の根拠として使える。 |
| 解決機構層 | 第7章から第12章 | 写像連鎖、候補生成、クラスタ、未解決、PID、履歴 | 応用章、評価章、限界章の根拠として使える。 |
| 拡張理論層 | 第13章から第18章 | 社会的連続性、文脈相対性、圧縮、自然地理、品質、暗号境界 | ケーススタディ、限界、応用分離の根拠として使える。 |
| 応用・評価層 | 第19章から第26章 | 応用識別子、通信、検証、セキュリティ、比較、事例、限界、結論 | 本文の統合、将来論文、実装方針に使う。基礎定理の証明には使わない。 |

## 3. 依存方向

推奨する依存方向は次の通りである。

```text
第1章 導入
  ↓
第2章 基本仮説
  ↓
第3章 住所可能実体
  ↓
第4章 表面住所表現
  ↓
第5章 形式的準備
  ↓
第6章 住所参照不可能性定理
  ↓
第7章 AMT写像連鎖
  ↓
第8章 候補生成
  ↓
第9章 クラスタ
  ↓
第10章 未解決状態
  ↓
第11章 PID発行
  ↓
第12章 履歴グラフ
  ↓
第13章から第18章 拡張理論
  ↓
第19章から第26章 応用、検証、限界、結論
```

横断参照は許す。ただし、循環した証明依存は避ける。たとえば、第17章の品質スコア実装が動くことを根拠に、第6章の不可能性定理を証明したことにはしない。逆に、第6章の不可能性定理を根拠に、第17章で品質スコアを真理ではなく証拠重みとして扱うことはできる。

## 4. 章別に使える共通根拠

## 4.1 第6章の根拠を使う章

第6章の住所参照不可能性定理は、次の章の共通根拠になる。

| 根拠章 | 使う章 | 使い方 |
| --- | --- | --- |
| 第6章 | 第7章 | 写像連鎖が単発変換では足りない理由。 |
| 第6章 | 第8章 | 候補欠落時に `unresolved` が必要な理由。 |
| 第6章 | 第9章 | クラスタが必要だが万能ではない理由。 |
| 第6章 | 第10章 | `ambiguous`, `unresolved`, `rejected` が安全状態である理由。 |
| 第6章 | 第11章 | PID発行にゲートが必要な理由。 |
| 第6章 | 第14章 | 絶対的最適住所が存在しない場合がある理由。 |
| 第6章 | 第17章 | 品質スコアを真理ではなく証拠重みとして扱う理由。 |
| 第6章 | 第25章 | 完全解決を限界として明記する理由。 |

引用例:

> 第6章で示すように、非単射観測の下では無条件完全解決器は存在しない。したがって本章では、候補が不足する場合を失敗ではなく `unresolved` として扱う。

## 4.2 第10章の根拠を使う章

第10章の未解決状態理論は、候補生成、PID発行、検証、限界の章で共通基盤になる。

| 根拠章 | 使う章 | 使い方 |
| --- | --- | --- |
| 第10章 | 第8章 | 候補生成失敗時の出力を定義する。 |
| 第10章 | 第11章 | PID非発行の安全性を支える。 |
| 第10章 | 第17章 | 低品質タブや再検証対象を `unresolved` と接続する。 |
| 第10章 | 第20章 | 登録失敗や監査失敗を正式状態として扱う。 |
| 第10章 | 第21章 | 検証項目として非発行状態を扱う。 |
| 第10章 | 第25章 | 未解決が理論の限界ではなく安全機構であることを示す。 |

引用例:

> 第10章で定義する非発行状態により、候補が存在しても品質、鮮度、リスクが不足する場合にはPID発行を保留できる。

## 4.3 第11章の根拠を使う章

第11章のPID発行ゲートは、通信、登録、監査、セキュリティ、ケーススタディの章で使える。

| 根拠章 | 使う章 | 使い方 |
| --- | --- | --- |
| 第11章 | 第20章 | 登録モデルで候補表示と登録を分ける。 |
| 第11章 | 第21章 | PID発行の再現性テストを定義する。 |
| 第11章 | 第22章 | 誤発行、重複登録、監査不能性を脅威として扱う。 |
| 第11章 | 第24章 | ケーススタディでPIDを発行する/しない条件を説明する。 |
| 第11章 | 第26章 | AMTの結論として安全な発行をまとめる。 |

引用例:

> 第11章の発行許容述語により、候補が表示可能であっても、PID発行にはより強い条件が必要である。

## 4.4 第12章の根拠を使う章

第12章の履歴グラフは、社会的連続性、住所保存則、災害時住所、結論章の根拠になる。

| 根拠章 | 使う章 | 使い方 |
| --- | --- | --- |
| 第12章 | 第13章 | 社会的連続性を履歴グラフで制約する。 |
| 第12章 | 第14章 | 文脈が変わっても参照クラスを追跡する。 |
| 第12章 | 第19章 | PIDと応用識別子の継承を分ける。 |
| 第12章 | 第20章 | 登録履歴と監査履歴を扱う。 |
| 第12章 | 第24章 | 旧住所から新住所、避難所、仮設住宅の事例に使う。 |
| 第12章 | 第25章 | 住所保存則の限界を書く。 |

引用例:

> 第12章の履歴グラフにより、旧住所と新住所は同一文字列として扱われるのではなく、履歴エッジを通じて追跡される。

## 4.5 第14章の根拠を使う章

第14章の文脈相対性は、品質、評価、ケーススタディ、限界に使える。

| 根拠章 | 使う章 | 使い方 |
| --- | --- | --- |
| 第14章 | 第15章 | 圧縮方式の最適性が用途依存であることを示す。 |
| 第14章 | 第17章 | 品質スコアが文脈別であることを示す。 |
| 第14章 | 第23章 | 商用API比較を用途別にしなければならない理由。 |
| 第14章 | 第24章 | 消防、配送、観光、不動産で異なる出力を説明する。 |
| 第14章 | 第25章 | 全用途で最適な住所解決器がないことを限界として書く。 |

引用例:

> 第14章の文脈相対性により、本章の品質スコアは汎用真理値ではなく、用途別の判断補助として定義される。

## 4.6 第16章と第17章の根拠を使う章

第16章の自然地理・垂直参照と、第17章の品質評価は、実装・GIS検証を強く参照する章である。

| 根拠章 | 使う章 | 使い方 |
| --- | --- | --- |
| 第16章 | 第3章 | 住所可能実体を住宅外へ広げる根拠として使う。ただし第3章の定義の証明には使わない。 |
| 第16章 | 第24章 | 山、湖、川、島、砂漠、湿地、世界遺産のケーススタディに使う。 |
| 第17章 | 第8章 | 候補生成の失敗モードを品質評価へ接続する。 |
| 第17章 | 第21章 | 実装検証項目として品質しきい値を扱う。 |
| 第17章 | 第25章 | 品質スコアは真理ではないという限界を書く。 |

注意: 第16章の実装成功例を使って「世界中のすべての島名を認識できる」とは書かない。使えるのは、登録済みソースとテスト対象において、自然住所表示が成立しているという証拠である。

## 6. 循環参照を避けるルール

禁止する書き方:

1. 第24章のケーススタディがうまく動いたので、第6章の定理が証明された、と書く。
2. 第17章の品質スコアが高いので、対象住所が真である、と書く。
3. 第20章の登録モデルが便利なので、第11章のPID発行条件が正しい、と書く。
4. ZKPで住所属性を証明できるので、AMTの住所意味論が正しい、と書く。

許される書き方:

1. 第6章の不可能性定理を根拠に、第10章で非発行状態を導入する。
2. 第10章の非発行状態を根拠に、第11章でPID発行ゲートを設計する。
3. 第11章の発行ゲートを根拠に、第20章で登録監査モデルを書く。
4. 第16章と第17章の実装検証を根拠に、第24章で自然地理ケーススタディを書く。

## 7. 最終PDFへの反映方法

最終的な論文本体では、章横断エビデンスを本文中に長く書きすぎない。本文では短く引用し、詳細は検証PDFまたは付録に置く。

推奨構成:

1. 本文: 章同士の根拠参照を短く入れる。
2. 付録A: Claim IDとLean定理名の対応表。
3. 付録B: Claim IDとGIS/実装テストの対応表。
4. Companion PDF: 章別検証ノート、章別編集差分、未検証項目、反例。

この方式により、第2章以降は章ごとに分割しても、論文全体としては一つの依存グラフを保てる。

## 8. 結論

章同士で検証を証拠として使う方針は採用すべきである。特に、第6章、第10章、第11章、第12章、第14章は、後続章の根拠として繰り返し使える中核章である。

ただし、根拠の種類を混ぜてはいけない。Lean証明は抽象命題の根拠、GIS検証はデータ品質の根拠、実装テストは実装挙動の根拠、ケーススタディは説明と反例探索の根拠である。この区別を守れば、章横断の引用は論文の説得力を大きく高める。
