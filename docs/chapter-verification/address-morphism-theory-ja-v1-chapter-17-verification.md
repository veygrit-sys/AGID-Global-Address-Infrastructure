# 住所写像論 日本語版 v1 第17章 検証ノート

対象: 第17章「評価関数、品質、評判」

本ノートは、第17章で述べられている「評価関数、品質スコア、配送履歴、評判を、住所解決とPID発行の安全制御に使う」という主張を、Lean形式化、実装テスト、PIDリスク予算、GIS警告予算、反例分析に照らして検証したものである。

結論を先に述べると、第17章は強く採用してよい。ただし、章全体で次の一点を徹底する必要がある。

> スコアは住所の真理そのものではない。スコアは、証拠、文脈、鮮度、出典、履歴、品質、リスクに基づく運用上の判断補助である。

したがって、高い評価スコアは候補表示や自動補助には有用だが、それだけでPIDを発行してよいことにはならない。PID発行には、候補被覆、しきい値、候補間マージン、品質、鮮度、リスク、履歴整合性、監査可能性を含むゲートが必要である。

第17章の安全な中心文は次である。

> AMTの評価関数は、候補やクラスタの相対的な証拠強度を測るための関数であり、住所の真理を直接返す関数ではない。品質スコアと評判スコアは、非表示、注意表示、再検証、追加証拠要求、PID発行停止、データ改善優先順位付けのための内部制御として使う。

## 1. 検証結果の要約

| 観点 | 判定 | 理由 |
|---|---:|---|

## 3. Leanで確認できる部分

### 3.1 しきい値とマージン

Lean定義:

```text
ScoreSelectable bestEnergy secondEnergy threshold margin
```

意味:

> 最良候補のエネルギーがしきい値以下であり、かつ第二候補との差が十分にあるときだけ、スコア上の選択を許す。

Lean命題:

```text
score_selection_requires_threshold
tied_evidence_prevents_score_selection
score_selection_conditions_are_recoverable
```

意味:

1. 最良候補がしきい値を超えている場合、選択できない。
2. 第二候補との距離が近すぎる場合、選択できない。
3. 選択されたなら、しきい値条件とマージン条件を回収できる。

これは第17章の「評価スコアが高く見えるだけでは不十分」という主張を支える。

### 3.2 PID発行ゲート

Lean定義:

```text
IssueAdmissible
```

この定義は、PID発行前に少なくとも次の条件を要求する。

1. 選択実体が候補集合に含まれる。
2. スコア選択がしきい値とマージンを満たす。
3. 品質スコアが品質しきい値以上である。
4. 鮮度が許容範囲内である。
5. リスクが許容範囲内である。

Lean命題:

```text
issue_if_admissible_requires_conditions
issue_if_admissible_emits_candidate
issue_if_not_admissible_abstains
```

意味:

> 発行されたなら条件が揃っている。発行された候補は候補集合の中にある。条件が揃わないなら、解決器は発行せず保留する。

これは、評価関数とPID発行を分離する根拠である。

### 3.3 品質、鮮度、リスクによる発行停止

Lean命題:

```text
low_quality_prevents_issue
stale_freshness_prevents_issue
high_risk_prevents_issue
high_energy_prevents_issue
low_margin_prevents_issue
```

意味:

> 品質が低い、鮮度が古い、リスクが高い、スコアがしきい値を超える、候補間マージンが不足する場合、PID発行は許されない。

これらは、第17.8節の品質しきい値を強く支える。

### 3.4 評判の単調性

Lean命題:

```text
positive_evidence_monotone_reputation
```

意味:

> 他の条件が固定され、正の証拠だけが増えるなら、単純な評判成分は低下しない。

ただし、これは評判モデル全体の正しさを証明するものではない。実運用では、失敗履歴、返品率、配送事業者の偏り、不正報告、地域データ量の偏り、鮮度を含める必要がある。

## 5. 節ごとの判定

### 5.1 第17.1節の判定

「評価関数は真理ではない」は、この章で最も重要な主張であり、強く採用すべきである。Leanの発行ゲートは、条件を満たしたことは示せるが、世界の真理そのものは示さない。

したがって、本文では「高スコアなら正しい」ではなく、「高スコアでも発行ゲートを通過しなければPIDを出さない」と書くべきである。

### 5.2 第17.2節の判定

証拠重みモデルは採用できる。ただし、本文のシグモイド式は「一例」として扱うべきである。AMTは特定の統計モデルを強制する理論ではなく、支持証拠、リスク、矛盾、鮮度、文脈適合性を分ける枠組みである。

安全な書き方:

> 評価関数は、証拠の支持成分、矛盾成分、鮮度成分、出典成分、文脈成分、リスク成分を分離して扱う。具体的な統計モデルは実装や用途により変わる。

### 5.3 第17.3節の判定

公式性と鮮度を両方見る方針は正しい。公式データでも古ければ危険であり、非公式データでも新しい現地変化を反映する場合がある。

ただし、非公式データを公式データより単純に上位に置くべきではない。本文では、公式性、鮮度、coverage、粒度、ライセンス、信頼性を別成分として扱うとよい。

### 5.4 第17.4節の判定

地域別・言語別品質は実装で支持される。ユーザーが言った「都市や田舎や島でも判定」「ユーザー側にスコアは表示しない」という設計方針と一致する。

修正すべき点は、記法 `Q(c,t,r,l,tau)` の `t` と `tau` の混同である。時刻は `time`、対象種別は `kind` などに分けると読みやすい。

### 5.5 第17.5節の判定

都市、田舎、島、砂漠、山地、極地の失敗モードを分ける主張は採用できる。第16章で自然・文化・垂直参照を扱ったため、第17章ではそれらを品質判定へ入れると自然につながる。

追加すべき分類:

1. 水域。
2. 湿地。
3. 氷河・氷原。
4. 森林・草原・荒野。
5. 文化地物。
6. 垂直建物。

### 5.6 第17.6節の判定

配送履歴と評判は重要だが、慎重に書く必要がある。配送履歴は実到達可能性の強い証拠になり得るが、住所同一性の完全証明ではない。

反例:

1. 配送員が電話で確認したため成功した。
2. 建物名が曖昧だが近隣知識で成功した。
3. 都市部は配送履歴が豊富で、疎地域はデータ不足になる。
4. 不正な返品や誤報告で評判が歪む。
5. 一時的な工事や災害で到達性が変わる。

したがって、評判は品質の一成分として扱い、公式性、候補被覆、履歴整合性、鮮度と分離するべきである。

### 5.7 第17.7節の判定

unresolved履歴を品質改善サイクルに接続する方針は採用できる。unresolvedは失敗ではなく、安全な非発行状態であり、同時にデータ不足の観測でもある。

本文では、unresolvedを次の改善信号として扱うとよい。

| unresolvedの集中 | 改善方向 |
|---|---|
| 山地・砂漠 | 自然地理データ、アクセス点データの追加 |
| 都市 | 垂直参照、入口、テナント、建物内部データの追加 |
| 島 | 多言語名、行政所属、港、海図データの追加 |
| 極地 | 基地、研究機関データ、氷床・地形データの追加 |
| 郵便番号弱地域 | 公式住所ソース、地図ソース、地域ルールの追加 |

### 5.8 第17.8節の判定

品質しきい値は強く採用すべきである。Leanで、品質、鮮度、リスクの不足が発行を止めることを確認している。

ただし、しきい値は一つの固定値ではなく、文脈、対象種別、地域、用途に依存させるべきである。

安全な記法:

```text
QualityOK(k, context, region, kind)
```

### 5.9 第17.9節の判定

品質スコアをユーザーに直接表示しない方針は採用できる。生点数は、地域差や言語差への不当な印象、過剰な確信、逆SEO的な操作、攻撃者によるしきい値探索を招き得る。

ユーザー向けには、次の粒度がよい。

1. 表示する。
2. 注意して表示する。
3. 再検証を促す。
4. 通常表示から隠す。
5. 追加情報を求める。

## 6. 反例と弱点

### 6.1 高スコア誤信反例

公式住所ソースと郵便番号が一致していても、建物が取り壊されている場合がある。この場合、高スコアでも真の到達可能性は失われている。

### 6.2 新鮮だが非公式反例

OSMや配送事業者データが最新の工事や新築を反映していても、法的住所としては未登録の場合がある。鮮度だけで公式性を置き換えてはいけない。

### 6.3 配送成功反例

配送が成功していても、住所表記が正しいとは限らない。電話確認、配達員の経験、近隣住民への聞き取り、過去の配送記憶で成功した可能性がある。

### 6.4 データ量偏り反例

都市部は配送履歴や地図更新が多いため評判が高くなりやすい。田舎、島、山地、砂漠、極地はデータが少ないため、不当に低品質扱いされる危険がある。

### 6.5 スコア公開攻撃反例

品質スコアを細かく公開すると、攻撃者が入力を調整し、PID発行しきい値を探索できる可能性がある。内部スコアは公開せず、必要なら粗い説明だけを返すべきである。

## 7. 論文へ追加すべき命題

### 命題17.1 評価非真理命題

> 評価関数の出力は、候補またはクラスタに対する証拠上の選好であり、実世界における住所同一性の真理値ではない。

### 命題17.2 しきい値・マージン必要命題

> 候補選択には、最良候補のしきい値条件と、第二候補に対する十分なマージン条件が必要である。

Lean対応:

```text
score_selection_requires_threshold
tied_evidence_prevents_score_selection
```

### 命題17.3 品質・鮮度・リスク発行停止命題

> 品質が低い、鮮度が古い、またはリスクが高い場合、PID発行は停止されなければならない。

Lean対応:

```text
low_quality_prevents_issue
stale_freshness_prevents_issue
high_risk_prevents_issue
```

### 命題17.4 評判分離命題

> 配送履歴に基づく評判は、候補評価の一成分であり、住所同一性、公式性、法的住所、配送可能性の完全証明ではない。

### 命題17.5 内部品質制御命題

> 品質スコアは、ユーザーへ直接表示する真理値ではなく、表示、注意、再検証、追加証拠要求、PID発行停止の内部制御として扱うべきである。

## 8. 最終評価

第17章は、AMTを実運用可能な理論にするための重要章である。第8章から第11章で候補生成、クラスタ、unresolved、PID発行を扱い、第16章で自然・文化・垂直参照を広げた後、第17章は「どの候補をどの程度信じ、どの時点で発行を止めるか」を定義する。

採用すべき中心方針は次である。

1. 評価関数は真理ではない。
2. 評価は証拠重み、鮮度、公式性、履歴、リスク、文脈の合成である。
3. PID発行には評価スコアだけでなく、しきい値、マージン、品質、鮮度、リスク、監査が必要である。
4. 配送履歴は強い証拠だが、真理ではなく評判成分である。
5. unresolved履歴は品質改善の信号である。
6. 品質スコアはユーザーへ直接表示せず、内部安全制御に使う。

この修正を入れると、第17章はスコアリング機能の説明ではなく、AMTの安全な運用判断モデルとして成立する。
