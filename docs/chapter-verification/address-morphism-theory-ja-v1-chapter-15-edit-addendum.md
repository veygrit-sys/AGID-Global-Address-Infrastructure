# 住所写像論 日本語版 v1 第15章 追加・編集差分案

対象: 第15章「住所圧縮と住所エントロピー」

本差分案は、第15章をより数学的に正確で、検証結果と実装に接続しやすい形へ修正するための本文案である。中心方針は、住所圧縮を魅力的な比喩で終わらせず、非単射圧縮、候補集合エントロピー、有限ビット容量、PID発行ゲートへ分解することである。

## 1. 章冒頭に追加する要約

第15章の冒頭に、次を追加するとよい。

> 本章では、住所を情報圧縮として捉える。ただし、ここでいう圧縮は、住所の唯一の本質を意味しない。住所は、地理的、制度的、社会的、自然地理的な複雑さを、人間、制度、機械、配送網が扱える表現へ写す参照表現である。郵便番号、従来住所、座標、Plus Codes、PIDなどは、それぞれ異なる圧縮方式である。

続けて、次を入れる。

> 圧縮は有用であるが、一般には損失を伴う。圧縮値が非単射であれば、その値だけから元の実体を完全に復元することはできない。したがって、住所解決は、圧縮表現から候補集合を展開し、文脈、証拠、履歴、品質、鮮度、リスク予算によって残差不確実性を減らす過程である。

## 2. 15.1の記法修正

現在の本文では、圧縮写像を次のように置いている。

```text
c : X -> C
```

ただし、第14章で文脈集合を `C` と読めるため、第15章ではコード空間を別記号にした方がよい。

置換案:

```text
comp : X -> Code
```

ここで `X` は住所可能実体集合、`Code` は住所表現、郵便番号、座標コード、PID prefixなどの表現空間である。

さらに、復元は単一値ではなく候補集合を返すものとして定義する。

```text
expand : Code -> P(X)
expand(a) = { x in X | comp(x) is compatible with a }
```

本文案:

> AMTでは、住所表現を単なる文字列ではなく、実体空間から表現空間への圧縮写像として扱う。
>
> `comp : X -> Code`
>
> ただし、現実の住所解決では、圧縮値からただ一つの実体を返すとは限らない。むしろ、解決器は圧縮値から候補集合を展開する。
>
> `expand : Code -> P(X)`
>
> 候補集合が一つに絞られ、かつ品質、鮮度、履歴、リスク、文脈条件を満たすときにのみ、AMTは安全に解決済み参照を返す。

## 3. 15.2を有限容量の命題として補強する

現在の命題3は正しい。章内番号として、次のように整理するとよい。

### 命題15.1 有限コード容量衝突命題

> `X` と `Code` を有限集合とする。`|X| > |Code|` なら、任意の写像 `comp : X -> Code` は単射ではない。すなわち、ある `x1 != x2` が存在して、`comp(x1) = comp(x2)` となる。

証明案:

> もし `comp` が単射なら、`X` の異なる元は `Code` の異なる元へ写る。したがって `|X| <= |Code|` でなければならない。しかし仮定は `|X| > |Code|` である。矛盾。したがって `comp` は単射ではなく、衝突を持つ。

続けて、Lean対応を書く。

> Lean形式化では、これをさらに復号不可能性として扱う。二つの異なる実体が同じ圧縮値へ写るなら、その圧縮値だけからすべての実体を完全復元する復号器は存在しない。この主張は `noninjective_compression_no_perfect_decoder` として検証されている。

## 4. 非単射圧縮不完全復号命題を追加する

15.2の後に、次の命題を追加すると章が強くなる。

### 命題15.2 非単射圧縮不完全復号命題

> 写像 `comp : X -> Code` が非単射であり、`comp(x1) = comp(x2)` かつ `x1 != x2` を満たす実体 `x1, x2` が存在するとする。このとき、すべての `x in X` について `dec(comp(x)) = x` を満たす復号器 `dec : Code -> X` は存在しない。

証明案:

> そのような `dec` が存在すると仮定する。すると `dec(comp(x1)) = x1` かつ `dec(comp(x2)) = x2` である。一方で `comp(x1) = comp(x2)` だから、左辺は同じ値である。したがって `x1 = x2` となる。しかし仮定では `x1 != x2` である。矛盾。

本文への意味:

> この命題により、郵便番号、短縮コード、粗い座標、同名地名、短い自然地名、短いPID prefixなどは、対象集合が十分大きい場合に完全な住所解決器にはなれないことが分かる。ただし、これはそれらの表現が無用であるという意味ではない。それらは候補集合を減らす有用な圧縮である。

## 5. 15.3 候補集合エントロピーの修正

現在の式:

```text
H(C_s) = - sum_{x in C_s} p(x) log2 p(x)
```

これは直感的にはよいが、より正確には「候補集合上の確率分布」のエントロピーである。また、第14章の文脈相対性と接続するため、文脈と履歴を条件に含めた方がよい。

置換案:

```text
H_addr(s,c,l)
  = H(E | U=s, Context=c, Lineage=l)
  = - sum_{x in C_s} p(x | s,c,l) log2 p(x | s,c,l)
```

ここで:

| 記号 | 意味 |
|---|---|
| `E` | 意図された住所可能実体 |
| `U` | 入力住所表現 |
| `s` | 実際に観測された入力 |
| `c` | 文脈。配送、行政、消防、自然地理検索など |
| `l` | 履歴、lineage、過去の配送履歴、公式変更記録 |
| `C_s` | 入力 `s` から生成された候補集合 |

本文案:

> 住所エントロピーは、住所文字列そのものの長さではない。住所エントロピーは、ある入力、文脈、履歴証拠の下で、どの実体が意図対象であるかについて残る不確実性である。

補足:

> 候補集合が一つで、その候補の確率が1なら、エントロピーは0である。候補が複数あり、確率が近いほど、エントロピーは高くなる。ただし、候補確率が偏っている場合、候補数だけでは不確実性を正確には表せない。

## 6. Shannon entropyとsurprisalを分ける

本文または脚注で、次を明記するとよい。

```text
h(x) = -log2 p(x)
H(E) = - sum_x p(x) log2 p(x)
```

説明:

> `h(x)` は一つの候補が観測されたときのsurprisalであり、`H(E)` は分布全体のShannon entropyである。住所写像論で候補集合不確実性を測るときは、通常 `H(E | U=s, c, l)` を用いる。

この区別を入れると、住所エントロピー論文で指摘された「`H_addr(e) = -log2 P(e)` はShannon entropyではなくsurprisalである」という問題を避けられる。

## 7. 15.4 必要識別ビット数の修正

現在の本文:

> 候補が `N` 個あり、等確率だとする。この中から一つを識別するには、少なくとも `ceil(log2 N)` bitの情報が必要である。

これはおおむね正しいが、二つの意味を分けるとより正確になる。

追加案:

> 等確率の候補 `N` 個から一つを識別する平均情報量は `log2 N` bitである。一方、固定長コードで `N` 個の対象を一意に表すためには、少なくとも `ceil(log2 N)` bitの自由容量が必要である。

さらに、実運用の余裕を書く。

> 実際のPIDやAGIDのような識別子では、自由容量の全てを対象識別に使えるとは限らない。prefix、version、reserved value、check digit、将来拡張、衝突リスク予算、監査用saltなどが容量を消費する。したがって `N <= 2^b` は必要条件であり、実装ではさらに安全余裕が必要である。

Lean対応:

> Leanでは、`BitCapacity(bits) = 2^bits` と `CapacityCovers(entityCount,bits)` により、有限コード容量の必要条件が形式化されている。

## 8. 15.5 圧縮方式比較表の補強

現在の表に、次の列を加えると論文として強くなる。

| 圧縮方式 | 圧縮対象 | 強い点 | 弱い点 | 典型的な残差不確実性 |
|---|---|---|---|---|
| 郵便番号 | 配送区域、配送経路 | 配送処理に強い | 個別部屋、入口、自然地理に弱い | 同じ区域内の多数の建物 |
| 従来住所 | 行政、社会、建物表現 | 人間可読、制度意味が豊か | 表記揺れ、多言語、旧住所 | 同名地名、建物内区画 |
| 座標 | 幾何位置 | 位置に強い | 垂直、社会的同一性、履歴に弱い | 同じ地点の階層、施設、入口 |
| Plus Codes等 | 地表セル | 広域で体系的 | 行政意味、配送可否を含まない | セル内の複数実体 |
| 施設名 | 人間の記憶、通称 | 探索しやすい | 同名衝突、名称変更 | 施設内の部屋、入口、別名 |
| PID | 解決済み参照 | 履歴と監査に強い | 発行ゲートが必要 | 発行前候補、merge/split |

AGID/AOIDをこの表に入れる場合は、本文では次の注意を付ける。

> AGID/AOIDはAMTの応用識別子であり、本稿では詳細設計を扱わない。ここでは、住所圧縮方式を比較するための例としてのみ言及する。

## 9. 15.6 都市化と住所情報量の修正

現在の方向性はよい。ただし、節タイトルを次のようにしてもよい。

```text
15.6 住所エントロピー仮説
```

または:

```text
15.6 密度、粒度、制度設計と住所情報量
```

本文案:

> 「都市化とともに住所情報量は増加する」という仮説は、直感的には有力である。都市では、建物密度、垂直階層、部屋、入口、テナント、ロッカー、地下空間、配送動線が増えやすく、単一実体を識別するために必要な情報量が増える傾向がある。
>
> しかし、この主張は無条件定理ではない。規則的なグリッド住所を持つ都市では、短い表現で多くの区画を識別できる場合がある。逆に、田舎、島、山地、砂漠、極地、湿地、湖沼、森林では、地名が広範囲を指す、同名地物が多い、公式住所が不足する、地図データが粗い、配送可能性が低い、という理由で高い残差不確実性が残る場合がある。
>
> したがって、本稿では都市化を原因とする無条件定理ではなく、識別対象数、密度、粒度、住所制度、データ品質、文脈要求によって住所情報量が変化するという経験仮説として扱う。

検証計画:

| 測定対象 | 指標 |
|---|---|
| 都市 | 建物数、部屋数、入口数、候補集合サイズ、住所長 |
| 田舎 | 同名地名、番地欠落率、郵便番号粒度、候補集合サイズ |
| 島 | 島名重複、行政所属、港/集落/自然地物の分離 |
| 山地 | 山名、登山口、山小屋、尾根、谷、標高差 |
| 砂漠 | 広域地名、オアシス、道路、キャンプ、座標依存度 |
| 水域 | 湖、川、滝、港、岸、島、保護区、深度情報 |
| 極地 | 研究基地、氷原、棚氷、公式地名、時変地形 |

## 10. 15.7 圧縮とプライバシーの修正

15.7は重要だが、ZKP論文とは分離して書く。

追加案:

> 住所圧縮は、最小開示の問題と関係する。配送文脈では、配送に必要な到達情報が必要である。一方、ECサイト、買い物Agent、年齢確認、地域資格、災害支援資格では、詳細住所ではなく「配送可能地域内である」「指定国に居住している」「同一住所の居住者である」といった属性だけで十分な場合がある。
>
> ただし、本章は暗号的秘匿証明を証明する章ではない。本章が与えるのは、住所からどの情報を残し、どの情報を隠すべきかを考える情報理論的基礎である。零知識証明による選択的開示は、別論文「住所写像論 II: 零知識住所述語」で扱う。

## 11. PID発行ゲートを章末に追加する

第15章の結論部に、次を追加するとAMT本体との接続が強くなる。

### 命題15.3 エントロピー単独ではPID発行条件にならない

> 候補集合エントロピーが低いことは、PID発行の必要条件の一部になり得る。しかし、それだけでは十分ではない。PID発行には、候補被覆、候補分離、source品質、鮮度、履歴整合、衝突リスク、監査証跡、文脈適合性が必要である。

本文案:

```text
emit PID only if:
  residual entropy is below threshold
  candidate coverage holds
  top candidates are sufficiently separated
  source quality passes
  freshness passes
  lineage/history does not conflict
  collision-risk budget passes
  audit trail is reproducible
```

この箇条書きは、第7章から第10章の候補生成、クラスタ、unresolved、履歴更新、PID発行と第15章を接続する。

## 12. 章末のまとめ案

第15章の最後を、次のように締めるとよい。

> 本章では、住所を圧縮表現として扱い、住所解決を残差不確実性の制御過程として定式化した。非単射圧縮は完全復号できず、有限コード空間には容量制約があり、候補が複数残る場合には不確実性が残る。したがって、住所写像論におけるPID発行は、短い住所文字列や単一コードに基づく即時確定ではなく、候補集合、証拠、履歴、品質、鮮度、リスク予算、監査を通じた安全な圧縮解除として理解される。
>
> 次章では、この考え方を住宅住所だけでなく、山、川、湖、砂漠、島、湿地、氷原、遺跡、世界遺産などの自然地理および文化地理へ拡張する。

## 13. 本文へ反映する優先順

1. `c : X -> C` を `comp : X -> Code` に変える。
2. `expand : Code -> P(X)` を追加する。
3. 非単射圧縮不完全復号命題を追加する。
4. Shannon entropyとsurprisalを分ける。
5. `log2 N` と `ceil(log2 N)` の意味を分ける。
6. 都市化主張を経験仮説へ弱める。
7. PID発行はentropy-onlyではないと明記する。
8. ZKP関連は別論文へ分離する。

この編集を入れると、第15章は第1章、第2章で提示した住所圧縮仮説を、Lean検証済みの形式命題と実装上のPID/候補制御へ接続する章になる。
