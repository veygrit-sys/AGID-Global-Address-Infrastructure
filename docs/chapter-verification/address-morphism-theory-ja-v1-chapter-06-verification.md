# 住所写像論 日本語版 v1 第6章 検証ノート

作成日: 2026-06-06

対象: `docs/address-morphism-theory-ja-v1-master.md` 第6章「住所参照不可能性定理」

目的: 第6章で述べられる「無条件完全住所解決器は存在しない」という主張を、Lean形式化、GIS検証、実装テスト、既存評価メモに照らして検証し、論文本文で採用してよい表現と、弱めるべき表現を整理する。

## 1. 第6章の位置づけ

第6章は、住所写像論の理論的中心である。

この章の主張は、「住所解決は不可能である」ではない。正確には、次の主張である。

> 非単射な観測、候補欠落、射影損失、正規化衝突、文脈依存性のいずれかがあるとき、観測だけを入力し、常に一つの正しい実体を返す無条件完全解決器は存在しない。

したがって、第6章はAMTを悲観的にする章ではない。むしろ、`ambiguous`, `unresolved`, `rejected` のような保留状態、候補生成の再現率、クラスタリング、履歴、PID発行ゲートを理論的に正当化する章である。

この章で守るべき最重要表現は、次の三つである。

| 避ける表現 | 採用する表現 |
| --- | --- |
| 住所解決は不可能である | 条件なしの完全単一解決器は存在しない |
| 真の住所は存在しない | 真の対象があっても有限・非単射観測だけでは常に復元できない |
| 座標や正規化は役に立たない | 座標や正規化は有用だが、それだけでは同一性を保証しない |

## 5. 主張別検証

## 5.1 CH06-C01 非単射観測補題

第6章の最も強い核は、次の補題である。

```
Let O : X -> Y be an observation map.
Let R : Y -> X be a total resolver.
Perfect(R, O) means: for every x in X, R(O(x)) = x.

If there exist x1 != x2 such that O(x1) = O(x2),
then no such R can be perfect.
```

Leanでは `no_condition_free_perfect_resolver` として検証済みである。証明の構造は単純で強い。もし `O(x1)=O(x2)` なら、解決器 `R` は同じ入力に同じ出力しか返せない。しかし完全性は同時に `R(O(x1))=x1` と `R(O(x2))=x2` を要求する。これは `x1 != x2` と矛盾する。

この補題は、住所写像論の不可能性主張として十分に採用できる。ただし、前提を明示しなければならない。

| 必須前提 | 理由 |
| --- | --- |
| 解決器は観測値だけを入力する | 追加証拠や対話を使う解決器まで否定しないため。 |
| 解決器は常に一つの実体を返す | `ambiguous` や `unresolved` を許す安全解決器は別扱い。 |
| 完全性は全ての実体に対する正解を要求する | 統計的に高精度な解決器とは別の性質である。 |

## 5.2 CH06-C02 候補欠落補題

候補生成写像が真の対象を含まない場合、後段の評価関数やクラスタリングでは真の対象を選べない。

Leanの `missing_entity_refutes_candidate_completeness` は、この性質を候補完全性の破れとして形式化している。また、`missing_candidate_prevents_issue` は、候補集合に存在しない対象をPIDとして発行してはいけないことを支える。

本文では、候補生成を「精度優先」だけで書くと危険である。第6章では次の原則を明記するとよい。

> 候補生成段階では、後段の評価で落とすことができるため、再現率を重視する。ただし候補を広げすぎると計算量、曖昧性、攻撃面が増えるため、出典、地理範囲、文脈、品質で制御する。

## 5.3 CH06-C03 射影損失補題

座標、郵便番号、行政コード、建物代表点などへの射影は有用である。しかし、射影は情報を落とす。

例:

| 射影 | 失われ得る情報 |
| --- | --- |
| 緯度経度点 | 階数、部屋、地下、入口、権利区分 |
| 郵便番号 | 同一郵便区内の建物差 |
| 行政区画 | 同一区画内の地物差 |
| 建物代表点 | 複数入口、別用途、テナント差 |

Leanの `projection_collision_prevents_vertical_resolution` は、射影後に異なる実体が同じ値になれば、射影値だけでは区別できないことを支える。

本文では「座標は住所ではない」と書くより、「座標は重要な観測だが、住所同一性を単独で保証しない」と書く方が安全である。

## 5.4 CH06-C04 正規化衝突補題

正規化は住所処理に不可欠である。表記揺れ、全角半角、略称、言語差、旧字体、新字体、句読点、ハイフン差を吸収できる。

しかし、正規化が強すぎると、区別すべき情報まで消える。

例:

| 正規化 | 危険 |
| --- | --- |
| 町名や地物名の略称展開 | 別の正式名に衝突する。 |
| 階数や棟番号の省略 | 同一建物内の対象が混ざる。 |
| 旧住所を新住所に単純置換 | 分割・統合の履歴を失う。 |
| 多言語名の単純同一視 | 地名、施設名、自然地理名が混ざる。 |

Leanの `normalization_collision_prevents_perfect_resolution` は、正規化後の値だけでは完全復元できない場合を形式化している。

このため、本文では次を追加するとよい。

> 正規化結果は証拠の一つであり、原表記の完全な置換ではない。安全なAMT実装では、原表記、正規化結果、正規化規則、出典、時刻を監査可能に保持する。

## 5.5 CH06-C05 文脈衝突補題

同じ表面表現でも、用途によって最適な参照対象が変わる。

例:

| 文脈 | 最適対象 |
| --- | --- |
| 配送 | 入口、ロッカー、配送可能な到達点 |
| 行政 | 住居表示、自治体、登記上の区画 |
| 消防・救急 | 到達経路、階数、入口、危険区域 |
| 不動産 | 権利区画、筆界、専有部 |
| 観光 | 地物名、施設名、代表地点 |

Leanの `conflicting_context_optima_prevent_absolute_address` は、文脈を入力しない絶対的な解決器が、互いに異なる文脈最適解を同時に満たせないことを支える。

したがって、第6章は第14章「住所相対性原理」の土台になる。

## 5.6 CH06-C06 保留状態の必要性

第6章の実装上の結論は、解決器が必ず `resolved` を返してはいけないという点である。

Leanの `ResolutionOutcome` は、次の四状態を形式化している。

| 状態 | 意味 |
| --- | --- |
| `resolved` | 十分な条件を満たし、特定実体を返す。 |
| `ambiguous` | 複数候補が近すぎる、または同一性が未確定である。 |
| `unresolved` | 候補や証拠が不足している。 |
| `rejected` | 入力、出典、品質、権限、リスクにより棄却する。 |

実装テストでも、近接候補がある場合は `ambiguous`、証拠不足なら `unresolved`、監査条件を満たさないPIDは発行しないという挙動が確認されている。

この結論は、AMTの安全性に直結する。

## 5.7 CH06-C07 観測直結PIDの危険

第6章はPID設計にも直接効く。観測値だけをハッシュしてPIDにすると、同じ観測を持つ異なる実体が同じPIDへ衝突する。

Leanの `observation_based_pid_collides_on_same_observation` は、この危険を形式化している。

したがって、PIDは次のようなゲートを通した後にのみ発行するべきである。

| ゲート | 目的 |
| --- | --- |
| 候補所属 | 発行対象が候補集合にあることを確認する。 |
| 評価閾値 | 証拠が十分強いことを確認する。 |
| マージン | 近接候補との混同を避ける。 |
| 品質閾値 | 国、言語、地域、自然地理のデータ品質を確認する。 |
| 鮮度 | 古い住所・失効データを避ける。 |
| 衝突リスク | 有限ビットPIDのリスクを予算内に抑える。 |

これは、`IssueAdmissible` と実装のPID監査テストで支持されている。

## 7. 弱めるべき表現

| 原稿で避けるべき表現 | 理由 | 修正文 |
| --- | --- | --- |
| あらゆる住所解決器は完全に失敗する | 強すぎる。実用解決器は高精度になり得る。 | 無条件完全単一解決器は存在しない。 |
| 住所の真理は存在しない | 哲学的に強すぎ、証明対象ではない。 | 真の対象があっても観測から常に復元できるとは限らない。 |
| GPS座標では住所を表せない | 座標は多くの場合有用である。 | 座標だけでは階層、入口、履歴、社会的同一性を十分に表せない場合がある。 |
| 正規化すれば曖昧性は消える | 正規化衝突がある。 | 正規化は曖昧性を減らすが、新しい衝突も作り得る。 |
| PIDは住所文字列のハッシュでよい | 観測衝突でPID衝突が起きる。 | PIDは候補、品質、鮮度、リスク条件を通過した参照対象に発行する。 |
| 類似性で商集合を作る | 類似性が同値関係とは限らない。 | 同値関係なら商集合、そうでなければクラスタ分割として扱う。 |

## 8. 反例として有効な例

第6章では、抽象定理だけでなく次の反例を短く入れると読みやすくなる。

| 反例 | 何を示すか |
| --- | --- |
| 同名マンションが同一市区町村に複数ある | 表面表現の非単射性。 |
| 同じ郵便番号に多数の建物が含まれる | 郵便番号射影の情報損失。 |
| 同一緯度経度に1階店舗、2階事務所、地下駐車場がある | 垂直参照の損失。 |
| 旧住所が行政変更で複数の新住所へ分割される | 履歴なし正規化の危険。 |
| 川、橋、道路、山、建物、公園が同じ地名を共有する | 地物種別と文脈の必要性。 |
| 旅行者向けの地名と配送用住所が違う | 文脈依存の最適性。 |

## 9. 本章の限界

第6章で証明できるのは、厳密には「一定の前提の下での不可能性」である。次の点は、本文で限界として明記する。

| 限界 | 説明 |
| --- | --- |
| 高精度な実用解決器の存在は否定しない | 追加データ、文脈、対話、配送履歴により精度は上がる。 |
| 真の実体の存在は否定しない | 証明しているのは、観測だけからの完全復元不能性である。 |
| ノイズ付き入力の統計限界は別定理で扱う | 第6章のLean中核は主に非単射性に基づく。 |
| GISデータの真実性そのものは証明しない | GIS検証は証明書と整合性の検証であり、現地調査の代替ではない。 |
| ZK証明は住所意味論を作らない | ZKは秘匿証明層であり、AMTが意味論的対象を定義する。 |

## 10. 総合評価

第6章の中核主張は、Lean形式化と実装検証により強く支持されている。特に、非単射観測補題、候補欠落補題、射影損失、正規化衝突、文脈衝突、保留状態、PID発行ゲートは、AMT本体の安全設計に直結している。

ただし、表現は慎重にする必要がある。第6章は「住所の真理は存在しない」と言う章ではない。第6章は、住所解決において「条件なしの完全性」を捨て、代わりに候補、文脈、履歴、品質、監査、保留状態を導入する必要性を示す章である。

推奨判定:

| 項目 | 評価 |
| --- | --- |
| 数理的中核 | 非常に強い。Leanで検証済み。 |
| 論文での重要性 | 最重要章の一つ。 |
| 表現上のリスク | 「不可能」を一般化しすぎると危険。 |
| 修正後の採用可否 | 強く採用可能。 |

第6章は、住所写像論の基礎定理として前面に出してよい。ただし、定理名は「住所参照不可能性定理」よりも、本文中では「非単射観測下における無条件完全住所解決器の非存在」と併記すると、国際論文としても誤読されにくい。
