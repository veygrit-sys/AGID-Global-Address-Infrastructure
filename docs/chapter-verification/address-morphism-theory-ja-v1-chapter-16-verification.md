# 住所写像論 日本語版 v1 第16章 検証ノート

対象: 第16章「自然地理・文化地理・垂直参照」

本ノートは、第16章で述べられている「住所は郵便住所や建物住所だけでなく、川、湖、滝、島、山、砂漠、湿地、氷原、遺跡、世界遺産、道路、橋、公園などの自然・文化・地図地物にも拡張できる」という主張を、Lean形式化、実装テスト、GIS警告予算、反例分析に照らして検証したものである。

結論を先に述べると、第16章は強く採用してよい。ただし、次の三つを本文で必ず分ける必要がある。

1. 参照対象としての住所。
2. 到達点またはアクセス点としての住所。
3. 郵便・配送可能な住所。

自然地理や文化地理は住所的参照対象になり得る。しかし、湖そのもの、山そのもの、世界遺産の保護範囲そのものが、常に配送可能な宛先であるとは限らない。配送や案内に使うには、入口、駐車場、港、登山口、管理事務所、ロッカー、建物内区画などの到達点を別に扱う必要がある。

また、「世界中の全ての島名、川名、湖名、遺跡名を認識できる」とは現時点では書けない。安全には、次のように書くべきである。

> AMTは、出典、ライセンス、鮮度、地物型、幾何粒度、アクセス点、品質、未解決状態を明示する限り、自然地理・文化地理・垂直参照を住所的参照対象として扱える。

## 1. 検証結果の要約

| 観点 | 判定 | 理由 |
|---|---:|---|
| 自然・文化地物を住所的参照対象にする | 採用 | 実装テストで川、湖、滝、島、砂漠、湿地、氷原、洞窟、谷、遺跡、世界遺産系の表示が通る。 |
| 郵便住所と非郵便参照住所を分ける | 強く採用 | 通常のstreet addressがある場合、自然文脈で置換しないテストが通る。 |
| 点、線、面、体積、ネットワーク、文化境界を分ける | 採用 | 地図地物テストが道路、橋、川、湖、公園、自然特徴、文化特徴を分類する。 |
| 水系を単なる水ラベルで潰さない | 採用 | 川、滝、湖、海、湾、湖畔、港、浜、水リスクを区別するテストが通る。 |
| 山地・砂漠・湿地・氷原などの疎地域を扱う | 採用 | 自然住所と住所タブ品質が、座標と地物証拠つきで表示または再検証へ回す。 |
| 全世界の全島名・全自然地名を完全認識する | 不採用 | Leanで候補欠落が完全性を破ることを確認済み。実データcoverage証明が必要。 |
| 2D座標だけでは垂直参照を完全に扱えない | Leanで支持 | `projection_collision_prevents_vertical_resolution` が対応する。 |
| 地図のラベル点を実体そのものと同一視する | 不採用 | 湖、山、川、遺跡、世界遺産はラベル点、形状、境界、入口が異なり得る。 |
| 到達点と参照対象を分ける | 採用 | `navigationDestination.test.ts` が建物中心点から駐車入口・車両到達点への補正を確認する。 |

第16章の安全な中心文は次である。

> 住所写像論では、住所を郵便配送可能な建物文字列に限定せず、自然地理、文化地理、道路網、垂直区画を含む参照体系として扱う。ただし、地物名は出典に依存し、地図上の点、線、面、境界、到達点は同一ではない。したがってAMTは、参照対象、アクセス点、配送可能点、出典、品質、未解決状態を分離して管理する。

## 3. Leanで確認できる部分

### 3.1 候補欠落は完全性を破る

Lean命題:

```text
missing_entity_refutes_candidate_completeness
```

意味:

> ある実体が、自分自身の観測から生成される候補集合に含まれないなら、その候補生成器は候補完全性を持たない。

これは第16章にとって重要である。川、島、砂漠、湖、遺跡、橋などは、郵便データだけでは候補に入らないことがある。したがって、AMTは自然地理・文化地理を扱えるが、それは実体が候補集合へ入るだけの出典がある場合に限られる。

本文では次のように書くべきである。

> 自然・文化地物の住所的参照は、出典拘束的である。候補生成器が当該地物を候補に含めない限り、後段のクラスタリング、評価、PID発行によってその欠落を完全には回復できない。

### 3.2 2D射影だけでは垂直参照を完全復元できない

Lean命題:

```text
projection_collision_prevents_vertical_resolution
```

意味:

> 異なる二つの垂直実体が同じ地表2D値へ射影されるなら、2D射影だけを見る解決器は、その二つを同時に正しく復元できない。

これは、1階店舗と2階事務所、地下入口と地上入口、同じ建物内の別室、宅配ロッカー、屋上設備、駐車区画などに対応する。したがって、本文では「座標は不要」ではなく、「2D座標だけでは不十分」と書くのが正確である。

安全な定式化は次である。

```text
P2D : X3D_t -> Ground2D_t

If P2D(x1) = P2D(x2) and x1 != x2,
then no resolver using only Ground2D_t can be correct for both x1 and x2.
```

## 4. 実装で確認できる部分

### 4.1 自然住所表示

`naturalAddress.test.ts` は、郵便住所が存在しない、または自然地理の文脈が重要な場合に、自然住所を構成できることを確認している。

確認済みの例:

| 種別 | 実装で確認した内容 |
|---|---|
| 海域 | 海名、海洋階層、水深、Plus Code、海洋出典を表示する。 |
| 山 | 山名、標高、近傍峰、座標、出典を表示する。 |
| 湖・内水 | 湖名、浜、港、水リスク、出典を表示する。 |
| 川・滝 | 川名、滝名、水系文脈、近傍水地物を表示する。 |
| 島・諸島 | 島名、環礁、近傍島、座標、出典を表示する。 |
| 砂漠・塩原 | 砂漠名、砂丘、塩原、座標、土地被覆出典を表示する。 |
| 氷原・極地 | 氷原、南極基地、極地データソースを表示する。 |

重要なのは、通常のstreet addressが存在する場合には、自然文脈で置換しない点である。これは、自然住所を郵便住所の上書きではなく、補助的な参照層として扱うことを意味する。

### 4.2 地図地物表示

`mapFeatureAddress.test.ts` は、地図から得られる地物ラベルを住所的文脈として扱えることを確認している。

確認済みの例:

| 種別 | 実装で確認した内容 |
|---|---|
| 道路 | 道路ラベルを建物名と混同せず、道路証拠として扱う。 |
| 橋 | 道路文脈とPOI文脈の両方で扱う。 |
| 山・川・湖・池・公園 | 表示可能なPOIラベルとして扱う。 |
| 草原・砂漠・森林・湿地・氷原 | landscapeまたは自然地物として扱う。 |
| 遺跡・世界遺産 | 文化地物ラベルとして扱う。 |
| 島・小島・諸島・環礁 | descriptor付きの住所ラベルとして扱う。 |
| 海岸・滝・氷河・洞窟・谷・礁・泉・湾 | generic waterと区別する。 |

### 4.3 到達点補正

`navigationDestination.test.ts` は、建物や地物の中心点をそのまま到達点にしない処理を確認している。

確認済みの内容:

1. 建物中心点から近いdrivewayへ補正する。
2. 明示的な駐車入口を優先する。
3. 証拠がない場合は元の点へfallbackする。

これは、第16.8節の「対象実体」と「到達点」を分離する主張を支える。

### 4.4 住所タブ品質

`addressTabQuality.test.ts` は、都市、田舎、島、山地、砂漠、湖、極地、水域などで住所タブを内部品質判定できることを確認している。

重要な結果:

| 環境 | 判定方針 |
|---|---|
| 都市 | 安定していれば二重検証を省略できる。 |
| 島 | 郵便番号が弱くても地図証拠が強ければ表示できる。 |
| 山地 | 自然地物と座標証拠があれば表示できる。 |
| 砂漠・塩原 | 未解決扱いにせず、再検証候補として残せる。 |
| 湖 | 座標と湖名証拠があれば表示できる。 |
| 明確に未解決 | 非表示または注意表示へ回す。 |

ユーザー側にスコアを表示する必要はない。第16章では、品質スコアを真理値ではなく、表示、注意、再検証、省略の内部制御に使うと書くのがよい。

## 5. GIS検証で確認できる部分

GIS検証は、地理的主張を直接Leanで証明するものではない。GIS検証は、外部データと幾何・出典メタデータを検査し、その結果を証明書としてLean側へ橋渡しする役割を持つ。

今回の結果では、登録済みGISデータの範囲で、エラーは0件であり、警告数も予算内であった。

安全に書けること:

1. 登録済みソースの警告予算は通過している。
2. GIS証明書生成は通過している。
3. AMTはGIS証明書を、候補生成と品質評価の外部根拠として使える。

まだ書けないこと:

1. 世界中の全自然地物が登録されている。
2. 全ての島名、川名、湖名、遺跡名を認識できる。
3. すべての地物境界が公式・最新・商用利用可能である。
4. 地図ラベルだけで法的境界や配送可能点が決まる。

## 6. 節ごとの判定

### 6.1 第16.1節の判定

自然・文化地物を住所的参照対象へ広げる方針は正しい。郵便住所ではない対象も、検索、案内、災害支援、保全管理、行政参照、観光、研究、配送補助に必要になる。

ただし、本文では「住所表示できる」を、「配送可能である」と混同しないようにする必要がある。

### 6.2 第16.2節の判定

点、線、面、体積、ネットワーク、文化境界の区別は必須である。地図アプリのラベル点は、しばしば「表示位置」にすぎず、「実体そのもの」ではない。

例:

| ラベル | 実体 | 到達点 |
|---|---|---|
| 湖名ラベル | 湖面全体、湖岸、流入口、流出口 | 港、浜、駐車場、管理所 |
| 山名ラベル | 山体、峰、稜線、登山道 | 登山口、山小屋、駐車場 |
| 川名ラベル | 河川ネットワーク、区間、支流 | 橋、堤防入口、船着場 |
| 世界遺産ラベル | 登録範囲、緩衝地帯、構成資産 | 入場口、案内所、管理事務所 |

### 6.3 第16.3節の判定

水系は、単なるwaterラベルとして扱うと情報が落ちる。川、滝、湖、池、湿地、塩湖、湾、海岸、流域、湖畔、港、浜、流入口、流出口を分ける必要がある。

実装はこの方向を支持している。ただし、実運用では、水位変動、季節湖、氾濫原、乾季の消失、私有地、危険区域などを追加属性として扱う必要がある。

### 6.4 第16.4節の判定

山地、谷、洞窟、砂漠、草原、森林、湿地、氷原、氷河、荒野は、郵便住所の弱い地域で特に重要である。実装は、疎自然地理を未解決として捨てず、座標、地物名、出典、品質により表示または再検証へ回す設計を支持している。

ただし、自然地物の境界は、国や地図ソースによって差が出る。本文では「境界の一意性」を断定せず、「source-scoped geometry」として扱うべきである。

### 6.5 第16.5節の判定

島名の扱いは重要であり、実装は島、小島、諸島、環礁、cay、keyなどを扱える。しかし、「世界全ての島名を認識できる」は不採用である。

反例:

1. 無人島や岩礁は地図ソースにより名称有無が異なる。
2. 同名の島が複数国に存在する。
3. 現地名、旧名、植民地期名、英語名、行政名が一致しない。
4. 島全体、港、集落、灯台、空港、保護区は別の参照対象である。
5. 領有権や行政管轄が争われる島では、出典ごとに表示が異なる。

したがって、島名については、世界完全認識ではなく、公式地名集、国際地名集、海図、OSM、自然地理データを束ねるsource-bound candidate generationとして書くべきである。

### 6.6 第16.6節の判定

遺跡、世界遺産、文化財、寺社、城跡、歴史地区は、住所的参照対象として重要である。実装は、遺跡や世界遺産ラベルを地図地物として扱う。

ただし、文化財には法的登録範囲、観光施設、管理者、入場口、緩衝地帯、撮影禁止区域などがある。本文では、地図ラベルを文化財境界と同一視しないようにする必要がある。

### 6.7 第16.7節の判定

垂直参照はLeanで支持される中核主張である。2D座標へ落とすと、同じ地表位置の別フロア、別部屋、地下、屋上、ロッカー、駐車区画を区別できない。

本文では、垂直参照を「拡張機能」ではなく、2D射影の情報損失を補うAMTの必要層として位置づけるとよい。

### 6.8 第16.8節の判定

実体と到達点の分離は、第16章で最も実用的な部分である。

```text
Reference target: lake, mountain, heritage site, river, island
Access target: entrance, port, trailhead, parking lot, bridge, office
Delivery target: mailbox, locker, reception, room, unit
```

AMTでは、参照対象と到達点の関係を `Access_t` として扱うとよい。

```text
Access_t subset X_t x X_t
```

湖に荷物を届けるのではなく、湖畔の管理事務所や港に届ける。山に届けるのではなく、登山口や山小屋に届ける。世界遺産に届けるのではなく、受付や管理事務所に届ける。この分離により、自然地理住所と配送住所を安全に併用できる。

## 7. 反例と弱点

### 7.1 ラベル点反例

地図上の湖名ラベルが湖の中心付近に置かれていても、その点は湖全体でも到達可能点でもない。したがって、ラベル点から配送可能点を直接決めることはできない。

### 7.2 河川ネットワーク反例

同じ川名が数百kmにわたる場合、「〇〇川」だけでは橋、河口、支流、堤防、滝、観測所のどれを指すか決まらない。線またはネットワーク実体として扱う必要がある。

### 7.3 山名反例

「富士山」は、山体、山頂、登山道、山小屋、五合目、神社、火口周辺、管理区域を含み得る。山名だけでは到達点を決められない。

### 7.4 文化財境界反例

世界遺産名は、単一建物、複数構成資産、緩衝地帯、景観保護区域を含むことがある。地図ラベルだけでは法的境界を証明できない。

### 7.5 垂直衝突反例

同じ緯度経度に、1階店舗、2階事務所、地下駐車場、屋上設備がある場合、2D座標だけではどの実体か決まらない。

### 7.6 島名網羅反例

小島、岩礁、季節的に露出する砂州、現地名しかない島、係争地の島は、ソースによって存在や名前が異なる。世界完全認識は、固定された出典集合、更新時刻、言語範囲、ライセンス範囲なしには検証できない。

## 8. 論文へ追加すべき命題

### 命題16.1 地物型明示命題

> 住所的参照対象が点、線、面、体積、ネットワーク、文化境界のいずれであるかを明示しない場合、同じ名称が異なる幾何粒度へ解釈され得る。

### 命題16.2 非郵便参照分離命題

> 自然・文化地物が住所的参照対象であることは、その地物が郵便配送可能点であることを含意しない。

### 命題16.3 垂直射影衝突命題

> 異なる垂直実体が同じ2D射影値を持つ場合、2D射影値だけに基づく解決器は、それらを同時に完全解決できない。

Lean対応:

```text
projection_collision_prevents_vertical_resolution
```

### 命題16.4 アクセス関係分離命題

> 参照対象 `x` と到達点 `a` は一般には同一でない。配送・案内・避難支援では、`Access_t(x, a)` を明示する必要がある。

### 命題16.5 出典拘束的自然地理命題

> 自然・文化地物の住所的解決は、候補生成器が参照する出典集合に拘束される。出典に含まれない実体について、候補完全性は主張できない。

Lean対応:

```text
missing_entity_refutes_candidate_completeness
```

## 9. 最終評価

第16章は、住所写像論を「郵便住所の理論」から「物理世界の参照理論」へ拡張する重要章である。実装テスト、GIS警告予算、Lean命題はいずれも、章の方向性を支持している。

ただし、章の強さは、断定を広げることではなく、分離を明確にすることで出る。

採用すべき分離:

1. 地図ラベルと実体。
2. 実体と到達点。
3. 参照住所と配送住所。
4. 2D座標と3D垂直区画。
5. 出典内coverageと世界完全coverage。

この分離を入れれば、第16章は自然地理、文化地理、災害支援、配送、観光、研究、保全管理、AGID/AOIDの応用へつながる強い章になる。
