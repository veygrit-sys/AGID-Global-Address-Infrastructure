# 住所写像論 日本語版 v1 第15章 検証ノート

対象: 第15章「住所圧縮と住所エントロピー」

本ノートは、第15章で述べられている「住所は情報圧縮であり、住所解決は候補不確実性を減らす過程である」という主張を、Lean形式化、実装テスト、PIDリスク予算、GIS警告予算、反例分析に照らして検証したものである。

結論を先に述べると、第15章は住所写像論の中核章として採用してよい。ただし、次の三点を必ず分ける必要がある。

1. 非単射圧縮による衝突と不完全復号。
2. Shannon entropyとしての候補集合不確実性。
3. 固定長コードやPIDにおける有限ビット容量。

また、「都市化とともに住所情報量は増加する」は無条件定理ではない。安全には、「識別対象数、密度、垂直階層、用途粒度が増えるほど、必要識別情報量は増えやすい」と書くべきである。

## 1. 検証結果の要約

| 観点 | 判定 | 理由 |
|---|---:|---|
| 住所を圧縮表現として捉える | 採用 | 郵便番号、住所文字列、座標、Plus Codes、PIDを同じ比較枠に置ける。 |
| 非単射圧縮には完全復号器がない | Leanで支持 | `noninjective_compression_no_perfect_decoder` が対応する。 |
| コード容量不足なら一意識別できない | Leanで支持 | `insufficient_bit_capacity_prevents_capacity_cover` が対応する。 |
| 候補が複数残るなら残差不確実性がある | Leanで支持 | `multiple_candidates_prevent_zero_residual` が対応する。 |
| 残差候補が複数なら曖昧状態が安全 | Leanで支持 | `proxy_residual_forces_ambiguous_abstention` が対応する。 |
| Shannon entropyを候補不確実性指標として使う | 実装で支持 | `resolveAddressMorphism` は候補確率からentropyを計算する。 |
| PID発行にリスク予算が必要 | 実装で支持 | `verify:pid-risk` が128 bit PIDの安全余裕を確認する。 |
| 都市化で住所情報量が必ず増える | 不採用 | グリッド都市、制度設計、田舎の同名地名、自然地理の曖昧性が反例になる。 |
| エントロピーだけでPID発行を決める | 不採用 | 品質、鮮度、候補分離、履歴、リスク、衝突ゲートも必要である。 |

第15章の安全な中心文は次である。

> 住所は、地理的、制度的、社会的、自然地理的情報を、人間や機械が扱える表現へ圧縮する参照表現である。圧縮が非単射である場合、圧縮値だけから元の実体を完全に復号することはできない。したがって住所解決は、候補集合の残差不確実性を、文脈、証拠、履歴、品質、リスク予算によって安全に減らす過程として定式化される。

## 3. Leanで確認できる部分

### 3.1 非単射圧縮には完全復号器がない

Lean命題:

```text
noninjective_compression_no_perfect_decoder
```

意味:

> 圧縮関数 `compress : Raw -> Code` が、異なる二つの実体 `left` と `right` を同じコードへ写すなら、そのコードだけからすべての元実体を完全に復元する復号器は存在しない。

これは第15章の「住所は圧縮であり、圧縮である以上、情報損失が起こる」という主張を支える。ただし、Leanが証明しているのは「衝突がある圧縮は完全復号できない」という一般命題であって、「すべての住所体系が常に非単射である」という経験的事実ではない。

### 3.2 有限ビット容量の下限

Lean定義:

```text
BitCapacity(bits) = 2 ^ bits
CapacityCovers(entityCount, bits) := entityCount <= BitCapacity(bits)
```

Lean命題:

```text
insufficient_bit_capacity_prevents_capacity_cover
```

意味:

> `2^bits < entityCount` なら、そのビット数の固定長コード空間は、対象実体数を一意に覆う容量を持たない。

これは `ceil(log2 N)` の直感と対応する。ただし、Leanでは実数対数やShannon entropyではなく、有限コード空間の容量下限として扱っている。

論文では次のように書くと安全である。

> N個の区別すべき対象を固定長コードで一意に表すためには、少なくともN個のコード値が必要である。したがって、b bitの自由容量を持つコードなら、必要条件として N <= 2^b が必要である。

### 3.3 複数候補なら残差不確実性が残る

Lean定義:

```text
CandidateResidualZero(candidateCount) := candidateCount <= 1
```

Lean命題:

```text
multiple_candidates_prevent_zero_residual
proxy_residual_forces_ambiguous_abstention
```

意味:

> 候補数が2以上なら、候補数ベースの残差不確実性はゼロとは言えない。その場合、追加証拠がない限り、解決器は強制的にPIDを出すよりも曖昧状態として保留する方が安全である。

これは第15章の候補集合エントロピーの運用的な下支えである。Shannon entropyの完全な形式化ではないが、「候補が複数残るなら一意性はまだ証明されていない」という安全性には十分対応する。

## 4. 実装で確認できる部分

`src/lib/addressMorphism.ts` では、候補クラスタのエネルギーを確率に変換し、次の形でShannon entropyを計算している。

```text
entropy = sum over p of -p * log(p)
```

ここでは自然対数が使われるため、単位はbitではなくnatである。論文では `log2` を使うならbit、実装では `log` を使うならnatであることを明記するか、実装換算では `H_bits = H_nats / log(2)` と書く必要がある。

関連テストでは、次が確認された。

| 実装領域 | 第15章への意味 |
|---|---|
| `addressMorphism.test.ts` | 明確な候補はverifiedになり、近接候補はambiguousになる。 |
| `addressTabQuality.test.ts` | 都市、島、山地、砂漠、水域、極地、田舎を内部品質で分ける。 |
| `naturalAddress.test.ts` | 山、川、湖、池、公園、島、砂漠、湿地、氷原、洞窟、谷、遺跡などの自然地名を扱う。 |
| `mapFeatureAddress.test.ts` | 道路、水辺、OpenFreeMap/Overpass地物を住所的ラベルとして扱う。 |
| `searchQuery.test.ts` | 多言語、表記揺れ、島名、アクセント差、typo近似の検索を扱う。 |
| `pidCollisionRisk.test.ts` | PIDの有限ビット容量と衝突リスクを予算化する。 |
| `pidIssuanceAudit.test.ts` | PID発行は候補生成、クラスタ、unresolved判定、履歴更新を通過したことを監査する。 |
| `qualityThresholdProof.test.ts` | 品質しきい値を秘匿しながら証明できる。 |

したがって第15章は、実装上も「住所解決は候補不確実性を減らし、十分な証拠がなければ保留する」という動作と整合する。

## 5. GISで確認できる部分とできない部分

GIS警告予算は、第15章の一部を支える。具体的には、地物データのsource登録、警告量、エラーの有無、自然地理ラベルの扱いを確認できる。

| 主張 | GISで確認できるもの |
|---|---|
| 自然地名も住所的候補になる | 山、川、湖、砂漠、島、湿地、氷原などの地物ソース登録と検証。 |
| 地図データ品質は不確実性に影響する | 警告数、source登録、境界検証、GDAL/QGIS確認。 |
| 砂漠、山地、島、極地は都市と違う品質判定が必要 | `addressTabQuality` とGIS警告予算の組み合わせで支持。 |

一方で、GISだけでは次を証明できない。

| GISだけでは決められないもの | 理由 |
|---|---|
| 住所エントロピーの一般的増減 | 確率分布、候補生成方式、文脈、履歴が必要である。 |
| 都市化が常に情報量を増やすか | 住所制度、グリッド設計、郵便番号、建物番号が交絡する。 |
| ある住所が配送に十分か | 配送業者、入口、ロッカー、権限、最新性が必要である。 |
| ある自然地名が一意か | 対象粒度、利用目的、地物境界、別名、言語が必要である。 |

したがって、第15章ではGISを「エントロピーを直接証明する道具」ではなく、「候補集合とデータ品質を構成する証拠源」として位置づけるべきである。

## 6. 本文各節の判定

### 6.1 15.1 住所は情報圧縮である

判定: 採用。ただし「住所の唯一の本質」ではなく「住所を比較する理論的視点」として書く。

現在の本文は良い。ただし、`c : X -> C` だけだと、読者は「C」が第14章の文脈集合と混同する可能性がある。第15章ではコード空間を `A`、`Code`、`S` などに変えた方が安全である。

推奨:

```text
comp : X -> Code
decode : Code -> P(X)
```

圧縮値から単一実体を返すのではなく、候補集合を返す復元写像として書くとAMT本体と接続しやすい。

### 6.2 15.2 有限圧縮と衝突

判定: 採用。Leanで支持。

ただし「鳩の巣原理」とだけ書くより、「有限コード空間の容量制約」とも書いた方が、PIDやAGIDのビット予算と接続しやすい。

推奨命題名:

```text
命題15.1 有限コード容量衝突命題
```

### 6.3 15.3 候補集合エントロピー

判定: 採用。ただし記法を厳密化する。

現在の `H(C_s)` は直感的には良いが、より正確には「候補集合の確率分布に対するエントロピー」である。したがって次のように書くとよい。

```text
H_s = H(E | U=s, c, l)
    = - sum_{x in C_s} p(x | s,c,l) log2 p(x | s,c,l)
```

ここで `E` は意図対象、`U` は入力、`c` は文脈、`l` は履歴またはlineage evidenceである。

### 6.4 15.4 必要識別ビット数

判定: 採用。ただし等確率の場合と容量下限を区別する。

`ceil(log2 N)` は、等確率候補の識別や固定長コード容量の説明として有効である。しかし現実の候補確率は一様とは限らない。論文では次を明記する。

```text
等確率候補N個から一つを識別する平均情報量はlog2 Nである。
固定長コードでN個の対象を一意に表すには、少なくともceil(log2 N) bitの自由容量が必要である。
```

### 6.5 15.5 圧縮方式の比較

判定: 採用。

比較表は有用である。ただし、AGID/AOIDはAMT本体ではなく応用論文で詳述する方針があるため、第15章では「応用識別子」として軽く扱うのがよい。

### 6.6 15.6 都市化と住所情報量

判定: 経験仮説として採用。

強い表現:

```text
都市化とともに住所情報量は増加する。
```

これは避ける。

安全な表現:

```text
識別すべき対象数、密度、垂直階層、入口や部屋などの用途粒度が増えるほど、必要識別情報量は増えやすい。ただし、住所制度やコード設計によって、表現長や衝突率は大きく変わる。
```

### 6.7 15.7 圧縮とプライバシー

判定: 採用。ただしZKP論文とは分離する。

この節はZK住所述語論文への橋渡しとして有効である。ただし、第15章では暗号的秘匿証明を証明しない。したがって、「住所圧縮は最小開示と関係する」とまでに留め、「ZKPで完全に安全」とは書かない。

## 7. 反例分析

| 強すぎる主張 | 反例 | 安全な修正 |
|---|---|---|
| 住所は常に実体を一意に表す | 同じ郵便番号に多数の建物や部屋がある。 | 住所表現は候補集合を減らすが、常に一意化するとは限らない。 |
| 圧縮値から元実体を完全復元できる | 異なる実体が同じコードへ写る場合がある。 | 非単射圧縮には完全復号器がない。 |
| 都市住所は常に長くなる | 規則的なグリッド都市では短い表現で区画を表せる。 | 対象数と粒度は情報需要を増やすが、記法効率は制度に依存する。 |
| 田舎は低エントロピーである | 同名集落、番地なし地域、広い自然地名が曖昧性を残す。 | 低密度は低不確実性を保証しない。 |
| AGIDだけで住所エントロピーはゼロになる | 同じセルに複数階、部屋、ロッカー、店舗がある。 | AGIDは空間不確実性を減らすが、AOID/PID/垂直参照/履歴が必要な場合がある。 |
| 郵便番号は場所を一意に表す | 郵便番号は配送区域であり、個別実体ではないことが多い。 | 郵便番号は候補集合を減らす圧縮方式である。 |
| 自然地名は一つの対象を表す | 山名が山頂、登山口、山小屋、尾根、火口を指す場合がある。 | 自然地理住所には粒度指定が必要である。 |
| エントロピーが低ければPID発行してよい | 低エントロピーでもsourceが古い、違法、履歴衝突がある場合がある。 | PID発行はentropyだけでなく品質、鮮度、履歴、リスク、監査を通す。 |

## 8. 追加すべき命題

### 命題15.1 有限コード容量衝突命題

有限集合 `X` と有限コード集合 `Code` について、`|X| > |Code|` なら、任意の写像 `comp : X -> Code` は単射でない。

これは本文の命題3と同じ趣旨である。

### 命題15.2 非単射圧縮不完全復号命題

`comp(x1) = comp(x2)` かつ `x1 != x2` なら、`Code` から `X` への復号器 `dec` で `dec(comp(x)) = x` をすべての `x` について満たすものは存在しない。

これはLeanの `noninjective_compression_no_perfect_decoder` と対応する。

### 命題15.3 候補残差命題

候補集合 `C_s` に二つ以上の候補が残り、追加証拠が候補を分離していない場合、残差不確実性はゼロではない。

これはLeanの `multiple_candidates_prevent_zero_residual` と対応する。

### 命題15.4 PID発行ゲート命題

PID発行は、候補エントロピーが低いことだけでなく、候補被覆、品質、鮮度、履歴整合、衝突リスク、監査証跡を満たすときに限って許可される。

これはLeanの `IssueAdmissible` 系と実装の `pidIssuanceAudit`、`pidCollisionRisk` と対応する。

## 9. 章の最終評価

第15章は、住所写像論の「曖昧性」を情報理論として説明する重要章である。第7章から第10章の候補生成、クラスタ、unresolved、PID発行の背景を、圧縮と残差不確実性としてまとめ直せる。

ただし、論文では次を避けるべきである。

1. Shannon entropy、surprisal、有限ビット容量を混同すること。
2. 都市化を住所情報量増加の唯一原因として書くこと。
3. AGID、郵便番号、座標が単独で住所エントロピーをゼロにすると書くこと。
4. エントロピーだけでPID発行を許すこと。
5. ZKPによる秘匿証明を第15章で証明済みのように扱うこと。

この修正を入れれば、第15章は第1章と第2章の「住所圧縮仮説」を数理化し、第16章の自然地理、第17章以降の品質・監査・応用識別子へつなぐ強い章になる。
