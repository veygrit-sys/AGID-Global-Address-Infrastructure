# 住所写像論 日本語版 v1 第6章 追加・編集差分案

作成日: 2026-06-06

対象: `docs/address-morphism-theory-ja-v1-master.md` 第6章

目的: 第6章「住所参照不可能性定理」を、Leanで検証済みの主張と整合する形に整え、過剰主張を避けながら、論文の核となる定理章として強化するための差し込み文、置換文、補題、系、反例をまとめる。

## 1. 編集方針

第6章は、住所写像論の理論的支柱である。ここでは、強い言い切りを弱めるのではなく、前提を正確にした上で強く言い切ることを目標にする。

冒頭に、次の編集方針を追加するとよい。

> 本章の定理は、住所解決の実用性を否定するものではない。本章が否定するのは、非単射な観測や候補欠落、射影損失、正規化衝突、文脈衝突が存在するにもかかわらず、追加条件なしに常に単一の正しい実体を返す完全解決器である。この不可能性は、AMTにおける候補生成、クラスタリング、未解決状態、履歴更新、PID発行ゲートを必要にする。

狙い:

「不可能性定理」を悲観論ではなく、安全な設計原理として読ませる。

## 2. 6.1 冒頭への置換・追加案

6.1の位置づけ説明に、次を追加する。

> 住所参照不可能性定理は、「住所解決はできない」という主張ではない。むしろ、住所解決を安全に行うためには、完全解決できる場合、曖昧な場合、未解決にすべき場合、棄却すべき場合を区別しなければならない、という主張である。
>
> したがって、本章の結論は次のように要約できる。
>
> 1. 観測だけから常に一つの正解を返す解決器は一般には存在しない。
> 2. 候補生成は真の対象を含むように設計されなければならない。
> 3. 座標、郵便番号、正規化文字列、行政コードは重要な証拠だが、単独では同一性を保証しない。
> 4. 住所解決は文脈依存である。
> 5. `ambiguous`, `unresolved`, `rejected` は失敗ではなく安全な出力である。

## 3. 6.2 非単射観測補題の書き方

6.2は、次のように定理形式で書くとよい。

### 補題 6.1 非単射観測補題

集合 \(X\) を住所可能実体集合、集合 \(Y\) を観測空間とする。観測写像を \(O:X\to Y\)、解決器を \(R:Y\to X\) とする。ここで、解決器が完全であるとは、すべての \(x\in X\) について \(R(O(x))=x\) が成り立つことをいう。

もし、異なる二つの実体 \(x_1,x_2\in X\) が存在し、

```
x1 != x2
O(x1) = O(x2)
```

を満たすなら、そのような完全解決器 \(R\) は存在しない。

### 証明

仮に完全解決器 \(R\) が存在するとする。完全性より、

```
R(O(x1)) = x1
R(O(x2)) = x2
```

である。一方、仮定より `O(x1) = O(x2)` であるから、同じ入力に対する関数 \(R\) の出力は同じでなければならない。したがって、

```
R(O(x1)) = R(O(x2))
```

であり、結果として `x1 = x2` が従う。これは `x1 != x2` に反する。よって完全解決器は存在しない。

### 本文注

この補題はLeanの `no_condition_free_perfect_resolver` と対応する、と脚注または検証付録で明示するとよい。

## 4. 6.3 候補欠落補題の追加案

候補生成の重要性を強めるため、6.3に次の補題を追加する。

### 補題 6.2 候補欠落補題

住所入力 \(s\) と文脈 \(c\)、時刻 \(t\) に対し、候補生成写像を \(\Gamma_{c,t}(s)\subseteq X_t\) とする。安全な候補制限型解決器が、出力可能な対象を \(\Gamma_{c,t}(s)\) 内に制限しているとする。

このとき、真の対象 \(x^\ast\) が

```
x* notin Gamma_{c,t}(s)
```

を満たすなら、その解決器は \(x^\ast\) を返すことができない。

### 解説

この補題は、候補生成の再現率がAMT全体の上限を決めることを示す。後段の評価関数、クラスタリング、履歴更新は、候補集合に入っていない対象を復元できない。

### 実装上の帰結

本文に次を追加する。

> 候補生成は、最終決定ではない。候補生成は、後段の評価と保留判定に渡すための安全な探索空間を作る段階である。したがって、候補生成では再現率を重視し、評価段階で品質、鮮度、距離、履歴、文脈、リスクにより絞り込む。

## 5. 6.4 射影損失補題の追加案

6.4は、座標批判ではなく「射影だけでは不十分」という主張にする。

### 補題 6.3 射影損失補題

住所可能実体集合 \(X\) から、座標、郵便番号、行政コードなどの低次元表現 \(Z\) への射影を \(P:X\to Z\) とする。異なる実体 \(x_1,x_2\in X\) が存在し、

```
x1 != x2
P(x1) = P(x2)
```

を満たすなら、射影値 \(P(x)\) のみを入力とする解決器は、\(x_1\) と \(x_2\) を常に正しく区別できない。

### 例として追加する本文

> 例えば、同一の緯度経度点に、1階の店舗、2階の事務所、地下の駐車場、建物裏側の配送入口が対応することがある。二次元座標は重要な観測であるが、それだけでは垂直参照、入口、用途、権利区画、配送可否を表せない。

## 6. 6.5 正規化衝突補題の追加案

6.5では、正規化の有効性と危険を両方書く。

### 補題 6.4 正規化衝突補題

正規化写像を \(N:S\to S'\) とする。異なる表面表現 \(s_1,s_2\in S\) が存在し、

```
s1 != s2
N(s1) = N(s2)
```

であり、かつ \(s_1\) と \(s_2\) の差が参照対象の区別に必要であるなら、正規化後の値だけから完全な住所解決を行うことはできない。

### 追加本文

> 正規化は、住所処理において不可欠である。しかし、正規化は原表記を消す操作ではなく、原表記に対する追加の観測を生成する操作として扱うべきである。安全なAMTでは、原表記、正規化規則、正規化結果、時刻、出典を保持し、正規化によって何が失われたかを監査可能にする。

## 7. 6.6 文脈衝突補題の追加案

6.6では、文脈なしの絶対住所解決を否定する。

### 補題 6.5 文脈衝突補題

同じ表面表現 \(s\) に対し、文脈 \(c_1\) では \(x_1\) が最適な対象であり、文脈 \(c_2\) では \(x_2\) が最適な対象であるとする。もし \(x_1\ne x_2\) なら、文脈を入力に取らない解決器 \(R:S\to X\) は、両方の文脈で同時に最適な出力を返すことができない。

### 追加本文

> 配送における住所は到達可能な入口やロッカーを重視する。行政における住所は住居表示や自治体境界を重視する。登記における住所は権利区画を重視する。緊急対応における住所は到達経路、階数、危険区域を重視する。したがって、住所解決は文脈を入力に含める必要がある。

## 8. 6.7 主定理の書き換え案

6.7の主定理は、次のように書くと強く、かつ誤読されにくい。

### 定理 6.6 住所参照不可能性定理

時刻 \(t\) における住所可能実体集合を \(X_t\)、観測空間を \(Y_t\) とする。解決器が次の条件を満たすと仮定する。

| 条件 | 内容 |
| --- | --- |
| 全域性 | 任意の観測に対して出力を返す。 |
| 単一出力性 | 常に一つの実体を返す。 |
| 観測限定性 | 追加の文脈、履歴、対話、出典確認なしに観測値だけを入力とする。 |
| 完全性 | 任意の実体について、観測から元の実体を常に復元する。 |

このとき、次のいずれかが存在すれば、その解決器は完全ではあり得ない。

1. 非単射観測
2. 候補欠落
3. 射影損失
4. 正規化衝突
5. 文脈衝突

### 証明の書き方

証明は、それぞれの補題への場合分けで書く。

| 場合 | 適用する補題 |
| --- | --- |
| 非単射観測 | 補題6.1 |
| 候補欠落 | 補題6.2 |
| 射影損失 | 補題6.3 |
| 正規化衝突 | 補題6.4 |
| 文脈衝突 | 補題6.5 |

この形にすると、主定理は単一の巨大な主張ではなく、検証済みの補題群からなる安全な不可能性定理になる。

## 9. 6.8 反例表の追加案

6.8には、次の表を追加すると読者が理解しやすい。

| 反例 | 破れる条件 | AMTでの対策 |
| --- | --- | --- |
| 同名マンションが同一区内に複数ある | 非単射観測 | 候補集合を複数保持し、追加証拠を要求する。 |
| 同じ郵便番号に多数の建物がある | 射影損失 | 郵便番号を候補生成の一証拠として扱う。 |
| 同一座標に複数階・複数入口がある | 射影損失 | 垂直参照層、入口、用途を追加する。 |
| 旧住所が行政変更で複数の新住所へ分かれる | 履歴損失 | 履歴グラフを使い、単純置換しない。 |
| 川、橋、道路、山、建物が同じ地名を持つ | 地物種別衝突 | 地物種別と文脈を候補属性に含める。 |
| 配送用住所と行政住所が違う | 文脈衝突 | 文脈 \(c\) を解決器の入力にする。 |

## 10. 6.9 系として追加する文

主定理の後に、次の系を入れると章の結論が明確になる。

### 系 6.7 安全保留状態の必要性

住所解決器が誤った単一実体を返すことを避けるためには、解決結果型に `ambiguous`, `unresolved`, `rejected` のような保留または棄却状態を含める必要がある。

### 解説

> これは実装上の失敗処理ではなく、理論的に必要な安全状態である。十分な証拠がないときに発行しないことは、AMTの中核的な正しさ条件である。

### 系 6.8 PID発行ゲートの必要性

PIDは、住所文字列、正規化文字列、郵便番号、座標などの観測値から直接発行してはならない。PIDは、候補所属、評価閾値、マージン、品質、鮮度、衝突リスク、監査条件を通過した参照対象に対してのみ発行されるべきである。

### 解説

> 観測値に基づくPIDは、観測衝突をそのままPID衝突へ変換する。PIDは観測の識別子ではなく、監査済み参照対象の識別子である。

## 11. 6.10 結論への差し替え案

6.10の結論を、次のように締めるとよい。

> 第6章の結論は、住所写像論における安全な解決器の設計原理を与える。住所は、単一の文字列、座標、郵便番号、行政コードに還元できない。有限で非単射な観測の下では、条件なしに常に正しい単一対象を返す完全解決器は存在しない。
>
> したがってAMTは、候補生成、クラスタリング、評価関数、保留状態、履歴グラフ、PID発行ゲートを導入する。これらは実装上の付加機能ではなく、不可能性定理から導かれる安全構造である。

## 14. 本定理が否定しないもの

第6章の末尾または脚注に、次の表を入れると誤読を防げる。

| 否定しないもの | 説明 |
| --- | --- |
| 高精度な住所解決器 | 追加証拠、履歴、文脈、対話により高精度化できる。 |
| 確率的推定 | 統計的に最尤な候補を選ぶことは可能である。 |
| 人間の確認 | 人間や配送実績による追加観測は情報を増やす。 |
| 座標、郵便番号、行政コードの有用性 | これらは重要な証拠であり、単独で完全ではないだけである。 |
| 住所の社会的実在性 | 本定理は観測からの完全復元不能性を述べる。 |
