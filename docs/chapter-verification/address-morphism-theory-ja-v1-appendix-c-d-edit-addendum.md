# 住所写像論 日本語版 v1 付録C/D 追加・編集差分案

対象: 付録C「反例集」および付録D「検証マップ」

目的: 反例集と検証マップを、論文本文の証拠索引として使える形にする。反例は単なる例ではなく、どの完全性主張を壊すのかを明示する。検証マップは、どの主張がLean、GIS、実装、データ、概念、別論文のどれに属するかを明確にする。

## 1. 付録Cの冒頭に加える文

挿入位置: 付録Cの冒頭直後。

> 本付録の反例は、住所写像論の限界を弱点として隠すためではなく、理論の安全性を支えるために列挙する。住所解決は、反例の存在を無視して単一の正解を返すのではなく、反例を検出したときに ambiguous, unresolved, conditional, rejected のいずれかへ安全に遷移する必要がある。

## 2. 付録Cの表を拡張する

現行の `反例、内容、影響` の3列に、`壊す素朴な主張`、`AMTの応答`、`検証方法` を追加する。

| 反例 | 壊す素朴な主張 | AMTの応答 | 検証方法 |
| --- | --- | --- | --- |
| 同名ビル | 建物名だけで一意に解決できる | 表面名だけではresolvedにしない。複数候補ならambiguousにする。 | Leanの非単射観測、正規化衝突、実装テスト。 |
| 同一郵便番号内の多数住宅 | 郵便番号だけで住戸を特定できる | 郵便番号は区域証拠として扱い、建物または住戸PIDの直接根拠にしない。 | 郵便ソース検証、住所検証テスト。 |
| 垂直衝突 | 2D座標だけで階や部屋まで分かる | 垂直参照層、部屋、入口、建物内部証拠を要求する。 | Leanの射影損失、実装テスト。 |
| 旧住所衝突 | 旧住所は必ず現在住所に一意変換できる | 履歴グラフで後継、分裂、統合、廃止、不明を保持する。 | Leanの分裂補題、PID lifecycle tests。 |
| 自然地名衝突 | 自然地名は一つの対象を指す | 地物型、範囲、アクセス点、出典、品質で分ける。 | GIS検証、自然地理テスト。 |
| 社会的移転 | 同一性は地理だけで決まる | 社会的連続性と地理的連続性を分離する。 | 履歴モデル、文脈相対性。 |
| 災害時住所 | 住所は恒久的で安定している | 一時住所、鮮度、失効、再検証を扱う。 | freshness gate、品質テスト。 |
| 世界遺産・遺跡 | 名称だけで範囲と入口が分かる | 文化的範囲、管理範囲、観光入口、配送到達点を分ける。 | 自然地理・文化地物テスト、出典検証。 |
| 砂漠・湿地・氷原 | 境界の曖昧な地物は住所対象にならない、または完全に境界確定できる | 出典付きなら住所的参照にできるが、品質、季節性、観測点を併記する。 | GIS検証、自然地理テスト。 |

## 3. 付録Cの末尾に加える注意書き

挿入位置: 付録Cの末尾。

> これらの反例は、AMTが対象を扱えないことを意味しない。むしろ、対象を扱うために、文字列、郵便番号、座標、地物型、履歴、文脈、品質、出典、鮮度を分離する必要があることを示す。反例を検出できない解決器は、誤ったresolvedを返す危険がある。

## 4. 付録Dの冒頭に加える文

挿入位置: 付録Dの冒頭直後。

> 本付録の検証マップは、各主張をどの方法で確認できるかを示す。Leanは抽象構造を証明する。GISは地理データと境界を検査する。実装テストは解決器、品質ゲート、PID監査、住所検証エンジンの振る舞いを確認する。郵便ソース検証は国別住所データと公式・オープンソースの登録状態を確認する。いずれの方法も万能ではないため、検証対象と限界を明示する。

## 5. 付録Dの検証状態を置き換える

現行の `可、不要、部分可` を次の語へ置き換える。

| 旧表現 | 推奨表現 | 理由 |
| --- | --- | --- |
| 可 | 形式化済み、形式化可能、実装検証済み、GIS検証済みのいずれか | 何が可能なのかが曖昧なため。 |
| 不要 | 対象外、または不要 | 本当に不要か、別の検証が必要かを分けるため。 |
| 部分可 | 部分形式化済み、実装検証済み、今後検証 | どの部分が済んでいるかを明示するため。 |

## 7. 付録Dの末尾に加える注意書き

挿入位置: 付録Dの末尾。

> 本検証マップは、AMTの全主張が同じ種類の証明で支えられることを意味しない。Leanで証明できるのは、非単射性、候補欠落、射影損失、非発行安全性、履歴保存、文脈衝突などの抽象構造である。GISと実装テストで確認するのは、地理出典、自然地理表示、郵便住所検証、品質ゲート、PID監査などのシステム性質である。商用API比較や全世界カバレッジは、公開データと同一評価条件を定めた上で別途検証する必要がある。

## 8. 断定を避けるべき表現

次の表現は、本文または付録で避ける。

| 避ける表現 | 置き換え |
| --- | --- |
| 全世界の住所を完全に解決できる | 検証済み出典の範囲で候補生成し、証拠不足ならunresolvedにする。 |
| 商用APIに常に勝つ | 同一データセットと同一指標で限定比較する。 |
| 住所は消滅しない | 住所参照は履歴グラフ上で後継、廃止、分裂、統合、不明として記録できる場合がある。 |
| 自然地理名をすべて認識できる | 出典に含まれる自然地理名を住所的参照として扱える。 |
| ZKPで住所の真実性を保証できる | ZKPは住所由来述語を秘匿証明できるが、住所の真実性にはissuer、出典、失効、鮮度が必要である。 |

## 9. 最終方針

付録Cは反例集として残すだけでなく、理論の安全設計を支える表にする。付録Dは検証マップとして残すが、検証状態を曖昧にしない。これにより、住所写像論は「万能住所解決器」ではなく、「反例を前提にした安全な住所参照理論」として提示できる。
