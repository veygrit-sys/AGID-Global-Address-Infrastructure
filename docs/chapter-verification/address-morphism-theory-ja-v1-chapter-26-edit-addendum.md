# 住所写像論 日本語版 v1 第26章 追加・編集差分案

対象: 第26章「結論」

本差分案は、第26章を、住所写像論日本語版v1の本編を閉じる結論章として補強する本文案である。中心方針は、新しい未検証主張を増やさず、これまでの検証済み主張を「AMT本体の立場」として整理することである。

## 1. 章冒頭に追加する要約

第26章の冒頭に、次を追加するとよい。

> 本章では、住所写像論日本語版v1の立場をまとめる。本稿の結論は、住所を完全に一意化できるという主張ではない。本稿の結論は、住所がどの条件で解決でき、どの条件で解決できず、どの条件で保留され、どの条件で履歴へ接続され、どの条件でPIDを発行してよいかを、ひとつの意味論として扱うべきだという主張である。

続けて、次を入れる。

> AMTは、住所を単なる文字列、座標、郵便番号、地名のいずれかに還元しない。住所は、空間、制度、履歴、言語、到達可能性、文脈、品質、監査が交差する参照である。

## 2. 26.1「住所写像論の核」を補強する

現行本文の後に、次を追加する。

> この見方では、住所表現は実体そのものではなく、実体に関する観測である。観測は、正規化、翻訳、略称、旧称、郵便番号、座標、地図ラベル、自然地理名、建物名、部屋番号、社会的名称によって構成される。したがって、住所解決は単なる文字列一致ではなく、観測から候補集合を生成し、証拠を比較し、必要に応じて保留する過程である。

続けて、次の短い整理を入れる。

| 見方 | AMTでの扱い |
|---|---|
| 住所は文字列である | 文字列は表面表現の一種である |
| 住所は座標である | 座標は観測の一種である |
| 住所は郵便番号である | 郵便番号は配送区域や候補生成の証拠である |
| 住所は地名である | 地名は地物、区域、社会的名称の証拠である |
| 住所は現在値である | 現在値は履歴グラフの一時点である |

短い結論:

> 住所写像論の核は、住所を単一形式ではなく、参照を形成する写像の連鎖として扱う点にある。

## 3. 26.2「安全な住所解決」を補強する

現行本文の後に、次を追加する。

> AMTにおける安全な住所解決とは、常に答えを返すことではない。むしろ、答えを返してはいけない条件を明示することである。候補が欠落している、候補が近接している、出典が弱い、品質が低い、履歴が古い、リスクが高い、文脈が一致しない場合、AMTは単一PIDを強制発行しない。

> `ambiguous`、`unresolved`、`rejected`、`conditional` は、ユーザー体験上は未完了に見えるかもしれない。しかし理論上は、誤った実体を確定しないための安全状態である。

さらに、次の表を入れる。

| 状態 | 意味 | 安全上の役割 |
|---|---|---|
| resolved | 十分な証拠で解決した | 参照固定とPID発行候補 |
| ambiguous | 複数候補が競合している | 誤った単一化を防ぐ |
| unresolved | 証拠不足または候補欠落 | 不明を不明として保持する |
| rejected | 不正、出典拒否、条件不適合 | 危険な発行を止める |
| conditional | 条件付きで利用可能 | 文脈や追加証拠へ依存する |

短い結論:

> AMTは、解決だけでなく、保留と拒否を正式な出力型として扱うことで安全になる。

## 4. 26.3「履歴と文脈」を補強する

現行本文の後に、次を追加する。

> 住所は静的な値ではない。行政変更、町名変更、住居表示、再開発、建物の改修、部屋番号の変更、避難所開設、仮設住宅、移転、統合、分割により、住所参照は変化する。したがって、AMTでは住所の本体を現在値だけでなく、履歴グラフとして扱う。

> また、住所の正しさは文脈に依存する。配送に必要な住所、消防に必要な住所、行政に必要な住所、不動産登記に必要な住所、観光案内に必要な住所、災害支援に必要な住所は、同じとは限らない。

次の表を入れる。

| 文脈 | 求められる参照 |
|---|---|
| 配送 | 受取可能地点、入口、ロッカー、配送可否 |
| 消防 | 迅速到達可能な入口、建物区画、危険情報 |
| 行政 | 公式区域、住民登録、制度上の所属 |
| 不動産 | 区画、階層、所有権、占有関係 |
| 自然地理検索 | 地物、区域、アクセス点、出典 |
| 災害支援 | 避難所、仮設住宅、支援対象、時間範囲 |

短い結論:

> AMTにおいて、履歴と文脈は補助情報ではなく、住所参照を決める中心要素である。

## 5. 26.4「AMTと応用」を補強する

現行本文の後に、次を追加する。

> AMT本体は、住所参照の意味論を提供する。AGID/AOID、ZK住所証明、Credential、MCP、買い物Agent、Polkadot連携、配送会社API、公式郵便API統合は、この意味論を利用する応用である。

> 応用層は重要である。しかし、応用層をAMT本体に混ぜすぎると、理論の責任範囲が不明確になる。例えば、ZKPは住所を秘匿して属性を証明するために有効だが、ZKPのsoundness、zero-knowledge、鍵管理、issuer trust、revocation、freshnessはAMT本体の証明ではない。AGID/AOIDも、公開地理参照、私的操作住所、権限委譲、通信、監査、QR、SDKという別の実装責務を持つ。

短い結論:

> AMT本体は住所意味論として安定させ、AGID/AOIDやZKPは応用論文または実装仕様として分離する。

## 6. 26.5「最終結論」を補強する

現行本文の後に、次を追加する。

> 住所写像論が目指すのは、曖昧性を消すことではない。曖昧性を検出し、記録し、必要なときは保留し、証拠が揃ったときだけ参照を固定することである。

> 住所は、文字列として読まれ、座標として測られ、郵便番号として圧縮され、地名として記憶され、履歴として変更され、文脈によって評価され、必要に応じてPIDとして固定される。住所写像論は、この一連の写像を扱う理論である。

第26章の末尾を、次の文で締めるとよい。

> したがって、住所写像論日本語版v1の中心的立場は明確である。住所とは、曖昧な世界を無理に一意化するための文字列ではなく、曖昧な世界を安全に参照し、解決できるときだけ固定し、解決できないときは保留できるようにするための意味論的構造である。

## 7. 本文末に入れる最終要約表

第26章の最後に、次の表を入れると論文全体の見通しがよくなる。

| 本稿の結論 | 意味 |
|---|---|
| 住所は参照である | 文字列や座標そのものではなく、対象へ向かう観測と証拠の体系である |
| 完全解決器は存在しない | 非単射観測や候補欠落の下では無条件完全解決はできない |
| 保留状態は必要である | ambiguous、unresolved、rejected、conditionalは安全状態である |
| PID発行は強い操作である | 候補表示よりも厳しい品質、履歴、監査条件を必要とする |
| 履歴と文脈は中心である | 住所は現在値だけでなく、変更と用途に依存する |
| 応用層は分離する | AGID/AOID、ZKP、Credential、MCP等はAMT本体の上に構築する |

## 8. 第26章の編集後構成

第26章は、次の構成にするとよい。

1. 章冒頭要約。
2. 26.1 住所写像論の核。
3. 26.2 安全な住所解決。
4. 26.3 履歴と文脈。
5. 26.4 AMTと応用。
6. 26.5 最終結論。
7. 最終要約表。

この構成により、第26章は短いながらも、住所写像論日本語版v1の主張を過不足なく閉じられる。

## 9. 第26章の注意点

結論章では、次を避ける。

1. 「世界中の住所を完全解決する」と書かない。
2. 「商用APIに必ず勝つ」と書かない。
3. 「ZKPで住所問題がすべて安全になる」と書かない。
4. 「品質スコアが真理を表す」と書かない。
5. 「自然地理を世界全て認識できる」と書かない。
6. 「AGID/AOIDをAMT本体の定理として扱う」と書かない。

これらを避けることで、第26章は第25章の限界と矛盾せず、日本語版v1を安全に締められる。
